# サービスを serve する

ユーザーはトップバーの「サービス」ボタンから、いま公開されているアプリを別タブで開く。**公開枠は全会話で共有の 1 本だけ**で、同時に 2 つは公開できない。起動・停止は `serve` ツールを使い、生の `bash` でバックグラウンド起動しない（所有者と起動コマンドが残らず、UI が「起動元不明」になる）。

## 到達できる条件

BFF はサンドボックスへ TCP connect して稼働を判定する。HTTP は叩かないため、500 を返すアプリでも到達可なら稼働中として扱われる。

| 条件             | 値                                                               |
| ---------------- | ---------------------------------------------------------------- |
| バインド先       | `0.0.0.0`（`127.0.0.1` は BFF から届かない）                     |
| ポート           | `8080` 固定（黙って別ポートへ移らない）                          |
| 待受プロセス特定 | `/proc/net/tcp` の listen エントリと `/proc/<pid>/fd` の照合     |
| ログ             | ワークスペース root の `.u7agent/serve/app.log`                  |
| 稼働記録         | ワークスペース root の `.u7agent/serve/state.json`（BFF が書く） |

## 環境変数（作業環境 → 環境変数）

値はユーザーが **作業環境 → 環境変数** で登録する。コードは `process.env.NAME` を読むだけでよい。

| 種別         | 自分の `bash` | `serve` / `debug_start` の起動プロセス |
| ------------ | ------------- | -------------------------------------- |
| 変数         | 渡る          | 渡る                                   |
| シークレット | **渡らない**  | 渡る                                   |

- **変数**は次の `bash` から、**シークレット**は次回の起動から反映される（起動中のサービスは古い値のまま）
- `bash` で `process.env.NAME` が `undefined` でも未登録とは限らない。シークレットは `bash` へ渡らないので、`undefined` は未設定の証拠にならない
- 確認は値を出さずに**存在**だけを見る。`bash` では `[ -n "${NAME+x}" ]`、起動プロセスでは `String("NAME" in process.env)` を返す小さなサーバーを `debug_start` で立てて `curl` で見る
- `[REDACTED]` はマスカーが値を伏せた結果で、注入されたことの証明にはならない。マスカーは BFF の起動時に作業環境のシークレットを読み直さないため、値が返っても伏せられないことがある。注入の有無は上の存在確認だけで切り分ける
- `.env` を作らない。値をファイルへ書かない（持ち込みコードに `.env` がある場合はここでは扱わない）
- 値を受け取ろうとしない（ユーザーに値をチャットへ貼らせない）。使うのは名前だけ
- 値が必要なら「作業環境 → 環境変数 に `NAME` を登録してください」と案内する。登録の代行はできない

## 手順

1. アプリの起動コマンドを決める。`package.json` の script、フレームワークの既定ポート、既存プロセスの有無を確認する。**コマンド自身でバックグラウンドに回さない**（`&` / `disown` を付けない）。ツールが `nohup` で起動し、到達したプロセスがその起動に由来するかをプロセスの親子関係で確かめるため、自分で切り離すと起動が失敗として扱われる。
2. `serve` ツールの `start` にそのコマンドを渡す。ツールは起動、記録、期限つきの到達確認（10 秒）まで行う。**到達できたらその作業ディレクトリの起動コマンドとして記録される**ため、次回以降は GUI の「起動」から同じコマンドで起動できる。
3. 到達できなかったら、`curl -fsS http://127.0.0.1:8080/` と `.u7agent/serve/app.log` の末尾を見て原因を切り分け、コマンドを直して 2 に戻る。
4. `serve` ツールの `status` で状態を確認し、ユーザーにはトップバーの「サービス」から開けることを伝える。

## 到達しないときの原因

- `127.0.0.1` にバインドしている（`--host 0.0.0.0` / `HOST=0.0.0.0` が要る）。Vite は `--host 0.0.0.0 --port 8080 --strictPort` を使う。`--strictPort` が無いと、8080 が埋まっているときに黙って別ポートへ移り、到達確認が失敗する。
- HMR / 開発サーバーの host 許可リスト（`server.allowedHosts` など）がブラウザ側の hostname を拒む。表示は別問題なので、まず到達を優先して直す。
- ポートの既定値が 8080 でない（`--port 8080` / `PORT=8080` を明示する）。
- 既存プロセスが残っている。`serve` ツールの `start` は到達可のときに停止してから置き換えるが、待受 PID を特定できないときは停止できない。その場合はユーザーに「起動元不明」として表示され、`stop` は使えない。
- 依存が未インストール、ビルドが未完了など、起動自体が失敗している。ログの末尾を読んでからコマンドを直す。

## 停止

- `serve` ツールの `stop` を使う。停止対象は常に「いま待受している PID」で、記録の PID ではない。
- 停止できるのは所有者の会話だけ。起動元不明のときは誰でも停止できる（誰も止められないサーバーを残さないため）。
- 停止後はポートの解放を確認してから応答する。解放できないときはエラーになるので、ログを見て原因を直す。

## デバッグ用 serve（自分で確かめるとき）

自分で `curl` やスクリーンショットで確かめるだけなら、公開枠を使わずに `serve` ツールの `debug_start` を使う。**公開枠（8080）はユーザーに見せるときだけ**使う。

- `debug_start` に渡す `command` は `127.0.0.1` に bind し、ポートは `$U7AGENT_DEBUG_PORT` から読む。例: `pnpm dev --host 127.0.0.1 --port $U7AGENT_DEBUG_PORT --strictPort`。環境変数（作業環境 → 環境変数）は公開枠と同じように渡る。
- ポートは起動のたびに 18000–18099 から採番される。**同じポートになるとは限らない**ため、常にツール応答のポートを使う。
- 到達確認は TCP connect ではなく待受の走査で行う。`127.0.0.1` 以外へ bind していたり、期限内に待受を確認できなかったりすると起動失敗になる（そのときログのパスがエラーに出る）。
- ログは `.u7agent/serve/debug/<port>.log`。起動のたびに空になり、停止しても消えない。
- このサーバーは**ユーザーのサービス UI には出ない**。ユーザーへ URL を案内しない（出すのは 8080 の「サービス」リンクだけ）。
- 確認は `curl -fsS http://127.0.0.1:<port>/` か、`browser` スキルの `u7agent-browser`。
- 確認が済んだら `debug_stop` で止める（run の終了では自動で止まらない）。`debug_status` で自分の会話のポートと待受の有無を見られる。
- 起動に成功したコマンドは**実績（GUI の起動）には記録されない**。ユーザーに見せるときは、あらためて `serve` ツールの `start` で 8080 の起動コマンドを渡す。

## してはいけないこと

- 生の `bash` で `nohup ... &` する（UI の所有者と起動コマンドが残らない）。
- `pkill` / `killall` で一括停止する（ツール API の 9418 など無関係なプロセスを巻き込む）。
- 公開枠以外のポートでユーザーへ見せようとする（ユーザーへ見せるのは 8080 の 1 本だけ。自分の確認は `debug_start` の 18000 帯）。
- 自動復旧・自動再起動を期待する（コンテナ再作成でプロセスは消え、UI は復旧しない）。
- 起動コマンドや `.env` にシークレットの値を書く / ユーザーに値の貼り付けを頼む（値は 作業環境 → 環境変数 から実行時にだけ入る）。
