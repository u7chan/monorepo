# スキルを作る

ユーザーの依頼から再利用できるスキルを作る手順。**受け入れ条件は「それらしい文章ができた」ではなく、置き場所と frontmatter がこの規約を満たすこと**。

## 1. 置き場所を決める

| 目的                             | 置き場所                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| このプロジェクトだけで使う       | `<project>/.agents/skills/<name>/SKILL.md`（作業ディレクトリ直下の `.agents/skills`） |
| すべてのセッションで使う（共通） | ワークスペース root の `.agents/skills/<name>/SKILL.md`                               |

- 作業ディレクトリ（cwd）は、登録済みプロジェクトか、未所属チャットのスクラッチ。cwd 直下の `.agents/skills` はプロジェクトスキルになる。
- ワークスペース root が分からないときは、cwd から親へ向かって `.u7agent` があるディレクトリを探す。見つからず、ユーザーに確認できなければ**プロジェクト側**（cwd 直下）に作る。
- `.pi/skills`、`~/.pi/agent/skills`、ホームディレクトリには**書かない**（このアプリは読まない）。

## 2. frontmatter を書く

```markdown
---
name: pdf-report
description: PDF のレポートを読み、要約と数値の抜き出しを求められたときに使う。表の抽出とページ指定の手順を含む。
# 任意。モデルからの自動起動を止め、/skill:pdf-report のような明示的な指定だけで使う
disable-model-invocation: true
---
```

- `name`: 小文字英数字とハイフンだけ、64 字以内。ディレクトリ名と揃える。
- `description`: **いつ使うか**を書く。1024 字以内。空にしない（自動起動の判断はこの文だけで行われる）。
- `disable-model-invocation`: 任意。常時見えている必要がないスキルは `true` にして、system prompt を膨らませない。

## 3. 構造

```text
<name>/
  SKILL.md       # 必須。手順と判断基準
  scripts/       # 任意。実行するスクリプト
  references/    # 任意。長い手順・スキーマ・例
  assets/        # 任意。テンプレートや画像
```

- 参照は **スキルディレクトリ基準の相対パス**で書く（例: `./references/schema.md`、`./scripts/report.py`）。読む側は SKILL.md の親ディレクトリを起点に解決する。
- SKILL.md は 500 行以内を目安にする。長い説明は `references/` へ分け、SKILL.md には「いつ読むか」を書く。
- スクリプトは標準ライブラリを優先し、実行例もスキルディレクトリからの相対で書く（cwd からの相対にしない）。

## 4. 作る・検証する

1. 用途を 1 文で確認し、`name` と `description` を決める。既存スキルと同じ用途なら、作る前にユーザーへ確認する。
2. `write` で `<置き場所>/<name>/SKILL.md` を作る。
3. 補助ファイルがあれば作る。
4. 検証する。
   - `read` で SKILL.md を読み、frontmatter の `name` / `description` が規約どおりか確認する。
   - `find` / `ls` で参照先（`./references/...` など）が実在するか確認する。
   - 同じ `name` のスキルが無いか確認する。あれば勝手に上書きせず、どちらを残すかユーザーへ聞く。

## 5. ユーザーへ伝える

- 作成したパス（どのスキルがどこにできたか）。
- 有効になるタイミング: **新規セッションと復元セッションから**。発見一覧はセッション作成・復元のたびに取り直すため、作成済みのセッションには遡及しない。
- 共通とプロジェクトで同名のスキルがある場合は `プロジェクト > 共通` の優先順位で決まり、影になった側は設定 → スキルで警告される。
- 設定 → スキルでは読み取り専用として見える（GUI からは編集できない）。

## やってはいけないこと

- 既存のスキルを確認なく上書きする。
- `description` を空にする。`name` に大文字・空白・日本語を使う。
- `.pi` 配下やホームに書く。
- スキルと関係ないファイルを作業ディレクトリ直下に散らかす。
