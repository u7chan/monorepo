# ヘッドレスブラウザで確認する

サンドボックスの `bash` から `u7agent-browser` を叩く。ヘッドレス Chromium・日本語と絵文字のフォント・外部到達のポリシーはイメージに同梱済みで、自分で入れるものは無い。

- 向いている: `serve` したアプリの動作確認、スクリーンショット、DOM の確認、クリックや入力の再現。
- 向いていない: 外部ページの取得・検証、認証が絡むフロー、GPU を使う描画（WebGL / 動画 / 音声）。

## 手順

1. `serve` ツールの `debug_start` でアプリを起動し、応答のポートを控える。URL は `http://127.0.0.1:<port>/`。ユーザーに見せるときだけ `serve` ツールの `start` で `0.0.0.0:8080` に出す（確認のループで公開枠を占領しない）。
2. `u7agent-browser check http://127.0.0.1:18000/` で読み込みと描画を確かめる（ポートは `debug_start` の応答に合わせる）。失敗が 1 件でもあれば終了コード 1 で、原因は出力に分類つきで出る。SPA の初回描画を待つなら `--wait-for-selector <selector>` を足す。
3. 期待どおりなら `u7agent-browser shot http://127.0.0.1:18000/ shot.png` で撮る。stdout に出るのは**実際に保存したパス**で、要求した名前とは連番の分だけずれ得る。
4. 返されたパスを `read` して目視する。画像が返ってきたら、そのパスで `![ホーム画面](shot-1.png)` のように本文へ貼る。
5. 画像に写らない失敗（クリック後の遷移、コンソールの例外など）は `run` のスクリプトで再現し、ログや `check` の出力で示す。

ユーザーへは「何を確認して、何が分かって、何がまだ分からないか」を書く。ユーザー自身がトップバーの「サービス」から開く導線は `serve` の話で、このスキルはエージェント側の確認を担う。

## コマンド

| コマンド                            | 用途                                                                                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `check <url> [--wait-for-selector]` | console.error / 未捕捉例外 / HTTP 4xx・5xx / 失敗したリクエスト / 遷移と ready selector の失敗を分類つきで集める。失敗 1 件で終了コード 1 |
| `shot <url> <out.png> [flags]`      | PNG を保存し、保存した cwd 相対パスを 1 行だけ stdout へ出す                                                                              |
| `dom <url>`                         | レンダリング後の HTML を stdout へ出す（上限で切り詰められ、その旨が stderr に出る）                                                      |
| `run <file.mjs> [--deadline-ms]`    | `{ page, context }` を受け取るスクリプトで操作する（任意コード）                                                                          |
| `--self-test`                       | 同梱物と外部到達ポリシーの自己診断。イメージの probe 用で、通常は使わない                                                                 |
| `--help`                            | フラグ・既定値・資源上限・起動引数の正                                                                                                    |

終了コードは 3 値。`0` 正常（`check` は失敗 0 件）、`1` 検証失敗（`check` の失敗、`run` のスクリプトの例外）、`2` 起動と入力のエラー（引数の誤り、ブラウザの起動失敗、期限超過）。`check` の `1` はアプリが失敗した意味で、ツールの不具合ではない。

ループバック以外の URL を渡すと、`shot` / `dom` はサブコマンドの入力として拒否されて `2`、`check` は遷移の拒否を `navigation` の検証失敗として集めるため `1` になる。同じ拒否でもサブコマンドで終了コードが違うので、`1` のときは出力の分類（`[失敗] navigation: ...`）まで見て、拒否とアプリの失敗を分ける。

## スクリーンショットの契約

- 既存ファイルは上書きしない。`shot.png` があれば `shot-1.png` になり、**連番の分だけ返るパスが変わる**。本文にも `read` にも、返されたパスだけを使う。
- 返るのは cwd 相対の実パス。呼び出し元の cwd（作業ディレクトリ）が保存先になる。
- 保存できるのは `.png` だけ。親ディレクトリは作られる。
- 既定は viewport の 1 画面で、`--full-page` はページ全体、`--width` / `--height` はスマホ幅などの確認に使う。既定値は `--help` を見る。

## 画像が見えるとき・見えないとき

`read` が画像を返すのは、モデルが画像を扱えるときだけ。扱えないモデルのときは `[Current model does not support images. The image will be omitted from this request.]` の注記だけが返り、画像は送られない。

- 画像が返らなかったら、画像を見た前提で報告しない。`dom` の HTML と `check` の出力で分かることだけを言い、見た目は未確認だと明示する。
- 画像を作ったこと自体は `shot` が返したパスで分かる。本文へはパスを貼り、ユーザーがプレビューで見られるようにする。

## 外部到達と `--no-sandbox`

- 通信できるのはループバックの `127.0.0.1` / `localhost` / `[::1]` だけ。外部 URL を直接渡すと `ループバック以外へは通信しません: <url>`、ループバックのページが外部へ redirect すると `外部へ redirect されました: <url>` で失敗する（HTTPS の redirect では `net::ERR_TUNNEL_CONNECTION_FAILED` のようなブラウザ側のエラーになる）。URL の別名（`127.0.0.2` など）も拒否される。
- `data:` URL は通信ではないので使える。静的な HTML をその場で確かめたいときはこれで足りる。JS や相対アセットが要るなら、空きポートで一時サーバーを立てる。
- 外部ページの取得・検証は対象外。`curl` で外部 HTML を取ってループバックで serve して開く迂回も方針違反として扱う。
- `--no-sandbox` はこの実行環境では必須で、CLI が常に付ける。自分で chromium を起動しない（付いていないと `No usable sandbox` で落ちる）。`apt` や `npm` でブラウザを入れ直す必要も無い。
- `run` は任意コードなので、外部到達のポリシーは標準経路（`shot` / `dom` / `check` / `--self-test`）にだけ効く。解除する手段は塞いでいないが、外部ページを対象にしてよいという意味ではない。

## `run` の使い方

- スクリプトは `.mjs`。既定 export の関数が `{ page, context }` を 1 つ受け取る。

```js
export default async ({ page }) => {
  await page.goto("http://127.0.0.1:18000/"); // debug_start が返したポート
  await page.getByRole("button", { name: "送信" }).click();
  await page.waitForURL("**/done");
};
```

- ドライバの解決は CLI 側に閉じているため、スクリプトから `playwright-core` を bare import では解決できない。`chromium.launch` でブラウザを開くこともできない（起動と終了は CLI が持ち、呼び出しをまたいで状態は残らない）。
- 期限は読み込みと実行の両方を覆い、超過するとブラウザと一時領域を回収して終了コード 2 で終わる。
- 用途は `shot` / `dom` / `check` で足りない確認（クリック、入力、複数ページ、console やネットワークの購読、`evaluate`）。

## 落ちたときのログの見方

診断は stderr に `u7agent-browser: ...` の形で出る。代表的な行と原因:

| ログ                                                                            | 原因                                                                       |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `No usable sandbox`                                                             | `--no-sandbox` が付いていない。自分で chromium を起動していないか          |
| `Failed to create headless user data directory container.`                      | `HOME` が書き込める一時領域の外にある。自分で起動していないか              |
| `chrome_crashpad_handler: --database is required`                               | 同じく `HOME` の場所。プロファイルの場所を自分で指定していないか           |
| `ループバック以外へは通信しません: <url>` / `外部へ redirect されました: <url>` | 外部到達の拒否。URL がループバックの 3 表記か、redirect していないかを見る |
| `期限 (<ms> ms) を超えました`                                                   | アプリが応答しない、またはスクリプトが終わらない                           |

ログと原因は一対一ではない。1 つの原因が複数の行に出るし、dbus の接続失敗や `Failed to adjust OOM score of renderer` のような無害な行も混ざる。**最後の 1 行だけで判断せず、並んでいる行と終了コードをまとめて読む**。

## 保証しないこと

- GPU を使わないソフトウェアレンダリング。WebGL / 動画 / 音声の再生は対象外で、その描画結果は正にならない。
- headless なので、実機のタッチ操作や音の挙動は近似でしか分からない。実機固有の見た目・操作は対象外と伝える。
- 外部ページと認証が絡むフローは対象外。ログインが必要なアプリは、認証を通した状態を作る手段が無い。
- OS レベルの通信制限ではない。生の `bash` からの通信は制限されていない。
- renderer サンドボックスは無い。イメージの制約を緩める根拠にしない。

## やってはいけないこと

- 自分でブラウザやドライバを導入する（`apt` / `npm i playwright` / ホームへの展開）。同梱物が正で、版も固定されている。
- 8080 を自分用の確認サーバーで使う（公開枠はユーザーに見せるときだけ。アプリの確認は `debug_start` の 18000 帯で行い、静的 HTML を一時サーバーで見るような別経路が要るときは `--port 0` のような動的な割り当てを使う。8080 を掴むとユーザーの公開が壊れる）。
- 要求した保存パスを本文へ書く（返されたパスが正）。
- `check` の失敗を `shot` だけで隠す。画像に写らない失敗を画像の合格で打ち消さない。
- 画像を見ていないのに「見た目は問題ない」と言う。
