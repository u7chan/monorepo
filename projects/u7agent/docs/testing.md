# テスト方針と GUI 受入

追加時の判断基準は [AGENTS.md](../AGENTS.md#テスト方針)。実行は `pnpm check`。server の API・sandbox・secrets・session persistence テストは減らさず、client の reducer、parser、パス解決、保存・fallback、制御ロジックも自動テストする。

サービスの公開経路は server 側の振る舞いテストで固定する。`server/test/service-proxy.test.ts` が、3 本目のリスナーからサンドボックスの 8080 への転送（メソッド / パス / クエリ / ボディ / ストリーミング / `Range` / `Content-Encoding` の透過、ホップバイホップ ヘッダの除去）、キャッシュ ヘッダの `Cache-Control: no-store` への正規化、GET / HEAD の再検証ヘッダの遮断、`Location` の書き換え、上流停止時の 502 を検査する。ポートの解決（`PI_SERVICE_LISTEN_PORT` / `PI_PREVIEW_PORT`）と `pnpm dev` が同じ値を渡すことは `server/test/preview-port.test.ts` が検査する。

- 左バーの会話行の ⋯ に「AI要約」と状態 (未実行 / 実行中 / 済み / 失敗 / 無効 / スキップ) が文字で出る。
  **常設のバッジ / チップは出ない。** 押すと desktop はダイアログ、singleColumn は下からのボトムシートになり、
  現在のタイトル・モデル・Effort・トークン・所要時間・失敗理由が出る。背景の操作は inert で、Escape で閉じ、
  閉じた後に元の ⋯ へ焦点が戻る。
- 再要約を押すと確認が出て、キャンセルでは生成しない。実行すると「要約中…」になり、完了後にタイトル・状態・
  usage・所要時間が更新され、サイドバーの行とヘッダのタイトルも追随する。手動で付けた名前では確認本文が
  「手動で変更したタイトルを…」に変わる。
- 会話を開いたまま自動要約が成功 / 失敗すると、チャット上に 1 回だけお知らせが出て「詳細」で同じダイアログが

  行メニューとダイアログの状態・使用モデル・Effort・失敗理由が残る。
- 設定 → 会話タイトルの「動作確認」は、保存済みの設定で固定のサンプルだけを送り、結果 (成功 / 失敗・生成タイトル・
  モデル・Effort・トークン・所要時間) を出す。会話一覧は増えず、どのタイトルも変わらない。Off / モデル未選択 /
  モデル利用不可ではボタンが押せず、理由が出る。設定を変えると前の結果は消える。この操作は本文を外部へ送るが、
  利用者の会話は送らない。

- [ ] OS からファイルを掴んでツリーの上に来ると破線のドロップゾーンが出る。子要素の上を通っても点滅せず、面の外へ出る / `Escape` / ドロップで消える。フォルダ行を入力欄へドラッグする既存の参照ドラッグでは出ない
- [ ] ドロップすると件数が進行表示に変わり、完了後にワークスペース root の一覧へファイルが増える。同時に送るのは 3 本までで、待機中に別のドロップを足しても増えない
- [ ] 送信中に別のドロップを足しても、先に完了した同じバッチの成功件数と連番の案内が消えない。全件の決着後は、次の独立したドロップで前回成功だけが結果から外れる（失敗は残る）
- [ ] 一覧の初回取得を遅らせ、その間にアップロードを完了させてから古い一覧応答を解放しても、その後に一覧が取り直されて新しいファイルが現れる（手動の再読み込みを要しない）
- [ ] 11 件以上 / 100 MiB 超を含むドロップでは、受け付けた分だけ保存され、残りはファイル名と理由が結果に残る。成功と失敗が混ざっても成功したファイルは一覧に出る
- [ ] 同名のファイルをドロップすると上書きされず、`name-1.ext` の連番で保存され、その旨が結果に出る
- [ ] サンドボックス停止中 / API 失敗時は理由が結果に残り、一覧は変わらない。結果は閉じるまで消えず、閉じると消える
- [ ] 作業環境の作業フォルダへドロップすると、そのセッションの作業フォルダ直下（ワークスペース root ではない）へ保存され、run の終了を待たずに一覧へ出る。結果はパネルを閉じるまで残る
- [ ] 同じ root を共有する別会話へ切り替えても結果が残る。root が変わる会話へ切り替える / パネルを閉じる / シートを閉じると実行中の要求は中断し、別の作業フォルダへは保存されない
- [ ] 作業環境の環境変数タブ / スキル面ではドロップゾーンが出ない（設定 → ファイル の「ダウンロードの除外」タブも同じ）
- [ ] モバイル幅 / タッチ操作には新しい入口が無い（タッチでは drag が起きない。設定 → ファイル の既存の閲覧・削除・リネームは従来どおり）

desktop と singleColumn の両方で次を確認する。

- 既定から新しい追加スペースへ切り替えると空の会話一覧・新規会話になり、Projects / New Project が出ない。会話一覧の見出しは「Chats / 未所属」のままで、チップが選択中の会話スペース名になり、押すと 設定 → 会話スペース（`/settings/spaces`）へ移る。同ページは作成フォームが一覧より上にあり、追加スペースが増えても一覧はページスクロールで見える。
- 会話スペースの一覧をグリップのドラッグで並べ替えると順序が変わり、F5 / 別タブ / 別ブラウザーでも同じ並びになる。**既定スペースの行にはグリップが無く**、追加スペースだけが動く。行の本体（選択）と ⋯ の押下ではドラッグが始まらず、ドラッグ中に `Escape` で取り消せる。ドラッグの待ちに別のスペースを作成 / 削除しても、遅れて届いた応答で一覧が巻き戻らず、新しい行はその場に残り削除済みの行は戻らない（保存の失敗は理由を出し、応答が返らなければ表示を戻さず次のドラッグを開く。ページを離れると下書きは捨てられ、最後に確定した順へ戻る）。
- 削除待ちの行がドラッグ中に消えると、そのドラッグは取り消され、見えない位置で並びが動いたり保存されたりしない（掴み直せば並べ替えられる）。保存待ちに別の設定へ移って戻っても、**離脱前に始めた保存の遅い応答では新しい並びが巻き戻らない**。
- 会話を送信し、添付・作業フォルダ・環境変数・サービス操作が追加スペースの cwd を使う。共通スキルは利用でき、設定 → ファイルは workspace 全体を表示する。
- 既定へ戻ると既存のプロジェクトと会話が戻り、追加スペースへ戻るとデモ会話が残る。切替だけではランを停止せず、戻って結果を確認できる。
- 入力中・添付中・作成待ち・実行中に切り替え、旧下書き・添付・ファイル面・先行選択・遅い成功 / 失敗 / busy が新しい表示へ混ざらない。後続の送信 / upload は開始元の所属で続行する。
- 設定保存後のカタログ再取得を遅延させ、待機中にスペースを切り替えて別のエージェントを選ぶ。旧応答後も共有保存値が巻き戻らず、リロード・再切替後に選択を保つ。mount 世代の失効と共有保存値の保護は `client/test/mountScope.test.ts` でも検証する。
- スペースを選んでタブを閉じて開き直す / ブラウザーを再起動 / 新しいタブで開くと、同じスペースが復元される。`localStorage` を消すと既定スペース、保存 ID を未知 / 不正へ変更するか一覧取得を失敗させると、理由と選び直し / 再取得を出し、既定スペースの会話を誤表示しない。
- 他タブで切替えても既存タブは変わらず、そのタブのリロードで追随する（URL に `space` があればその値、なければ最後に書いた保存値が正になる）。
- 他スペースの `/s/<sessionId>` は会話を開かず既存の見つからない旨を出し、自動切替しない。通知リンク / 設定 → ランタイムの「起動元の会話」のリンクは、保存値が別のスペースでもその会話の所属で開く（通常クリックはそのスペースへ切り替えて URL を `/s/<sessionId>?space=<spaceId>` にし、`?space=` 付きのリンクも開いた後まで同じ URL を保つ。他のクエリとフラグメントは残る）。開いた会話は URL (`/s/<sessionId>?space=<spaceId>`) に残り、F5 で同じ会話が開く。**その URL をコピーして、別のスペースを保存しているブラウザー / プロファイルで開くと、その会話が開ける**（`space` を落とした `/s/<sessionId>` は保存値のスペースで解決する）。`?space=` が未知なら復旧画面になり、選び直した後に F5 しても復旧画面へ戻らない。プロジェクト dialog / ファイル面の残存や操作不能、SSE 再接続・削除後 fallback の混線が無い。
- 未所属の会話を ⋯ から引き継ぐ（エージェントとスペースを選ぶ）。実行すると移動先のスペースへ切り替わり、一覧に出て、作業フォルダのファイルと添付があり、履歴は空（`messageCount` は 0、未送信は消える）で、タイトル・ピン・通知は変わらない。引き継ぎ後の入力欄にチップ「HANDOFF.mdを参照」が出て、付けたまま送ると指示文が送信本文に入り、✕ で外して送ると入らない。チップは送信後は戻らず、リロード / 別スペースへ切り替えて戻ると同じ状態で戻る（送信済みなら出ない）。F5 / BFF 再起動後も同じで、移動元のスペースには残っていない。プロジェクト配下の行にも項目が出て、スペースの選択は出ず、メモの説明に保存先（リポジトリ直下）とコミット / 除外が利用者判断であることが出る。現在のエージェントを選ぶとスナップショットが維持され、実行中は項目が押せず、メッセージ 0 件ではメモを作れない理由が出てメモ OFF なら実行できる。**引き継ぎ前から履歴を表示していても、開き直した時点で旧バブルが消える**（同じ会話 id のまま履歴が入れ替わる。空の応答で古い発言が残らない。履歴の応答をブラウザの routing で遅らせても古い発言が戻らない）。片付けが残った応答では、移動先のスペースへ切り替わったあとの状態行に警告が出る（会話の GET が 409 の間も出る）。
- 設定 → 会話スペースで追加スペースを作り、会話・添付・環境変数を作ってから行の ⋯ で削除する。確認ダイアログにスペース名と消える対象（会話・履歴・作業フォルダのファイル・添付・環境変数とサービス実績）と実行中の会話が止まることが出て、初期焦点は「キャンセル」、Escape でも閉じ、取り消したら何も消えない。**既定スペースの行には ⋯ が出ない。** 削除すると一覧からその行が消え、既定スペースと他の追加スペースの会話・環境変数・ファイルは無傷で、実行中の会話は止まる。選択中のスペースを消すと**手動で戻らずに**会話を持たない chat（`/`）へ移り、既定スペースの新規会話になってから、そのまま F5 しても既定が開く（復旧画面にならない）。選択していないスペースを消しても選択と URL は動かない。削除待ちの行を選び直しても（両方向）、後着の応答で新しい選択を巻き戻さない。
- 対象スペースのサービスが公開中なら削除は 409 になり、案内（設定 → ランタイムで停止）が一覧の `role="alert"` 行に出て、一覧・選択・ファイルは変わらない。

### 有料 API を使わない GUI fixture

プロジェクト root で `ROOT=$(mktemp -d /tmp/u7agent-spaces-e2e-XXXXXX)` を作成し、同じ ROOT を各ターミナルに渡す。既存の `.env` や本番ストアを使わない。ポートが空いていることを確認して次を別プロセスで起動する（競合時は 3 ポートとも別の空き値へ変える）。

```bash
# terminal 1: 実ファイル操作用の一時サンドボックス
mkdir -p "$ROOT/workspace" "$ROOT/store"
PI_SANDBOX_CWD="$ROOT/workspace" PI_SANDBOX_TOKEN=spaces-e2e-local-token \
  SANDBOX_HOST=127.0.0.1 SANDBOX_PORT=17991 pnpm --filter server start:sandbox

# terminal 2: 認証情報・LLM を使わない stub pi の BFF
U7AGENT_FIXTURE_ROOT="$ROOT" PI_SANDBOX_URL=http://127.0.0.1:17991 \
  PI_SANDBOX_TOKEN=spaces-e2e-local-token PORT=17990 \
  pnpm --filter server exec tsx test/spaces-fixture.ts

# terminal 3: UI（通常の pnpm dev は起動しない）
```

`http://127.0.0.1:17992` を開く。fixture は通常のプロジェクトと会話を 1 件ずつ用意し、再起動時は既存データを保持する。**追加スペースは fixture が作らないので、引き継ぎを見るときは 設定 → 会話スペース（`/settings/spaces`）で作成してから行う**（未所属の会話を行の ⋯ から引き継ぐか、プロジェクト所属なら同じスペースのままエージェントだけ代える）。stub の応答は実ツールを呼ばないため、モデルによるファイル生成は受入結果に含めない。状態行のツール表示は stub が流す 3 つのシナリオで受入できる。`investigate` の進捗は依頼文（例: 「リポジトリの docs 構成を調べ…」）で、連続ツール呼び出し（速い順次 + 並列）は本文に `連続ツール` を、最後のツールの後に届く one-shot 行は `高速ツール` を含めて送ると始まる（後者は start と end が同じ時刻の行が 1 本だけ届く。**有料 API なしで何度でも再現できる**）。ツール履歴のターン集約は、本文に `応答ごとツール` を含めて送ると始まる（ツール 1 件につき本文を持たない assistant 応答を 1 通積み、最後に本文を 1 通流す。`連続ツール` は全呼び出しを 1 通の応答に載せるため、応答境界をまたぐ形にはならない）。生成バッジの受入は、本文に `画像バッジ` / `画像バッジ本文なし` / `音声バッジ` / `モデル行なし` / `生成失敗` / `複数モデル` を含めて送ると始まる（それぞれ `generate_image` / `generate_speech` の結果本文を流す。`モデル行なし` はモデル行を書く前のセッション、`生成失敗` は結果本文を残さない失敗カード、`複数モデル` は同じターンに別モデルの 2 枚で、どれも実 API を呼ばない）。検索プロバイダーのチップの受入は、本文に `検索チップ`（成功）/ `検索失敗`（失敗）/ `検索と生成`（同じターンに生成と検索）を含めて送ると始まる（`web_search` の結果本文を流すだけで実 API は呼ばない）。生成音声のプレイヤーは `音声バッジ`（モデル行あり）/ `音声2本`（同じターンに mp3 と wav の 2 本）/ `音声モデル行なし` / `音声失敗` で見る（再生には一時ワークスペースに実ファイルを置く。stub は結果本文しか流さず、ファイルは作らない）。生成物のキャプションは `画像バッジ`（本文の Markdown 画像 1 枚）/ `複数モデル`（同じターンに別モデルの 2 枚）/ `画像再掲`（生成カードを流さないターンで、再掲と `cp` したコピーの画像を出す）/ `音声バッジ`（プレイヤーの直下）で見る。圧縮は、本文に `自動圧縮` を含めて送ると user message を積む前に 1 回だけ自動（preflight）で走り、手動圧縮のボタンは 1 回目が成功・2 回目が失敗（`too-small`。区切りも所要時間も出ない）で、3 回目以降は成功に戻る（同時に成功と失敗の見た目を 1 セッションで確認できる）。履歴ページの窓（50 item）より長いターンは、本文に `長いターン` を含めて送ると 1 run で本文あり応答を 55 件積む（ターン終端の `Done ·` の受入用）。添付 / ファイル画面は実サンドボックス経由で確認できる。遅い要求や取得失敗はブラウザの routing で注入する。実サービスの公開・モデル / 画像 / 検索設定の外部通信は使わない。終了後は全プロセスを停止して、この ROOT だけを削除する。

### 生成物の実ファイルの置き方

stub は結果本文だけを流すため、画像のプレビュー・拡大・キャプションと音声の再生の受入に使う実ファイルは、その会話の作業フォルダ配下の `generated/` に手で置く（パスはシナリオの結果本文と一致させる）。**未所属の会話の作業フォルダはワークスペース root ではなく、ストアあり（fixture は一時ストアを使う）では会話ごとのスクラッチ `<workspace root>/.u7agent/sessions/<id>`**（`<id>` は会話 URL `/s/<id>` の ID）。プロジェクト配下の会話はそのプロジェクトのディレクトリ。

```bash
SESSION="$ROOT/workspace/.u7agent/sessions/<id>"
mkdir -p "$SESSION/generated"
ffmpeg -f lavfi -i "sine=frequency=440:duration=2" -c:a libmp3lame -y "$SESSION/generated/night-platform-cat-intro.mp3"
ffmpeg -f lavfi -i "sine=frequency=440:duration=2" -y "$SESSION/generated/night-platform-cat-intro.wav"
for name in night-platform-cat cat-a cat-b cat-copy; do
  ffmpeg -f lavfi -i "color=c=gray:s=320x200" -frames:v 1 -y "$SESSION/generated/$name.png"
done
```

右パネルの作業フォルダ面でも同じ場所が見えるので、置いたファイルはそこで確認できる。ファイルを置かなくてもキャプションは出る（画像の読み込みに失敗しても対応が取れていれば出す）。配信の失敗として見えるのは画像 / 音声そのもので、キャプションの有無とは別に切り分ける。

### singleColumn の操作面（メニュー / 選択一覧 / 行操作）

上の viewport 表に加えて、popover を開いたまま境界を跨ぐリサイズ / 回転と、低い窓、検索入力とソフトキーボード、長い日本語 / ID / パスを見る。次の 3 群に分けて確認する。

- [ ] **到達性**: ⋯ と選択肢の見た目は desktop と同じで、押せる範囲だけが広がる。拡張した範囲の端を押しても開き、隣の選択が発火せず、clip で欠けない。行の高さが足りない面でも隣の行の ⋯ と重ならない。実機（iOS Safari / Android Chrome）で ⋯ とメニュー項目が押せ、ソフトキーボード表示中も popover が収まる

- [ ] **キーボード・焦点**: Tab / Shift+Tab が popover の外へ出ると閉じ、`Escape` はパネルだけを閉じて背面の画面と焦点を変えない。disabled の項目を飛ばして ↑↓ が動き、閉じた後に焦点が開いた ⋯ へ戻る。スクロールで ⋯ が clip の外へ出たらメニューが閉じる
