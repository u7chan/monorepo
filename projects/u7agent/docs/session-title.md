# 会話タイトル

一覧のタイトルを、定型プロンプト (エージェント定義の `suggestions`) の先頭ではなく利用者の依頼から作り、
設定で選んだモデルによる AI 要約で一度だけ整える。設定の実体は
`server/src/title-summary-settings.ts`、入力の抽出と正規化は `server/src/session-title.ts`、
実行の判断 (タイミング・試行・競合) は `server/src/sessions.ts` が持つ。

## タイトルの作り方

| 状態 | タイトル |
| --- | --- |
| AI 要約 Off | 依頼本文から作る (タイトル用の AI 呼び出しをしない) |
| AI 要約 On・応答前 / 実行中 | 同じ非 AI タイトルを仮タイトルとして即時に出す |
| AI 要約 On・初回の本文あり正常完了後 | 1 回だけ非同期に生成し、成功したら仮タイトルを置き換える |
| 生成の失敗・モデル不在・予算超過 | 仮タイトルを維持し、自動再試行しない |
| 手動で改名済み | 自動処理で上書きしない (会話メニューから明示的に再要約したときだけ置き換える) |

非 AI タイトルの入力は、client が定型プロンプトを結合する前の本文 (`titleSource`) を使う。
サーバーはそこから**先頭のスキル参照だけ**を外し、`/skill:name 依頼` は `依頼`、
`<skill …>…</skill>` ブロックは後ろの依頼、引数の無いスキル指定はスキル名をタイトルにする。
`/skill:` を参照として外すのは、タイトルに使う文字列が送信本文そのもので、かつその指定を
**実際に展開できたとき**だけにする。定型プロンプトを結合した送信では、展開されたのはプロンプト側の
指定であり、個別依頼の `/skill:` は展開されない。この展開結果を流用すると、未知の指定をタイトルだけ
別の意味に解釈してしまう (保存メッセージには指定が残る)。
先頭以外の `/skill:`、認識できない XML 風タグ、コードフェンスの中身は本文として残す
(任意のタグを一律に削ると依頼そのものが消えるため)。

`titleSource` を送らない従来形式の送信は、本文全体から同じ規則で抽出する (既存の送信契約は変えない)。

## 画面

左バーの会話行の ⋯ に「AI要約」を出し、右端に状態 (未実行 / 実行中 / 済み / 失敗 / 無効 / スキップ) を
文字で出す。常設のバッジやチップは置かない (狭いヘッダと一覧を記号で埋めない)。押すと desktop は
ダイアログ、singleColumn は下から出るボトムシートで、現在のタイトル・状態・モデル・Effort・トークン・
所要時間・失敗理由を出す。「再要約」は確認後に実行し、「設定を開く」は設定 → 会話タイトルへの
テキストリンクにする。

開いている会話で AI 要約が成功 / 失敗したときは、チャット上に 1 回だけお知らせを出し、詳細から同じ
ダイアログを開ける。会話を開いた時点で既に終わっている試行は再表示しない (履歴を遡るたびに出さない)。
Off で判定だけ残った会話やスキップはお知らせを出さず、行メニューとダイアログで示す。文言と色の対応は
`client/src/lib/sessionTitleStatus.ts` が持つ。

## 設定

`GET/PUT /api/settings/session-title` がアプリ DB の 1 行 (`title_summary_settings`) を読み書きする。
行が無い = Off・モデル未選択・Effort 未指定・既定の定義。会話履歴の compaction の要約とは別の機能で、
本会話のモデルとも独立している。

- Off でもモデル・Effort・定義は保持する。過去のタイトルは一括再生成せず、既存データは変更しない。
- On の保存には、その時点で認証済み・利用可能なモデルを要求する。未選択・不明なモデルは 400。
- Effort は選択モデルが対応する段階だけを保存できる。未対応の段階は 400。未指定のときは実行時に
  モデルの最小段階へフォールバックする。モデルを変えて Effort を省略した場合、新モデルが対応しない
  保存値は未指定へ戻す。
- 定義は空白だけ・上限超過を 400 にし、既定文へ戻せる。
- 選択モデルが後から利用不可になった場合は `modelAvailable: false` で警告し、要約だけを飛ばす
  (別モデルへ無断で切り替えず、会話の送信も止めない)。保存済み Effort がモデルの段階から外れた場合も、
  実行時は最小段階へフォールバックし、結果を適用する前に設定の世代で古い結果を捨てる。
- 定義で解除できない固定の安全策: ツールを渡さない・入力と出力に予算を置く・出力を 1 行に検証する・
  既知の秘密値をマスクする・自動要約で手動改名を上書きしない。
- 設定画面の「動作確認」は `POST /api/settings/session-title/test` で、保存済みのモデル / Effort / 定義と
  固定のサンプル入力 (利用者の会話は送らない) で 1 回だけ生成する。結果 (タイトル / usage / 所要時間 /
  モデル / Effort) は画面に出すだけで、会話にもタイトルにも保存しない。Off / モデル未選択は生成せず
  理由を返す。生成の失敗は 200 の `ok: false` で返す。

## 実行のタイミングと試行

判定点は**初めて本文を伴う正常完了が得られたラン**の直後 (`run_end` の `completed` と、そのランの確定応答)。
途中応答・ツール実行中・`ask_user` の回答待ち・停止・エラーでは生成しない。最初のランが失敗した場合は、
後に初めて本文あり正常完了となったランが判定点になる。

- 判定は会話ごとに 1 回だけ記録し (`meta.titleAttempt`)、Off などの理由で対象外でも後続のターンや設定変更で
  再走査しない。失敗しても再試行しない。
- 予約 (状態 `pending`) は外部呼び出しより先に meta へ保存する。再起動・複数タブ・クラッシュで重複実行しない。
  `titleOrigin` / `titleAttempt` は読み込みでも復元し、添付のみで `skipped` になった会話を再起動後に再走査しない。
  予約のまま落ちた会話は、**起動時の descriptor 復旧**と会話を開いたときの両方で `skipped` / `interrupted`
  として保存し直す (未ロードの一覧・行メニューも永久に「実行中」と見せない)。
- 本文の完了・保存・通知・次の送信は、要約の完了を待たない。
- 生成は独立した短いリクエストで、会話の SDK セッションへ「タイトルを作って」というメッセージを足さない。
  会話の SDK セッション ID を `sessionId` として渡す。opencode-go のようにリクエストのルーティングへ
  `x-opencode-session` を要求するプロバイダーは、この値が無いと要約を受け付けない。
- 予約の `persist()` が失敗したときは外部生成を開始しない (試行を保存できないまま送ると、クラッシュ後に
  試行済みかを復元できない)。予約の task は保存より先に立て、保存待ちの間の Off・手動改名でも取り消せる。
- 予約時にモデル・定義・設定の世代を確定し、保存後 (Off への変更・再保存) や手動改名の後に届いた結果は捨てる。
  Off への変更は未開始の処理を取り消し、進行中の呼び出しも中断する。
- 実行は共有の低優先度キュー (同時実行数の上限・待ち時間の上限) を通す。順番待ちの間に本会話が動き出したら
  補助呼び出しは捨て、本会話の送信を待たせない。
- 要約 task (`titleTask`) が残っている間は idle sweep の対象外にする。未選択の古い会話を再要約している間に
  sweep が走ると record がメモリから外れ、API は成功しても結果を保存できないため。
- 入力は依頼本文と対象ランの最終応答を中心に、固定指示と定義を含めて文字数予算で切る
  (長い応答が先に予算を使い切って個別依頼を落とさない)。全履歴・ツール出力・添付の中身は送らない。
- 出力は 1 行だけを受理し、前後の引用符・見出し・`タイトル:` を落として先頭 60 文字に切り詰める。
  複数行・空・**出力トークン上限での打ち切り (`stopReason: "length"`)** は不正として仮タイトルを維持する。
  推論トークンも出力上限に含まれるモデルがあるため、出力予算は可視テキストの長さとは分けて確保し、
  可視テキストが長すぎる 1 行もタイトルとして採用しない。
- 要約へ送る入力 (依頼本文・対象ランの最終応答・編集可能な定義・固定指示) は、外部呼び出しの直前に
  マスクする。受信時のマスクだけでは、定義の編集や受信後に登録された秘密値を保護できない。
- 予約 (`pending`) と終端 (`done` / `failed` / `skipped`) のたびに `resync` を配り、
  `SessionPayload.titleSummary` / `SessionSummary.titleSummary` に状態を載せる (診断を開かなくても
  一覧・チャット・ダイアログが追従する)。`titleSummary` は `{ origin, attempt? }` で、`attempt` は
  `state` / `trigger` (`auto` / `manual`) / モデル / Effort / usage / `durationMs` を持つ。
  実行しなかった理由は `skipReason` (`disabled` / `model-unset` / `manual` / `no-request` / `cancelled` /
  `settings-changed` / `not-ready` / `interrupted`)、失敗理由は `error` (マスク済み・300 文字上限) に載せる。
- 使用モデル・Effort・usage・費用は補助呼び出しとして `GET /api/sessions/:id/diagnostics` の `title.attempt` にも載せる。
  タイトルを採用できなかった失敗・結果を捨てた場合も、取得できた usage は残す (失敗した要求が無料とは限らない)。
  Off で取り消した後に届いた中止応答も、タイトルは適用しないが usage は残す。
  依頼本文と生成タイトルは診断へ載せない。
- 取消は `AbortSignal` として実際のモデル呼び出し (`completeSimple`) まで渡す (Off への変更・手動改名・停止で中断する)。

## 会話メニューからの再要約

`POST /api/sessions/:id/title/summarize` は保存済みのモデル / Effort / 定義で 1 回生成し、現在のタイトルと
試行を返す。自動の「1 会話 1 試行」とは独立で、`pending` / `failed` / `skipped` の後でも実行できる。

- 実行中・圧縮中・別の要約の実行中は 409。Off / モデル未選択 / 依頼本文なし / 要約できる応答なしも 409。
- 手動で変更したタイトルも、確認ダイアログを経た明示操作なので置き換える (自動要約は置き換えない)。
- 生成に失敗しても 200 で `titleSummary.attempt.state = "failed"` と `error` を返し、現在のタイトルは保つ。
  画面は応答の試行をそのまま出し、一覧を取り直す。
- 依頼本文は送信時にマスクした先頭 600 文字を `meta.titleRequest` に残し、再起動後も同じ入力を使う。
  旧 meta で欠落している会話だけ最初の user メッセージから作る (定型プロンプトが混ざり得る)。
- 応答は最後の完了した assistant テキストを使う (エラー / 中断の応答は対象外)。
- 入力の組み立て・マスク・出力検証・取消は自動要約と同じ経路を通す。手動実行でも usage は試行へ残す。

## 採用しなかった案

- 結合後の文字列から定型プロンプトを前方一致で推測して消す方式。参照と依頼の境界が失われ、固定文が変わると壊れる。
- 会話の SDK セッションへ追加メッセージを送ってタイトルを作る方式。会話履歴と費用が利用者の意図と無関係に増える。
- 毎ターンの自動再要約、過去会話の一括再生成、エージェント別の上書き。再実行は会話メニューから
  利用者が明示したときだけ行い、自動の試行回数は 1 回のままにする。

## 既知の制限

- 導入前の会話は、保存タイトルに由来が無いため手動のタイトルとして保護する。自動では書き換えない。
- 個別の依頼や応答にも識別情報が無い場合 (定型プロンプトだけ・添付だけ) は内容別のタイトルを保証しない。
- 選択モデルの可用性は保存時と生成時に見るが、実行中に認証が外れた場合は失敗として仮タイトルを残す。
- 再要約のために依頼本文の先頭 600 文字を `meta.json` に残す (タイトル本文より長い利用者の文が残る)。
  旧 meta の会話は最初の user メッセージから作るため、定型プロンプトが混ざる場合がある。
