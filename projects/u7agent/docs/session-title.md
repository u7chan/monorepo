# 会話タイトル

一覧のタイトルを、定型プロンプト (エージェント定義の `suggestions`) の先頭ではなく利用者の依頼から作り、
設定で選んだモデルによる AI 要約で一度だけ整える。設定の実体は
`server/src/title-summary-settings.ts`、入力の抽出と正規化は `server/src/session-title.ts`、
実行の判断 (タイミング・試行・競合) は `server/src/sessions.ts` が持つ。

## タイトルの作り方

| 状態 | タイトル |
| --- | --- |
| AI 要約 Off | 依頼本文から作る (タイトル用の AI 呼び出しをしない) |
| AI 要約 On・応答前 / 実行中 | 同じ非 AI タイトルを仮タイトルとして即時に出す |
| AI 要約 On・初回の本文あり正常完了後 | 1 回だけ非同期に生成し、成功したら仮タイトルを置き換える |
| 生成の失敗・モデル不在・予算超過 | 仮タイトルを維持し、自動再試行しない |
| 手動で改名済み | 自動処理で上書きしない |

非 AI タイトルの入力は、client が定型プロンプトを結合する前の本文 (`titleSource`) を使う。
サーバーはそこから**先頭のスキル参照だけ**を外し、`/skill:name 依頼` は `依頼`、
`<skill …>…</skill>` ブロックは後ろの依頼、引数の無いスキル指定はスキル名をタイトルにする。
先頭以外の `/skill:`、認識できない XML 風タグ、コードフェンスの中身は本文として残す
(任意のタグを一律に削ると依頼そのものが消えるため)。

`titleSource` を送らない従来形式の送信は、本文全体から同じ規則で抽出する (既存の送信契約は変えない)。

## 設定

`GET/PUT /api/settings/session-title` がアプリ DB の 1 行 (`title_summary_settings`) を読み書きする。
行が無い = Off・モデル未選択・既定の定義。会話履歴の compaction の要約とは別の機能で、本会話のモデルとも独立している。

- Off でもモデルと定義は保持する。過去のタイトルは一括再生成せず、既存データは変更しない。
- On の保存には、その時点で認証済み・利用可能なモデルを要求する。未選択・不明なモデルは 400。
- 定義は空白だけ・上限超過を 400 にし、既定文へ戻せる。
- 選択モデルが後から利用不可になった場合は `modelAvailable: false` で警告し、要約だけを飛ばす
  (別モデルへ無断で切り替えず、会話の送信も止めない)。
- 定義で解除できない固定の安全策: ツールを渡さない・入力と出力に予算を置く・出力を 1 行に検証する・
  既知の秘密値をマスクする・手動改名を上書きしない。

## 実行のタイミングと試行

判定点は**初めて本文を伴う正常完了が得られたラン**の直後 (`run_end` の `completed` と、そのランの確定応答)。
途中応答・ツール実行中・`ask_user` の回答待ち・停止・エラーでは生成しない。最初のランが失敗した場合は、
後に初めて本文あり正常完了となったランが判定点になる。

- 判定は会話ごとに 1 回だけ記録し (`meta.titleAttempt`)、Off などの理由で対象外でも後続のターンや設定変更で
  再走査しない。失敗しても再試行しない。
- 予約 (状態 `pending`) は外部呼び出しより先に meta へ保存する。再起動・複数タブ・クラッシュで重複実行しない。
- 本文の完了・保存・通知・次の送信は、要約の完了を待たない。
- 生成は独立した短いリクエストで、会話の SDK セッションへ「タイトルを作って」というメッセージを足さない。
- 予約時にモデル・定義・設定の世代を確定し、保存後 (Off への変更・再保存) や手動改名の後に届いた結果は捨てる。
  Off への変更は未開始の処理を取り消し、進行中の呼び出しも中断する。
- 入力は依頼本文と対象ランの最終応答を中心に、固定指示と定義を含めて文字数予算で切る
  (長い応答が先に予算を使い切って個別依頼を落とさない)。全履歴・ツール出力・添付の中身は送らない。
- 出力は 1 行だけを受理し、前後の引用符・見出し・`タイトル:` を落として先頭 60 文字に切り詰める。
  複数行・空は不正として仮タイトルを維持する。
- 使用モデル・usage・費用は補助呼び出しとして `GET /api/sessions/:id/diagnostics` の `title.attempt` に載せる。
  依頼本文と生成タイトルは診断へ載せない。

## 採用しなかった案

- 結合後の文字列から定型プロンプトを前方一致で推測して消す方式。参照と依頼の境界が失われ、固定文が変わると壊れる。
- 会話の SDK セッションへ追加メッセージを送ってタイトルを作る方式。会話履歴と費用が利用者の意図と無関係に増える。
- 毎ターンの再要約、過去会話の一括再生成、エージェント別の上書き。初期スコープ外 (必要になった会話は手動で改名する)。

## 既知の制限

- 導入前の会話は、保存タイトルに由来が無いため手動のタイトルとして保護する。自動では書き換えない。
- 個別の依頼や応答にも識別情報が無い場合 (定型プロンプトだけ・添付だけ) は内容別のタイトルを保証しない。
- 選択モデルの可用性は保存時と生成時に見るが、実行中に認証が外れた場合は失敗として仮タイトルを残す。
