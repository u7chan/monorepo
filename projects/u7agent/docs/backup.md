# バックアップ（エージェント定義・定型プロンプト・共通スキル）

設定のバックアップ画面（`/settings/backup`）で、ユーザー定義のエージェント・自作の定型プロンプト・共通スキル（`.agents/skills`）を 1 つの ZIP にまとめて持ち出し、別のインスタンスへ全置換で戻す。形式と plan / apply は [server/src/backup/](../server/src/backup/) が正で、文言と確認の要否は `client/src/lib/backup.ts`、状態遷移は `client/src/lib/backupFlow.ts` が持つ。画面の構成は [ui-layout.md](ui-layout.md#設定のバックアップ)、受入は [testing.md](testing.md#バックアップの受入) を参照する。

これは DB 全体のコピーではなく、定義だけを選んだ curated bundle である（[persistence.md](persistence.md#バックアップの範囲)）。会話・プロジェクト・ワークスペースのファイル・設定・API キー・共有コンテンツ・プロジェクト側スキル・組み込みの定義は入らない。

## 対象と非対象

| 対象 | 入るもの | 入らないもの |
| --- | --- | --- |
| エージェント | ユーザー定義のみ（サンプルを含む） | ビルトインの汎用アシスタント |
| 定型プロンプト | 自作のマスタのみ | 組み込みプロンプト |
| 共通スキル | `<root>/.agents/skills` の ZIP | プロジェクト側スキル、組み込みスキル |

組み込みの定義はアプリの更新に追従するため、書き出しも上書きも対象外にする。バンドルに組み込みの ID が「定義として」混ざっていた場合は 400 で断るが、`agents[].promptIds` から組み込みプロンプトを参照することは許可する（組み込みは復元先にも必ず居るため）。

## ZIP の形式

トップレベルは `manifest.json` と、`manifest.targets` に挙げた対象のファイルだけである。

```text
manifest.json   { app, schema, exportedAt, targets }
prompts.json    { prompts: [{ id, label, prompt }] }   // 自作のみ・表示順
agents.json     { agents: [...] }                      // ユーザー定義のみ・表示順
skills.zip      // 既存の共通スキル ZIP（0 件なら空の ZIP）
```

- `agents.json` はプロンプト本文を写さず `promptIds` だけを持つ。本文は `prompts.json` に 1 回だけ書く。
- `skills.zip` はスキル画面のエクスポート（`GET /api/skills/files/export`）をそのまま入れ子にする。BFF はスキルの中身を解釈し直さず、既存の検証と plan / apply を再利用する。
- `manifest.targets` と実エントリは完全一致させる。余分・欠落・重複・未知のトップレベルエントリは 400。query の `targets` は manifest の部分集合だけを許可し、省略時は manifest の全対象になる。
- `app` / `schema` の不一致、JSON の未知キー、ID の空・重複・長さ超過は 400。`exportedAt` と ZIP の mtime は同一判定に使わない。

外側の ZIP の上限（`BACKUP_MAX_BYTES`）は内側のスキル ZIP の上限（`SANDBOX_MAX_UPLOAD_BYTES`）に JSON の上限（`BACKUP_JSON_MAX_BYTES`）とヘッダ分を足した値で、export の実サイズ検査と restore の `content-length` / 読み取り上限の両方に同じ値を使う。JSON の件数とサイズの上限も 400 で断る。外側の ZIP の作成・読み取りには既存の `server/src/sandbox/zip.ts` と `server/src/sandbox/zip-read.ts` を使い、JSON は `ZipEntry.data` で一時ファイルを経由せずに入れる。

## 復元は全置換

復元は対象ごとの全置換である。バックアップに含まれる対象はバックアップの状態へ同期され、バックアップに無い既存の定義は削除される。同名でも ID が違えば別物として削除と追加になる（名前ベースのマージはしない）。バックアップに含まれない対象は変更しない。

差分は追加・更新・同一・削除・並び替えに分け、同一の行は書き換えない。差分が無ければ「変更なし」として実行できない。`変更なし` は「選択した全対象に差分が無く、ブロッカーも無い」の意味に限る（DB の差分が 0 でもスキルの差分が残る partial は実行できる）。

plan と apply は同じ正規化を通す。モデルのフォールバックと `promptIds` の除去を適用した後の実効値で差分と件数を計算しないと、fallback された項目が毎回「更新」に見えて 2 回目が「変更なし」にならない。apply は受信した ZIP とその時点の状態で再 plan する（サーバーは状態を持たず、plan と apply の間の変更は apply の再判定が正になる）。

適用の順序は「削除するエージェント → プロンプトの upsert → エージェントの upsert → 削除するプロンプト → 並べ替え」で、1 トランザクションに閉じる。`agent_prompts.promptId` は `ON DELETE RESTRICT` なので、この順序でないと適用後の参照を外せない。プロンプトの削除は「現在の自作 ID - バックアップ ID」で求め、全削除 → 再挿入はしない。使用中かどうかは適用後のエージェントの参照で判定する（plan のブロッカー）。

## 部分適用

DB とスキルは完全な原子性を持たない。DB は 1 トランザクション、スキルはサンドボックスの取り込みと削除で別であるため、DB の適用後にスキルだけが失敗した場合は `complete: false` の partial を返し、何を置換して何が残ったかを結果に出す。再実行は冪等で、残りだけが適用される。

スキルは「新規 / 同名置換を先に適用 → バックアップに無い既存スキルを削除」の順にする。先に全削除しないのは、適用が失敗したときに既存スキルを全滅させないためである。削除対象は `SKILL.md` を直接持つ発見済みフォルダだけで、それ以外の項目は残るものとして扱う。

plan のブロッカーは対象ごとに持つ。ブロックされた対象を選んだまま apply すると 409 で何も変更しない。スキルの `invalid` / 400 / 413 は skills 対象のブロッカーとして 200 の plan に載せ、agents / prompts は skills を外せば復元できる。DB トランザクションのコミット前に失敗した 503 にだけ `state: "not_stored"` を付け、コミット後にスキルだけ失敗した 200 には付けない。

## モデルと参照のフォールバック

モデルの可否はセッション作成と同じ実効の一覧で判定する。

- API キー未設定で一覧が空、またはモデル一覧自体が取得できないときは、判断せずモデルを保持して警告する（あとからキーを設定すれば元のモデルで動く）。アプリ既定モデルと API キーはバックアップ対象外なので、未設定なら設定画面を案内する警告も出す。
- カタログに無い、または復元先の許可リストで明示的に除外されているモデルは未設定（アプリ既定）に戻して警告する。`thinkingLevel` は残す。
- `promptIds` の参照先が適用後の DB に無いときは紐づけを外して警告する。スキル名とツール名が見つからないときは許可リストから消さず警告だけを出す。

## 全削除

「定義をすべて削除」はユーザー定義のエージェント（サンプルを含む）・自作の定型プロンプト・共通スキルを削除する。エージェントを先に消してから自作プロンプトを消すため、使用中制約に当たらない。組み込み・プロジェクト側スキル・会話・プロジェクト・ワークスペースのファイル・設定・API キー・共有コンテンツは触らない。削除したサンプルは再起動でも戻らない。

## 排他と受信

`export/check` / `export` / `restore`（plan と apply） / `reset` はプロセス内の 1 本の排他で直列化し、進行中は 409 の `busy` にする。export の DB 読み取りとスキルの取得も同じ排他の中で行い、別の操作由来の状態を混ぜない。

復元は raw の ZIP を受けるため、`bodyGuard`（64 KiB / text 化）より前に登録する。`content-length` の事前 413 と、読み取り中の上限監視を入れ、受信は `mkdtemp` の private dir へ spool して成功・失敗・abort のいずれでも消す。

## 既知の制限

- 全置換は破壊的である。確認ダイアログのプレビューと削除チェックで防ぐが、既存の会話が参照するスキルは次の読み込みから新しい内容 / 不在になる。
- スキルの削除だけが失敗した partial が残り得る。再実行で解消できることを結果に明記する。
- スキルの symlink / 特殊ファイルは ZIP に入らず、実行権限も復元されない。`SKILL.md` を持たない直下の項目は export と削除の対象外で残る。バックアップからの完全復元は名乗らない。
- バックアップ ZIP は暗号化されない。システムプロンプトに利用者が書いた秘密が入り得るため、平文のファイルとして扱う。
- `export/check` は dry-run import をしない軽い見積りで、復元可否を保証しない。復元前の restore plan で検証する。
