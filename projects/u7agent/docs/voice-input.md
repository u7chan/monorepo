# 音声入力の録音と文字起こし

録音 1 回分の接続・期限・終了と、入力欄（Composer）への挿入の扱いをまとめる。ブラウザ側の状態機械は
`client/src/lib/voiceInput/session.ts`、設定画面のプレイグラウンドは `client/src/lib/voiceInput/playground.ts`、
入力欄の所有領域は `client/src/lib/voiceInput/draft.ts`、録音の制御は `client/src/lib/voiceInput/composer.ts`、
Realtime セッションの中継は [api-settings.md](api-settings.md#音声入力の-realtime-中継) を正とする。

## 接続

設定 → 音声入力（`/settings/voice-input`）のプレイグラウンドと入力欄のマイクは、マイクを取って offer SDP を作り、
`POST /api/voice-input/session` へ送って answer SDP を受ける。音声と文字起こしのイベントはブラウザと OpenAI の間で
WebRTC を通り、BFF は SDP を中継するだけで音声も文字起こしも持たない。ブラウザが外部オリジンへ直接 POST しないため、
CSP の `connect-src` は `'self'` のままにする（[api-settings.md](api-settings.md#音声入力の-realtime-中継) の
「CSP を緩めない理由」）。

## 期限の強制

録音の上限は固定で、正は `client/src/lib/voiceInput/session.ts`。上限は手動停止にも適用し、上限に達したら音声の送信を
止めてマイクを解放し、確定を要求する。

`RTCRtpScriptTransform` を持つブラウザでは、`client/src/workers/voiceAudioDeadline.ts` が期限後の音声フレームを
送信側で落とす。worker は同一オリジンの別チャンクとして配信し、`blob:` を作らない（CSP の `script-src` を
緩めないため）。

- `RTCRtpScriptTransform` を持たないブラウザでも録音は成立させ、期限の強制だけを諦める。この場合の期限は画面側の
  タイマーによる `track.stop()` だけになる
- transform の API はあるのに worker / transform の起動に失敗した場合は、期限を守れない録音を黙って続けず中止する
  （失敗の分類は `audio-filter`）
- **既知の制限**: 期限の強制を持たないブラウザで画面が固まると、上限を過ぎた音声が送られうる。プレイグラウンドは
  この制限を表示する

## 入力欄への挿入

録音を始めた時点のカーソル位置（選択があればその範囲）を基準に、**システムが所有する未確定領域**を持つ。途中の
文字起こしはこの領域だけを差し替え、確定テキストは確定時に一度だけ入れる。

- 領域の外の手入力は消さない。領域より前の編集は領域の位置をずらすだけで、自動の差し替えを続ける
- **境界を含む編集**（領域の中への入力・削除、領域の直前 / 直後への挿入、スキルやファイル参照の挿入、IME の確定）で
  所有が切れたら、以降の自動の差し替えを止める。確定しても本文は変えず、確定テキストは捨てて入力欄の注記
  （`Composer` の notice 行）で伝える。残った途中文と確定文を並べると同じ発話が二重に入るため、どちらかを選ぶなら
  利用者が書いた側を残す
- 取消・失敗で戻すのは所有領域だけ。開始後に書いた文は巻き戻さない。開始時に選択していた文字があるときは、その
  範囲を置き換え、取消で元の文字を戻す
- 確定後はカーソルを確定テキストの直後へ戻し、焦点を入力欄へ返す。ただし利用者が別の場所（別の面の操作要素）へ
  移っていたら焦点は奪わない
- 確定したテキストは**入力欄に入れるだけで自動送信しない**（プレイグラウンドは本文へ入れず、読取専用で表示する）

## 入力欄の主ボタン

待機中は従来の `composerAction`（送信 / 停止）をそのまま使う。音声の操作中だけ主スロットを音声が占有し、実行中の
停止は副スロットへ残す（[ui-layout.md](ui-layout.md#入力欄の主ボタン送信と停止)）。

| 状態 | 主スロット | 副スロット | マイク |
| --- | --- | --- | --- |
| 音声が待機 | 従来の `composerAction` | 従来のまま | 使えるときだけ出す |
| マイク許可待ち・接続中 | 取消（接続を捨てる） | 実行中なら既存の停止 ■ | 隠す |
| 録音中 | 録音停止 ●（残り時間の弧） | 実行中なら既存の停止 ■ | 隠す |
| 確定待ち | 送信不可（スピナー） | 実行中なら既存の停止 ■ | 隠す |

- run が終わっても録音は続き、録音を止めても run と待機キューは変えない。run の停止で録音も止めない
- アイコンと `aria-label` で ■（実行の停止）と ●（録音の停止）を区別する
- 送信は入口で止める（Enter / フォーム submit / 再実行 / 未送信の再送）。ボタンの `disabled` だけに頼らないのは、
  停止の直後の二度押しが入れ替わった位置の送信へ届く経路を塞ぐため

## 開始前の確認と可用性

- 入力欄から録音を始める前に、音声が OpenAI へ送られ利用料がかかること・u7agent が保存しないことを伝え、初回の
  開始時だけ確認ダイアログを出す（既読は localStorage の 1 キー）。データの取扱いへのリンクを添える。設定画面で
  説明済みでも初回は省略しない。ボタンは増やさず、マイクの押下の中で確認する
- マイクを出すのは、キーが保存され復号でき、マスカーを持つ起動で、かつ secure context（HTTPS か localhost）の
  ときだけ。使えない理由は設定画面の注記にだけ出し、入力欄の近くには並べない。可用性は App の起動時に
  `GET /api/settings/voice-input` で取り、設定画面でキーを保存 / 削除したら取り直す
- 取得に失敗しても会話は止めず、マイクを出さないだけにする

## 終了の条件

手動停止・上限による自動停止・取消・設定や実行状況へ移る・会話 / スペースの切替（添付が暗黙に作った会話への移動を
含む）・アンマウント・`pagehide` のどれでも、マイク・peer・worker・タイマーを閉じる。停止後はマイクを止めてから
commit を送る（音声と制御は別経路なので、同時に送ると末尾の音声を追い越す）。録音には世代を持ち、キャンセル後に
届いたコールバックは状態も本文も変えない（確定テキストが次の会話の下書きへ混ざらない）。

## 保存しないこと

音声も途中・確定の文字起こしも保存しない（履歴を持たない）。確定テキストは入力欄へ入るだけで、送信した本文だけが
通常の会話履歴に残る。金額の概算と言語の指定もしない。課金は、残高不足（上流の 402 に対応する分類）だけを文言に
使い、金額は表示しない。

## 非ゴール

録音の保存・履歴、金額の概算、録音上限の設定、キーボードショートカット、複数マイクの選択。
