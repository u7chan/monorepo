# レイアウトモード

シェルは viewport から決まる 3 モードを持つ。判定の正は `client/src/lib/layout.ts` で、`useLayoutMode` が resize / orientationchange に追従する（CSS のメディアクエリでは分岐しない）。**閾値そのものはコードが持つ。ここには値ではなく、値の理由と、値が変わっても変わらない契約を書く。**

## スペース

desktop / singleColumn とも設定ナビの「会話スペース」から作成・選択し、選択はブラウザー（オリジン）単位で保持する（他タブの切替はリロードで追随する）。追加スペースは会話専用（Projects / New Project / プロジェクト操作を出さない）。**認証や安全な隔離ではなく、共通設定・ファイル・公開サービスは共有する**ことを設定画面に明記する。**作成フォームは一覧の上に置き、一覧に高さの上限を設けない**（エージェント / スキルの一覧が追加行を先頭に置くのと同じ順で、一覧が伸びても作成操作は画面内に残す。スクロールはページ 1 本にする）。**一覧はグリップのドラッグで並べ替えられ、順序はサーバーへ保存する**（ドラッグの規則はエージェント一覧と共通: グリップを掴んだときだけ動き、しきい値未満は選択のタップ、`Escape` / capture 喪失 / レイアウト切替で取り消し、端では実際にスクロールしている祖先を自動スクロール。**既定スペースの行にはグリップを出さず**、グリップは削除の ⋯ と反対側に置く。順序は全ブラウザーで共有、選択はブラウザー単位のまま）。保存の応答は現在の一覧へ**マージ**し（応答に入っていない行＝既定スペースや、保存待ちの間に作られた行は元の位置に残す）、HTTP エラーでは表示を元の順へ戻して理由を出し、応答が返らない失敗では表示を戻さずに次のドラッグを開く。**結果不明の下書きはページを離れた時点で捨てて最後に確定した順へ戻し、離脱前に始めた保存の応答も反映しない**（一覧はページより長生きするため、古い応答で新しいページの確定した並びを巻き戻さない）。F5 などの再取得で GET の順に合う。正規化（未知の id・重複・既定スペースは捨てる）は [api.md](api.md#スペース)。**削除は追加スペースの行の ⋯ にだけ出し、既定スペースの行には出さない**（改名・リセット・アーカイブの導線も無い）。削除は不可逆なので共通の確認ダイアログでスペース名と消える対象（会話・履歴・作業フォルダのファイル・添付・環境変数とサービス実績）を並べ、実行中の会話が止まることと選択中なら既定スペースへ切り替わることを示す。項目の出し分けと文言の正は `client/src/lib/spaceSettings.ts`。切替時は入力・添付・作成先・各先行選択・ファイル面・dialog を持ち越さず、取得失敗や未知の保存 ID は復旧画面で選び直して既定スペースの会話を自動表示しない（[frontend.md](frontend.md#スペースの選択)）。

未所属セッションは行の ⋯ から**会話を引き継ぐ**（エージェント / スペースの交代）。履歴と未送信は破棄され、作業フォルダと添付は同一スペースならその場、別スペースなら移動先へ移る。プロジェクト所属も項目を出し、**同じスペースへの交代だけ**を許す（作業ディレクトリが同じで移す先がない）。引き継ぎ先のエージェントは現在のものを既定にし、**現在のエージェントがカタログから消えていても選べる**（送信時に id を省き、保存済みのスナップショットを維持する）。メモ（作業フォルダ直下の `HANDOFF.md`）は既定 ON で、書いたかどうかを会話の状態に残す。**実行すると移動先のスペースへ切り替えて、引き継ぎ後の会話を開く**（切替は `openOwnerSession` と同じ経路。同一スペースは切り替えずに、同じ id のまま旧履歴を捨てて開き直す）。実行中・キュー待ち・圧縮中・片付け中は項目を無効にし、押せない理由を説明行へ出す（項目ごと隠さない）。確認は消えるもの（履歴と未送信）と残るもの（作業フォルダのファイルと添付）を並べ、プロジェクト所属ではメモが**リポジトリ直下**にでき、コミット / 除外は利用者判断であることを示す。片付けが残った応答では、移動先へ切り替えたあとの状態行に警告を出す。文言と選択の正は `client/src/lib/sessionHandoff.ts`、表示は `client/src/components/SessionHandoffDialog.tsx`。失敗時の復旧と meta の記録は [run-lifecycle.md](run-lifecycle.md#引き継ぎと復旧)。**引き継ぎで `HANDOFF.md` を作ると、その会話を開いたときに入力欄の上へチップ「HANDOFF.mdを参照」が出る**（見た目と送信時の合成はエージェントの定型プロンプトと同じで、違うのは供給元だけ）。**表示は会話の状態（payload の `handoff`）から導出**し、クライアントのメモリには置かない（別スペースへの切替とリロードをまたいで同じになる）。外すとその送信には入らず、引き継ぎ後の**最初に受理した送信**でサーバーが消費済みを立て、以後は出ない（未送信の破棄では戻らない）。**保証するのは指示文が送信本文へ一度だけ入る / 外すと入らないまで**で、実際に読むかはモデルとツール次第（`read` を持たないエージェントは読み切れず、チップを外しても自発的に読むことはある）。

## モードと境界

| モード | 条件 | シェル |
| --- | --- | --- |
| desktop | 幅と高さの両方が足りる | 左バー + main（幅が狭い帯では左バーを overlay へ退避） |
| landscape | 高さが足りない | `SingleColumnBar` + Chat + singleColumn Composer |
| portrait | 幅が足りない | `SingleColumnBar` + Chat + singleColumn Composer |

- **desktop が高さも要求するのは、横向きスマホが幅だけで 2 カラムを選ぶと Chat が数十 px まで潰れるため。** landscape は横向きスマホだけでなく、低いデスクトップウィンドウも同じ扱いにする
- desktop でも幅が狭い帯では左バーを overlay へ退避して main へ幅を回す。閾値は右パネルの幅が縮み始める幅と同じ数字で、「狭くなるとパネルもチャットも苦しい帯」の入口を 1 つの数字で表す。左バーの幅は選べるが、狭い窓では main が足りないので閾値は据え置き
- desktop の中にも **900px** の境目がある。エージェント / スキルの設定で一覧と編集面を並べるか、一覧ページ + 全画面シートにするかの境界で、理由は [設定の一覧と編集の境界](#設定の一覧と編集の境界) を参照する（この値も CSS の `wide:` バリアントと JS の `resolveWide` が同じ数字を持つ）

## モードごとの構成

- メイン領域は チャット / 設定ページ のどちらかで、URL が決める（[frontend.md](frontend.md#url-と画面の対応)）。設定ページは `<dialog>` を被せずメイン領域に出す
- **設定ページを開いている間もチャットは mount したまま、`display` は切らない。** SSE 購読（実行中のラン）と入力中の下書きを失わないため。切替は opacity のクロスフェードで、隠れた側は `visibility` でフォーカスと読み上げから外す（消える間は見せたいので `visibility` だけ遅らせる）。スクロール位置はアプリとして復元しない
- 設定ページのセクションと**並びは `client/src/lib/settingsNav.ts` の `SETTINGS_SECTIONS` が正**で、docs に一覧も件数も写さない。理由が必要な項目は定義側のコメントに置く（例: ダウンロードの除外をファイルのタブにする理由）。相互参照は URL（`/settings/<section>`）で書く
- **面の操作は帯の右端に置く（左に文脈、右に操作）。帯は 1 面に 1 行で、タブがあるページはタブ行の直下、タブが無いページはヘッダの直下に置き、操作を持たない面には出さない（チャットの作業環境パネルの帯も同じ `client/src/components/TabToolbar.tsx`）。ヘッダはページの説明とページ全体の導線だけにする**（面の操作をヘッダに戻さない）。**取り直し（[再読み込み] / [カタログ更新]）は帯の右端に 1 つだけ置く。** 取り直すまとまりの見出し行に置き、本文のエラー枠には置かず「上の『再読み込み』で取り直します」の 1 行で案内する。未保存の下書きを捨てる面（設定 → 通知 / 設定 → ファイル の「ダウンロードの除外」）は変更がある間だけ無効にし、理由を読み切れる幅で出す（帯が操作で埋まる狭い幅ではヘッダ側へ逃がす）。**取得中はどの面でも無効にする**（進行中は取得を持つ hook が追い、破棄された要求の完了でも解除する）。保存がある行では、取り直しは保存群の左に置いて区切り線で分ける（保存は常に右端）。狭い一覧の見出しだけは例外で、ブロック所有の小さい寸法を保つ
- singleColumn では `SingleColumnBar` が「作業先と、どのエージェントのどの会話か」・通知・作業フォルダ・nav の導線を常時出す。設定ページのヘッダは左端に [アプリに戻る]、その右に `☰` とタイトルを置き、**説明はタイトル行の次の全幅の行へ出す**（ボタンと横に並べると説明の幅がボタンに削られ、同じ長さの文でも画面ごとに折り返しが変わる。`☰` が無いと設定の間を移動できない）。**説明はその画面で決めることを 1 文で書き、詳細は本文の注記へ譲る**
- singleColumn のエージェント / スキルの編集は全画面シートへ出す（[設定の一覧と編集の境界](#設定の一覧と編集の境界)）。サイドバーは `NavSheet`（モーダル dialog のドロワー）へ退避する
- **singleColumn の単一列 Grid は viewport 幅に拘束する**（`minmax(0, 1fr)` と `min-w-0`）。拘束しないと select の選択肢の幅や textarea の `cols` 既定値が item の最小サイズとして効き、送信 / 添付ボタンが viewport の外へ出る
- singleColumn の入力欄と選択欄は iOS Safari の focus 時ズームを避けるため 16px 以上にする（`@theme` の 16px トークンを使う。`text-base` は色トークンが取っているため使えない）
- **singleColumn の操作面は判読性と誤タップ防止を優先し、寸法は各コンポーネントが持つ。** desktop の寸法は変えず、判定は `html` の `data-layout` を写した 1 つの値だけを見る（`(pointer: coarse)` では分岐しない）。popover は計測の前に viewport 由来の幅 / 高さの上限を当て、入り切らない一覧は内部スクロールへ逃がす
- 画面切替は履歴を追加しない（`replaceState`）。Back / Forward はブラウザーの既存履歴に従う

## ポップアップの出入り

native `popover="auto"` のパネルは、見た目の出入りだけを `@layer components` の共通クラスで共有する。開閉の入口（トリガー / light dismiss / `Escape` / `Tab` での退出）とフォーカス、位置と大きさは各コンポーネントが持つ。

- **scale を使わない。** 開いた直後に `getBoundingClientRect()` から位置を決めるため、scale は rect の高さに乗って位置がずれる。translate は高さを変えないので計測に影響しない
- **`display` に値を持つユーティリティを当てない。** UA の「閉じている間は `display: none`」が消え、パネルが常時見える
- 開く側の初期フレームは `@starting-style` が持つ（要素が描画されていない間は遷移の前の値が無い）
- `prefers-reduced-motion` では遷移だけを切る（機能は落とさない）

## 確認と入力のダイアログ

ネイティブの `window.confirm` / `prompt` / `alert` は使わず、共通ダイアログを通す。**この契約は `.oxlintrc.json` の `no-restricted-globals` / `no-restricted-properties` で lint 時に固定する**（構文で見るので、文字列やコメント中の紛らわしい記述を誤検出しない）。

- `ConfirmProvider` がアプリの root にダイアログを 1 つだけ置き、`useConfirm()` / `usePrompt()` が Promise を返す（UI を持たないフックからも同じ部品を使える）
- 開閉と焦点は native `<dialog>.showModal()` の標準挙動に任せ、閉じたら開いたボタンへ焦点を戻す
- 初期焦点は取り消し側に置く（破壊的な操作を Enter で確定させない）。prompt は入力欄に置き、現在値を選択状態にする
- 対象の名前は本文へ埋めず、clamp した独立の行に出す（会話タイトルは初回メッセージ由来で最大 60 文字になる）
- 実行する側のボタンは何をするかを書く（`OK` / `はい` を使わない）
- **モーダルは常に 1 つだけ出し、開いている間の要求は待ち行列へ積む。** 応答は先頭の要求にだけ対応付け、古い応答は無視する。先の Promise を未解決のまま捨てると、呼び出し側の `finally` が走らず二重送信のガードが残る
- 確認を開いている間に会話が切り替わったら、確定しても後続を実行しない（未確認の別会話へ圧縮や起動を送らない）
- 取り消せない操作は danger のトーンにし、取り消したら後続の処理を呼ばない
- **選択とトグルを持つダイアログ（引き継ぎのエージェント / スペース / メモ）は共有契約へ `select` を足さず、`ProjectDialog` と同じ専用部品にする。** モーダルは 1 つだけ・要求は待ち行列という共有の契約は confirm / prompt の 2 種を前提にしたもので、選択肢の一覧はダイアログごとに違う
- **引き継ぎの既定は現在のエージェント・現在のスペース・メモ ON** とし、少ない操作で実行できるようにする。プロジェクト所属では移動先スペースの選択を出さない（作業ディレクトリが同じで移す先がない）。メッセージ 0 件ではメモのトグルを無効にして理由（メモにできる会話がまだない）を示し、トグル OFF なら実行できる

## 作業環境パネル

チャットの右パネル / singleColumn の全画面シートの上位名は**作業環境**で、**同じスロットが 作業フォルダ / 環境変数 / スキルの 3 つのモードを持つ**（別の容器を追加しない）。

- 作業フォルダ面は 設定 → ファイル（/settings/files） と同じ `FileBrowser` を使う（root と `readOnly` だけが違う）。環境変数の設計は [secrets.md](secrets.md#作業フォルダの環境変数) を正とする。一覧の上部には種別ごとの短い凡例を常時出し、種別の説明を追加 / 変更フォームの中だけに置かない（登録前後どちらでも、変数はエージェントの `bash` にも渡り、シークレットはサービスとして起動したプロセスの `process.env` にだけ入ると読み取れるようにする）。凡例は長文に戻さない（一覧の上を説明で埋めない）。**一覧はグリップのドラッグで並べ替えられ、順序は cwd ごとにサーバーへ保存する**（ドラッグの規則はエージェント / スペースの一覧と共通。行には値と ⋯ があるため、グリップだけを起点にし、行そのものはドラッグしない。順序は全ブラウザーで共有し、値・展開状態・世代は変えない。HTTP エラーでは表示を元の順へ戻して理由を出し、応答が返らない失敗では表示を戻さず次の取得でサーバーの順へ合わせる）。一覧は 1 つの面（外周の 1 本の枠 + 行の区切り線）にし、変数の値を行の中の別の枠へ入れ子にしない（カードインカードを作らない）。「値を表示」は値が伏せられるシークレットの入力だけに出す（変数は素の入力欄）
- **cwd が決まらない会話では導線自体を出さない**（ワークスペース root へは落とさない）。設定ページではパネルを出さない（設定 → ファイル と二重になるため）
- 面のモードを既定（作業フォルダ）へ戻すのは、閉じる導線 / **選択中セッションの変化**（同一プロジェクトで cwd が同じでも戻す）/ チャット以外への移動 / singleColumn ⇄ desktop の切替。`cwd` だけでは同一プロジェクトの切替と新規チャットを拾えないため、セッションの識別子も見る
- **変数の値は一覧表示のため行ごとに保持する（state にだけ置き、どこにも保存しない）。** ドラフトは従来どおり `localStorage` / `sessionStorage` / URL へ保存せず、パネル / シートを閉じる・`Escape`・セッション切替で破棄する（確認は出さない）。`autocomplete` は切る
- パネルの幅の上下限はコードが持つ。**上限を `FileBrowser` の container 境界より下で止めるのは、そこで左右 2 段が発火するとツリーとプレビューが並んで読める幅が減るため**
- 選んだ幅は端末ごとの表示設定として保存し、狭い窓では捨てずに表示時に clamp する（広げ直したときに選んだ幅へ戻せるようにする）
- ドラッグ中は React を再描画せず CSS 変数だけを書き換える（パネルはツリーとハイライトを含み、move ごとの再描画が重い）。確定は pointerup / pointercancel / lostpointercapture / アンマウントのどの経路でも同じ処理を通し、state と保存値をそこで 1 度だけ更新する
- 境界のハンドルは共通クラスで内容より上へ描く（後から置かれた positioned 要素に描画順で負けると当たり判定ごと奪われる）。**代償としてその帯では内容側のホイールスクロールをハンドルが受ける**

## 作業先と作業フォルダの導線

左バーが overlay になる帯では、プロジェクト配下の新規会話と未所属の新規会話を main 領域だけで区別できない。**そこで作業先をバーに常時出し、空状態の見出しと作業フォルダの導線を同じ判定で分ける。** 判定の正は `client/src/lib/chatScope.ts`。

- 作業フォルダの root は選択中セッションの `payload.cwd`、セッション未作成では作成先プロジェクトの `cwd`。**セッションがあるときに作成先の `cwd` を渡さない**（選択待ちの空 root に、別プロジェクトのツリーを出さないため）
- 環境変数タブの要求元も同じ判定を使い、**cwd への解決はサーバーだけが行う**（client は cwd を送らない）
- 起動時の正はメッセージ 0 件かどうかで、添付だけしたセッションも同じ規則で扱う

### 作成先

作成先がプロジェクトになるのは、プロジェクトを指定する入口を通ったときだけ。それ以外は未所属へ戻る。**最後に開いたプロジェクトは保存しない**（会話を指定しない `/` の起動・リロードでは未所属の新規会話から始まる）。

| 入口 | 作成先 |
| --- | --- |
| `/`（会話を指定しない起動・リロード）、「新しい会話」、内部フォールバック（開けない / 削除 / SSE 閉鎖 / リンク解決失敗） | 未所属（直前の作成先を引き継がない） |
| プロジェクト行の ⋯「このプロジェクトに新しい会話」 | そのプロジェクト |
| プロジェクトの追加（新規作成 / 既存登録の成功後） | 追加したプロジェクト |

- 見た目で選ばせる作成先は持たない。プロジェクト行のクリックは配下セッションの折りたたみのトグルで、`Chats` 見出しはラベルだけ
- 非ゴール: `/` を開いたときに前回の会話を自動で開くこと。会話 URL を開いたときもスクロール位置は復元せず、最新位置から始まる（[チャットの自動追従と最下部ボタン](#チャットの自動追従と最下部ボタン)）
- **未作成チャットのエージェント選択は作成先を動かさない**（いまの作成先をそのまま使う）。セッションを開いている間はエージェントを選び直せない（作成時に固定され、選び直しても新しい会話になるだけのため）

### 既定オープンと手動操作

desktop のパネルと singleColumn のシートは state を分ける。**1 つにすると、desktop で開いたまま狭めたときに全画面シートが自動で開き、Effect で閉じても 1 フレーム遅れて `showModal()` と focus 移動が走る。**

- パネルの既定（作成先がプロジェクトなら開）へ戻すのは利用者操作の新規会話の入口だけで、起動時の初期値は（会話 URL を開いても）閉
- シートは既定オープンの対象外（手動トグルだけ）。singleColumn へ入っただけでは開かない
- **閉じる判定は Effect ではなく描画中の同期で行う**（子の `showModal()` より先に state を確定させる必要がある）。監視するキーは layout / メイン領域 / root の 3 つで、route オブジェクト全体は比較しない
- レイアウト切替は互いの state に影響しない。閉じる導線は押した面だけを閉じる
- ドロワーへ退避したときは開いていた `NavSheet` を閉じ、docked へ戻ったフレームで両方を重ねない

### 非同期ロード中の表示契約

一覧の取得前や欠落した id では、チップ / 見出し / root が一時的に食い違い得る。**状態（開閉）は変えず**、次を取る。

| 状態 | チップ / 見出し | root |
| --- | --- | --- |
| `projects` / `sessions` 未取得、一覧に無い id | 未所属 | `payload.cwd`（GET の応答が先に来るため）。作成先がまだ引けないときは空 |
| 所属プロジェクトが消えた / 解除された | 未所属 | `payload.cwd` のまま（フォルダは残る） |
| セッションの選択待ち（GET 中） | 応答まで元の表示 | 応答まで元の root |

## チャットの自動追従と最下部ボタン

メッセージ領域は「最下部付近にいるときだけ」最新へ追従する。読み返している間は応答が届いても位置を動かさず、下端中央のボタンを「最新へ戻る」導線にする。判定は `client/src/lib/chatScroll.ts` の純関数が正。

- **追従を外せるのは「ユーザーが上へ戻した」ときだけ。** 位置が増える `scroll` は自分が書いた位置かレイアウト起因で、ユーザー操作ではない。右パネルを開くとチャット幅が変わって本文が折り返し直り、ブラウザーのスクロールアンカリングが `scrollTop` を増やして `scroll` を配る（同一フレームの ResizeObserver callback より先に届く）。距離だけで判定すると追従が必ず外れるので、向きで判定し、追従中に離れていたらその場で書き戻す
- **送信はバブルの形（件数と末尾の role）から推測せず、`sendSeq` の増加で拾う。** 履歴を全置換する `resync` で件数が増えても送信と誤読しない。`sendSeq` は引き継いで単調に保つ（post が失敗してエコーを戻しても減らさない）
- 会話の切替は空からの遷移も含めて最下部へ揃える（新規チャットの作成は送信だけでなく添付でも起きる）
- ボタン押下と追従の書き込みは instant。`smooth` はアニメーション中の `scroll` で追従と競合し、`prefers-reduced-motion` の分岐も増える
- **追従中だけ scroll anchoring を止める。** 表の折り返しで高さが縮むと、仮想キャンバスの再計測前にブラウザーが位置を補正し、読み返し操作と誤判定する。読み返し中は既定へ戻し、レイアウト変更時の読み位置を保つ役目はブラウザーに残す
- 本文更新と仮想キャンバスの総高は layout effect で**描画前に**追従する（passive effect で本文だけを追うと、巨大な表で実 DOM と仮想キャンバスの高さが追いつくまで末尾から離れたフレームが見える）。同時に `resolveScrollFollow` で現在位置を判定し、まだ `scroll` が届いていない読み返し操作を上書きしない
- DOM への書き込みは `snapToBottom()` に閉じ、設定ページ中のような非表示中は書かない。observer は表示中だけ張る
- 非ゴール: スムーススクロール / 新着のドット・件数バッジ / 位置の永続化（会話を跨いだ復元）/ 設定ページ往復後の読み位置の復元 / resync をまたいで同じメッセージを見続けること（表示の同一性は保証しない）/ 「一番上へ」ボタン

## 入力欄の主ボタン（送信と停止）

入力欄の右端の主スロットは、実行中に送信（↑）と停止（■）で入れ替わる。判定は `client/src/lib/composerAction.ts` が正。

- **送れるもの（本文 / 添付 / 定型チップ）が無いときだけ ■ が主スロットへ入る。** 送るものがあれば ↑ を主に残し、停止は枠だけの控えの ■ として ↑ の左へ並べる。停止は待機キューも破棄するため、下書きを書いている間も押せる位置へ残す（ChatGPT は送信が現れると停止を消すが、そこで積まれるのは中断ではなく待機で、捨てる判断は書きながら起きる）
- **送信の直後は短いあいだ入れ替えを保留する**（長さの正は `Composer` の `STOP_PROMOTION_HOLD_MS`）。本文が消えた描画で主スロットが ↑ から ■ へ変わると、1 回目のクリックの続き（二度押し / ダブルタップ）がそのまま停止へ届き、走っている実行と待機キューが落ちる（変更前は主スロットが常に ↑ で、送信直後は無効だったため起きなかった）。保留中も控えの ■ は押せるので、続けて止めたいときの逃げ道は残る
- **実行中以外の理由で送信が止まっている間は ■ を主スロットへ上げない。** 対象は回答待ち（`上の質問に回答してください`）/ モデル未設定 / 添付のアップロード中。主スロットの下に出る理由や進行中の操作が次の一手を示しているので、破壊操作を主役にしない。■ は控えに残し、↑ は無効のまま置く
- 待機件数はボタンのラベルに載せない。件数の正はコンポーザーの内容欄の先頭に置く固定ブロック（入力欄の外・状態行の上。`送信待ち N 件` + 1 行ずつ本文と `取り消し`。SDK が取り出した入力は `取り消し` の代わりに `反映中`）で、状態行は活動の語だけを出す。行が入り切らないときは一覧だけをスクロールさせ、入力欄と状態行を常に見える位置に残す（`取り消し` は各行に残る）。**低い窓では、入力欄の上へ浮くライブ表示の箱（実行中のツール）の最大高と状態行・入力欄の分を引いた高さまで一覧を詰める**ので、待機を積んだままツールが走っていても箱が viewport の外へ出ない（行は畳まず内部スクロールで全件に届く）。**一覧には 1 行分の下限を置き**、それを下回る高さでは行の到達性（`取り消し` の導線）を優先して箱が上へはみ出す側を受け入れる。■ は `title` に「実行を中断し、待機中の送信も破棄します」を出し、実行中の ↑ は「待機キューに積んでから送信します」で中断と区別する
- 形は塗りの四角（`StopIcon`、サービスの停止と同じで、入力欄では円に合わせて大きく描く）。**主スロットの ■ と控えの ■ は円の大きさも ↑ と同じ**にし、主 / 控えの差は塗りと枠だけにする（送信と同じ位置の入替えで、指が別の操作を拾わないため）
- 停止の入口はこの 1 か所だけにし、footnote のテキストリンクは置かない

## 入力欄の Enter（送信と改行）

`Composer` の textarea の Enter はモードで分ける。判定は `client/src/lib/composerKeys.ts` が正。

- **singleColumn は Enter を改行に残す。** タッチ入力では `Shift+Enter` を前提にできず、改行の逃げ道が無いため。送信は送信ボタンに寄せる
- desktop は Enter で送信、`Shift+Enter` で改行
- **IME の変換確定 Enter で送信しない。** `isComposing` に加えて `keyCode === 229` も見る（`compositionend` が keydown より先に届くと `isComposing` が false のまま確定の Enter が来る実装がある）
- `enterkeyhint` はモードに合わせる（キーのラベルのヒントなので動作は変えない）

## 送信後の入力欄のフォーカス

**送信の時点の一次ポインタで、フォーカスを戻すか外すかを決める**（`client/src/lib/composerFocus.ts`）。再実行カードの送信は入力欄のフォーカスに触れず、定型プロンプトの選択は本文へフォーカスを移す。

- coarse は外す。戻すとソフトキーボードが閉じない（iOS Safari は同じ要素への `focus()` が no-op になり、Android Chrome はタップで外れたフォーカスを戻してキーボードを開き直す）。`blur()` は送信の click / submit と同じ同期処理の中で呼ぶ（ユーザー操作の外へ遅らせると閉じない端末がある）
- fine は戻す。送信ボタンのクリックでフォーカスがボタンへ移るため、戻さないと次の入力を書き始められない。**singleColumn でも同じ**（幅 / 高さが足りない desktop の窓で連投する経路を残す）
- **`any-pointer: coarse` は見ない。** マウス併用のタッチ PC までタッチ扱いになり、マウス操作の連投でフォーカスが落ちる。これは直前の入力方式ではなく UA が選ぶ一次ポインタの能力なので、**一次が coarse のままマウスを使う端末ではその送信でもフォーカスが落ちる**（保証できるのは「一次が fine のマウス併用タッチ PC」で、ハイブリッド機器全般で退行しないとは言えない）

## 入力欄の拡大

入力欄は右上のボタンで画面いっぱいの面へ広げられる（singleColumn でも同じボタンを出す）。**広げるのは同じ入力欄で、別の面へ mount し直さない**（下書き・カーソルの位置・IME の変換中・添付が消えるため）。

- 外装は native `<dialog>`。畳んでいる間は UA の `display: none` を上書きして通常のブロックとして置き（`role="presentation"` にして dialog の区切りとして読み上げさせない）、広げると `showModal()` がそれを top layer へ移す（初期焦点は本文。dialog の既定の先頭要素を一度掴むと、本文の IME の変換中が blur で切れる）。背景の操作停止と `Escape`、焦点の復帰は標準の挙動で付く
- 閉じる入口は右上のボタン / 背景クリック / `Escape`。`Escape` は自分の dialog の `cancel` だけを受け（添付画像の拡大など portal の dialog の分は通す）、退場アニメの間も消費して閉じ切らせない（先に閉じると、全画面の寸法のまま通常フローへ戻る 1 フレームが出る）。実際の `close()` は退場アニメの終了と**同じ描画**で行う。ここで消費するので、設定ページからチャットへ戻る `Escape` には届かない（設定ページへ移るときは消費しない）
- 面（枠・背景）は広げている間だけ外側の容器へ移し、入力欄は残りの高さまで伸ばす。畳むと `scrollHeight` の計測へ戻る
- **送信 / 設定ページへの移動 / レイアウトの切替で畳む**（開いたままだと、隠れた `inert` な面の中で modal だけが残る）。送信で畳むときの焦点は[送信後の入力欄のフォーカス](#送信後の入力欄のフォーカス)と同じ規則で `close()` の後に決め直す（標準の復帰は拡大のボタンへ戻すため）
- ドロップと貼り付けの受け口は面ごとにする（入力欄の外の余白でブラウザーがファイルを開くのを避ける）
- 出入りは減光と箱の拡縮。`prefers-reduced-motion` では時間だけを 0 にする（閉じ切る契機は残す）

## 設定の編集フォーム（エージェント / スキル）

- **可変長の項目（定型プロンプト / スキル）を持つエディタは、`<form>` を「スクロールする本文 + 常時表示のアクション行」の 2 段にする。** 確定操作の位置が件数に比例して下がるのを避けるため。削除は編集中だけ操作行へ出す（singleColumn のヘッダは 戻る + ナビ + タイトル の 3 要素で、破壊操作が保存の隣に並ぶ）
- 本文の 2 カラム化は container 幅で判定する。エディタ列の幅が「左バーの実幅 + 一覧」を引いた残りで決まるため、viewport では判定できない
- アイコンの canvas 縮小とエンコードは DOM 依存なので lib に閉じ、純関数（縮小サイズ / data URL の検証）と分ける
- **編集面は上段 = プロフィール / 下段 = 可変のカード grid。** 上段は左に 名前・説明・アイコン、右上に Model / Effort、下に 役割 / 基本指示（全幅）。下段は **ツール | スキル** の 2 列で、定型プロンプトは全幅。上段の 2 列判定はエディタ列の container 幅で行い（列幅の理由は上と同じ）、狭いときは 1 列に積む。Model / Effort の欄は選択肢の文字が切れない幅（目安 400px 以上）を確保する
- **行は常に全部出し、アプリ側で使えない行には理由、外した行には依存の注記を出す。** 行を消すと「外した」のか「そもそも無い」のかが読めなくなる（スキル欄で取得失敗時に欄ごと消さないのと同理由）。例外は一覧そのものを取得できていないときで、そのときは行ではなく理由を出す。注記はカードに 1 本だけ置き、同じことを行やスキル欄へ重ねて書かない
- ビルトインの汎用アシスタントと読み取り専用スキルはフォームを出さず、専用の閲覧ビューを出す（編集も削除もできないため）。ビルトインは許可リストを持たないので、閲覧ビューは共通 / 組み込みとツールを**チェックなし**で並べ、変更できないことと規則（許可リストを持たず、アプリ側で無効なものは使えない）を注記する（何も刺さないエージェントが欲しいときはユーザー定義で作る）
- 共通スキルは 閲覧 → `編集` でフォームへ入る。`キャンセル` は**未保存の差分があるときだけ**確認してから破棄する
- **エージェント編集のスキル欄は、共通 / 組み込みスキル（`.agents/skills` とアプリ同梱。全エージェントへ既定で効く）をチェックボックスで外す。**共通スキルは実体がファイル側にあり増減も編集の外で起きるので、いま選ばれていないものが「外した」のか「無い」のかを注記で分け、取得できないときは欄ごと出さず理由を出し（空の一覧と見分けが付かないため）、取り直しはスキル欄の見出し行の右端に置く（読み込み中は出さない）。組み込みは「すべて外す / すべて使用に戻す」を持つ。スキルを外した帰結（`read` を外すと本文が読めない、`serve` を外すと組み込み `serve` の手順が実行できない）はツール欄が持ち、スキル欄には書かない
- **ツール欄も同じ見た目の行を使い、ツール ID を等幅で出す。** グループは「作業ツール」（サンドボックスで実行する分）と「アプリのツール」（BFF ローカルの分）の 2 つで、見出しに `使用 n / 全 m` を出す。一括操作は「すべて使用に戻す」（明示リストのとき）/「すべて外す」（OFF があるとき）で、スキル欄と同じ規則にする

## 設定の一覧と編集の境界

設定 → エージェント（/settings/agents）/ スキル（/settings/skills） は、**900px 以上のときだけ一覧と編集面を並べる**。900px 未満と singleColumn は「一覧（ページ）+ 編集（全画面シート）」に統一する。**1 列に積むと、選択のためだけの一覧が常に編集領域を削る。**

- **編集の下書きはページが持つ。** 幅の帯をまたぐとフォームの container が変わり（ページ ⇄ dialog）、フォーム自身が state を持つと unmount で未保存の入力が消える。初期化の条件はフォームごとに違い、**エージェントは編集対象の定義の内容**（並び順だけの更新や同内容の取り直しでは初期化しない）、**スキルは選択対象と編集状態**の変更で初期化する。**ファイルスキル（共通）も同じ境界に従う** — 一覧の選択キーは root 相対 `relativePath` で、閲覧の内容（name / description / 未 trim の本文 / 版）を 1 回の取得でまとめて取り、その同じ値から下書きを作る（閲覧と保存が別の取得を見ない）。下書きは編集面の hook が持ち、競合 (409) では残したまま `再読み込み` を促し、削除の確認はその時点の一覧を取り直してから出す
- **エージェントの並べ替えはグリップを掴んだドラッグだけに開く。行そのものはドラッグしない。** 行のクリックは編集対象の選択なので、掴む場所を重ねると選択と衝突し、タッチでは一覧の縦スクロールを奪う。ビルトインは先頭固定なのでグリップを出さない（[api-catalog.md](api-catalog.md#エージェントの表示順)）
  - 移動量のしきい値を越えてから掴んだと見なし、行の中央線を越えたら配列を差し替える。終了経路（pointerup / pointercancel / capture 喪失 / `Escape` / unmount / レイアウト切替）は 1 箇所にまとめて cancel と確定を分け、どの経路でも見た目と下書きを残さない。`Escape` は `preventDefault()` で消費する（設定ページからチャットへ戻る `App` の `Escape` へ届かせない）。**掴んだときに捕捉した行が DOM から消えたら（削除などで集合が変わったら）その回で取り消す**（捕捉した添字と DOM の行がずれ、掴んだ行を見つけられない・挿入先が 1 つずれるため）。
  - 端に寄ったら rAF で自動スクロールする。対象は固定せず、**実際にスクロールしている祖先**を辿り、一覧が短く内部スクロールが起きていないときはページ側を使う（900px の境界でスクロール枠が変わるため）。
  - 確定は保存が返ってから下書きを消し、応答がないときは表示を戻さず結果不明として伝え、**次の取得が届いた時点で下書きを捨ててサーバーの並びへ戻す**（[frontend.md](frontend.md)）。追従は直接操作でアニメーションを掛けない（`prefers-reduced-motion` の分岐を持たない）。キーボードでの並べ替えと、端末ごとの並び・複数タブの自動同期は非ゴール（[api-catalog.md](api-catalog.md#エージェントの表示順)）
- 保存 / 削除が成功したらシートを閉じて一覧へ戻る。失敗したときは開いたままにし、同じ note をシートの最下段へも出す（背面の note が見えないため）
- `Escape` の順は シート → ページ → チャット。シートは `<dialog>` の標準挙動で閉じ、`keydown` を `window` へ伝播させない（伝播させると同時に `App` がチャットへ戻す）
- 閾値は CSS の `--breakpoint-wide` と `client/src/lib/layout.ts` の `WIDE_MIN_WIDTH` が同じ値を持つ（片方を変えたらもう片方も変える。`docs-check` では検出できない）。`LayoutMode`（desktop / portrait / landscape）には足さない — `html[data-layout]` と CSS の `singleColumn:` バリアントが 1:1 で連動しており、値を変えると見た目が全画面で動く（[モードと境界](#モードと境界)）
- 一覧を積む帯が無くなるので、一覧だけのページは 1 行のグリッド（`grid-rows-1`）にする。一覧側の高さ上限（`DefinitionList` の帯）も外し、スクロールはページ 1 本に統一する
- 「アプリに戻る」は singleColumn のときだけ、設定ページのヘッダ左端（`☰` の左）に出す。狭い desktop では左バー overlay の ☰ が nav の導線になる
- 開閉 state は編集対象と分ける（`null` が「新規」も意味して閉じた状態と区別できないため）。幅を狭めてシートの帯に入っても勝手には開かない

## サイドバー

nav / settings の 2 モードを持ち、モードは URL から導出する（`NavSheet` は同じ `Sidebar` を開くだけなので、desktop と singleColumn のどちらでも切替が保たれる）。

- **overlay ではモードの切替（設定 / アプリに戻る）でドロワーを閉じず、セクションの選択で閉じる。** 切替で中身が入れ替わると押した項目が unmount するため、焦点はドロワーの中の先頭操作要素へ引き戻す。閉じる要求は 1 経路に寄せる
- `Escape` の順は 詳細シート → nav ドロワー → チャットで、開いているもの 1 つだけが受ける
- 退場の終了は `animationend` が本則だが、animation を切る環境では来ないため、CSS の時間値の最大から保険を掛ける
- 退場アニメ中に**モーダルを開く操作だけは退場後（unmount と同じコミット）に実行する**（退場中に開くと、開いたモーダルが戻り先として掴む要素が unmount で消え、閉じた後に focus が body へ落ちる）
- **焦点を戻す先（ドロワーを開いた要素）が消えているか `focus()` が効かない場合は、docked の nav の先頭、無ければドロワーを開く導線へ戻す**（起点はドロワーを開いたまま docked へ広げると unmount するため）
- 閉じた内容はアニメーションのため DOM に残すので、`inert` で操作・読み上げの対象から外す
- **開閉の保存は `cwd` をキーにする**（`project.id` は削除 → 再登録を跨がない）。Effect で書かないのは、行の選択が先に `Sidebar` を unmount する面があるため（mount 時に 1 回読んで write-through する）
- 一覧と設定ナビのスクロール枠は scrollbar gutter を常に確保し、あふれの有無で内容幅を変えない。**overlay scrollbar の環境ではガターに頼れないため、サムが行・項目と重ならない余白を右側に持つ**（重なったサムの描画順は環境依存で、前面・背面のどちらも破綻して見える）。**設定ページの内側のスクロール枠も同じ扱いにする**（例: 設定 → ファイル（/settings/files）のツリー）
- 行のハイライトは開いているセッションだけが持つ。**作成先の選択は見た目に持たない**

### 幅

docked の左バーの幅は右端のハンドルで選べる。幅の正は `client/src/lib/sidebarWidth.ts`（bounds / clamp / step / parse / store）。

- **上限を viewport に依存させない。** docked になる帯でも main が十分残り、右パネルとチャットの下限の和を上回るため
- ドラッグ中は React を再描画せずシェルの CSS 変数だけを書き換え、確定は pointerup / pointercancel / lostpointercapture / アンマウントのどの経路でも同じ処理を通す
- 幅を広げると設定ページの 2 カラム判定を割って 1 カラムへ落ちることがある。判定は container 幅が正なので許容する

### nav モード

ブランド / 新しい会話 / Projects / Chats（現在の会話スペースのチップ）/ フットノート / 設定（下部固定）。フットノートには health の `versions.commitHash` を、返るときだけ併記する（設定 → ランタイム の環境タブの接続状態カードと同じ値。ローカル開発では返らないので出さない）。

- プロジェクト行のクリックは折りたたみのトグルで、行の操作は 設定 → ファイル と同じ ⋯ メニューに畳む（プロジェクト行とセッション行で共有）。削除は danger のトーンに揃える
- セッション行の ⋯ には引き継ぎの項目を出す（プロジェクト配下の一覧も含む）。実行中・圧縮中・片付け中は無効にし、押せない理由を説明行へ出す（項目ごと隠さない）
- **セッション行の状態は「いま動いている」ものだけを出す**（実行中 / 圧縮中 / 回答待ち、その他は無表示）。回答待ち（`awaitingAnswer`）は実行中より優先し、待機件数と理由は行に出さない。導出は純関数が正で、行の寿命（BFF の再起動と sweep / TTL で idle へ戻ること）は [run-lifecycle.md](run-lifecycle.md#ライフサイクル--制限) を参照する
- 状態ラベルは行の truncate 対象の外の縮まない要素として置く（長い名前でもラベルが切れない）。**色だけで意味を伝えない**（出す行では状態の要素だけに `title` を付ける。行全体に付けると行全体のツールチップになる）
- 並び順はプロジェクトが作成順、配下はピン留めを先に `lastUsedAt` 降順。同値の行は元の一覧順を保つ。ピン留めがあるときは、そのかたまりを小見出しと区切り線で他と分ける（無ければどちらも出さない）。グループ化は純関数が担い、**未知の `projectId` は `Chats` へ寄せて一覧から消さない**
- プロジェクトの削除の確認では配下セッション数を示し、ディレクトリが残ることも明示する

### settings モード

「アプリに戻る」+ セクションの一覧（並びは `SETTINGS_SECTIONS` が正）。開いている項目は塗りで示し、**内側の一覧の選択とは色を分ける**（ページの選択と一覧の選択を区別する）。行の寸法は 1 箇所（`MenuItem`）が持ち、内側の一覧と共有する。テーマ切替の入口は「外観」に一本化する（バーとドロワーには置かない）。

一覧は Projects と Chats を 1 つのスクロール領域にまとめ、設定ナビは下部に固定する。高さが足りない viewport では、desktop は一覧を、singleColumn は**ドロワー全体**を 1 つのスクロール領域にする（一覧だけを伸縮させると 0px に潰れる）。

## 制約

- Android Chrome はソフトキーボード表示で `window.innerHeight` が縮むため、desktop 表示中でも一時的に landscape へ切り替わることがある（キーボードを閉じれば戻る。タッチ入力の送信はキーボードを閉じる）。**高さの判定に `visualViewport` は使っていない**
- 幅が足りないタブレットは portrait になり、左バーはドロワーへ退避する
- iOS Safari の safe-area は `Composer` の下余白で扱う。`viewport-fit=cover` は指定していない
