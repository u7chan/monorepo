# u7agent 音声入力スパイク

OpenAI Realtime API の `gpt-live-transcribe` を使い、日本語を話し終わる前に文字が出るかを確かめる、ローカル専用の実験です。u7agent 本体への統合、OpenRouter 対応、録音の保存、会話への自動送信は行いません。

## 起動

Bun 1.4.4 で動作確認しています。ブラウザはマイクと WebRTC の送信フレーム制御（`RTCRtpScriptTransform`）を使える最新版の Chromium 系を推奨します。

```sh
cd projects/_labs/u7agent-voice-input
bun install --frozen-lockfile
bun --no-env-file run start
```

起動時に表示される `http://localhost:8790/` を開き、GUI に **OpenAI Platform の API キー**を入力して「登録」を押します。`.env` は作りません。登録は外部通信を行わず、キーが使えるかは録音開始時に確認されます。

このアプリにはログイン認証がなく、同じローカルサーバーを開くタブは登録状態を共有します。LAN やインターネットへ公開しないでください。常用キーではなく検証用のキーを使い、テスト後は「登録解除」するかサーバーを停止してください。パスワードマネージャーの保存確認が出た場合も保存しないでください。

## 実マイクで検証する

1. 「自動停止時間」で 10 秒・30 秒・1 分・2 分（既定）から選びます。入力欄のマイク（「録音開始」）を押し、「録音中」が出たら日本語で話します。例：「明日の午後三時に、青い傘を持って駅前へ行きます」
2. **まだ話している間に**光る入力欄へ文字が入ることを確認してから、四角ボタン（「停止・確定」）を押します。短文だけで判断せず、長めの文や英数字を含む文でも試してください。
3. 同じ入力欄で語尾まで確定し、編集できることを確認します。すでに下書きがあればカーソル位置に入り、エラー時は元の下書きに戻ります。停止後に初めて文字が出た場合、文字起こしは成功しても Live の検証は不合格です。
4. 「録音開始 → 最初の途中表示」「停止 → 確定」の時間を控えます。前者の起点は実際の発話開始の検知ではなく、画面が録音中になった時点です。後者は末尾の音声到着を待つ時間を含みます。音声・文字起こし本文・キーを検証結果へ転載する必要はありません。

自動停止を試すなら、10 秒を選び、四角ボタンを押さずに待ちます。ボタンの外周が減り、残り 3 秒で点滅します。動きの軽減を設定している場合、点滅せず残量の弧が警告色に変わります。上限に達すると新しい音声の送信を止め、マイクを解放して文字起こしを確定します。画面が一時的に固まっても上限以降の音声フレームは送信せず、マイクの解放と確定は画面の処理が再開してから行います。

手動・自動どちらの停止でも、今回の録音開始から停止までの時間と、[公式単価](https://developers.openai.com/api/docs/models/gpt-live-transcribe#pricing)を掛けた概算コスト（USD）が出ます。確定イベントに音声秒数があれば、その秒数で概算を更新します。接続準備や確定を待つ時間は録音時間に含めず、概算は請求額や累計を示すものではありません。

## 構成

- Bun + Hono の BFF が Hono JSX で 1 ページを返し、ブラウザ標準の JS と CSS で操作します。
- 通常の API キーは BFF のメモリだけに登録し、ブラウザへ返しません。録音ごとに BFF が文字起こし用の短命キーを取得します。マイク音声と文字起こしイベントはブラウザと OpenAI の間で WebRTC により送受信し、BFF は中継・保存しません。OpenAI 側では API 利用料がかかります。
- サーバー側 VAD（無音検出）は使わず、停止で 1 発話を確定します。音声と確定イベントは別経路なので、マイクを止めてから短く待って確定を要求します。末尾の欠落がないかは実マイクで確認します。

実キー不要のテストは `bun run test`。OpenAI の [Realtime 文字起こし](https://developers.openai.com/api/docs/guides/realtime-transcription) と [WebRTC 接続](https://developers.openai.com/api/docs/guides/voice-webrtc?api=realtime) を参照しています。
