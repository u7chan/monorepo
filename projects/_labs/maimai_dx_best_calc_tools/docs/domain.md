## 1. RATING の全体構造

> Splash PLUS 以降、RATING は **【楽曲RATING（新曲枠）】+【楽曲RATING（ベスト枠）】** で算出される。
> 段位RATING は Splash PLUS で廃止。オトモダチ対戦の段位は現在 RATING に影響しない → **本ツールの対象外**。

```
RATING = Σ 単曲レート値（新曲枠 上位15譜面）
       + Σ 単曲レート値（ベスト枠 上位35譜面）
       + APボーナス（対象譜面のうち AP 以上評価の数）
```

- 新曲枠: 直近バージョン + 一つ前のバージョンで追加された全譜面 のうち、単曲レート値上位 **15** 譜面
- ベスト枠: 新曲枠の候補とならない全譜面 のうち、単曲レート値上位 **35** 譜面（Splash までは 25）

## 2. 単曲レート値

```
単曲レート値 = floor( 譜面定数 × 達成率(実数) × Rank係数 )
```

### 2.1 譜面定数

- 提示 Lv とは別の内部難易度（小数第1位まで）。例: 表示「Lv13」でも内部 13.3 として処理されることがある
- ツールBの選択肢より、現行は Lv15(.0) / Lv14〜10(.0〜.9) / Lv9〜7(.0, .7) / Lv6以下(.0) の分布
- （参考）BUDDiES までは .7〜.9 に「+」（例: 13+）が付く表記仕様だった
- （参考）PRiSM PLUS 以降、筐体・maimaiでらっくすNET で曲が**定数の小さい順**に並ぶため、新曲の定数推測がしやすくなった → 定数推定の際の手掛かり

### 2.2 達成率

- リザルト表示は % 単位だが、算出時は **100分の1した実数** を用いる（例: 99.50% → 0.9950）
- 理論値は 101% だが、RATING 算出では **天井 100.5%（= 1.005）**。それ以上は全て 1.005 とみなす
  - ツールBも入力上限 101、係数判定用には 100.5 で cap する実装

### 2.3 Rank係数

達成率（%）に対するステップ関数。**境界の「寸止め」値（100.4999 など）にも専用の係数が存在する**（ユーザー指摘、ツールB `getRankCoefficient()` と実装一致）。

### 2.4 小数切捨の位置

- wiki の式は「(小数切捨)」と明記。ツールBも **単曲レート値ごとに `Math.floor`** している → **デフォルト: 単曲レート値で切捨**
- 最終 RATING も整数（ツールBは合計に `Math.floor`）

## 3. APボーナス

- **CiRCLE から追加** された要素
- でらっくすRATINGの対象になっている楽曲（譜面＝カウント対象50譜面）に **ALL PERFECT 以上の評価** がつくと +1 ポイント
  - AP = 達成率 100.00% 以上（AP+ の 100.50% 以上も含む）
  - ツールBは単曲レート = floor(基礎値) + 1（APチェック時）として実装
- 実装: `単曲レート値 = floor(譜面定数 × 達成率(実数) × 係数) + (achievement >= 100.00 ? 1 : 0)`
  - 入力に AP フラグを持たせても良いが、達成率 >= 100.00 で自動判定できる（ツールBは 101% 入力時に自動チェック + 手動も可）

## 4. 枠の定義（新曲枠 / ベスト枠）

### 4.1 新曲枠の候補

- **現バージョン** で追加された全譜面 + **一つ前のバージョン** で追加された全譜面
- 「全てのでらっくす譜面」でも「『新曲だよ！』カテゴリ」でもない。**スタンダード譜面でも現バージョンで追加されれば新曲枠**（難易度単位で判定: BASIC/ADVANCED/EXPERT/MASTER/Re:MASTER それぞれが独立した譜面データ）

### 4.2 Re:MASTER の例外

- BASIC〜MASTER 譜面が **過去バージョン** で追加されている場合、その楽曲の Re:MASTER は例外的に **ベスト枠の候補** となる
- 例1: **We Gonna Party** — Re:MAS 追加が楽曲収録バージョンより後 → ベスト枠扱い
- 例2: **Blows Up Everything** — Re:MAS 追加が楽曲収録バージョンと同じ → 新曲枠扱い

```
判定ロジック（譜面単位）:
is_new_candidate(chart) =
    chart.added_version ∈ {current_version, prev_version}
    AND NOT ( chart.difficulty == Re:MASTER
              AND song の BASIC〜MASTER の最古追加version < chart.added_version )
```

### 4.3 ベスト枠

- 新曲枠の候補とならない全譜面（= 上記で除外されたものすべて）から単曲レート値上位 35

## 7. データモデル（実装用）

```ts
// 譜面マスタ（定数DB）
interface Chart {
  songName: string;
  difficulty: 'BASIC' | 'ADVANCED' | 'EXPERT' | 'MASTER' | 'Re:MASTER';
  level: number;          // 表示Lv (1〜15)
  constant: number;       // 譜面定数 (例: 13.3)
  addedVersion: string;   // この譜面の追加バージョン (難易度単位)
  // isDx: boolean;  // スタンダード/でらっくす (枠判定には不要だが情報として保持可)
}

// スコア（ユーザーのプレイデータ。最初のステップは手渡しCSV想定）
interface Score {
  songName: string;
  difficulty: string;
  achievement: number;   // 達成率 % (2桁表示 → 4桁入力許容)
  // isAp?: boolean;     // 省略時は achievement >= 100.00 で自動判定
}

// 設定
interface Config {
  currentVersion: string; // 例: 'PRiSM PLUS' ← 要確認（新曲枠判定に必須）
  prevVersion: string;    // currentVersion の直前バージョン
}
```

## 8. スコア入力フォーマット（Lv毎の CSV を想定）

maimai.net（公式マイページ）のスコア一覧をユーザーが渡す前提。最初のステップは認証なしで、ユーザーが書き出した CSV をそのまま読む。

```csv
level,song,difficulty,achievement
12,曲名A,MASTER,99.32
12,曲名B,Re:MASTER,100.00
13,曲名C,MASTER,96.99
```

- `level` は便宜上の仕分け（Lv別にファイル分割する場合はファイル名から判定でも可）
- `achievement` は % 値（2桁表示が基本。係数の境界寸止め判定のため 4桁入力も許容する）
- AP は `achievement >= 100.00` で自動判定（明示フラグ列も許容）
- 譜面定数は別途 **定数DB**（`constant` と `addedVersion` を持つ）を用意し、`(songName, difficulty)` で照合する
  - 定数DBが無い初期状態でも動くよう、CSVに `constant` 列を許容するかは要検討（楽曲名マッチングより確実なのはDB側で管理すること）

## 9. 未確定ポイント（較正・確認事項）

1. **単曲切捨の位置**: wiki 式は単曲切捨、wiki 目安値は切捨なしと矛盾 → デフォルトはツールBと同様の単曲切捨。実 RATING と比較して較正
2. **境界寸止め係数の実効範囲**: 100.4999 → 22.2 などは 4桁精度の入力でのみ発動。NET 表示（2桁）のスコア入力では実質「100.49 → 21.6」の扱いになる。4桁入力対応にする
3. **AP の判定境界**: 100.00% 以上で +1 とするが、厳密な境界（100.4999 の AP+ 扱い）は要検証
4. **現行バージョン名**: 新曲枠判定に必須。**要確認**（wiki 更新時点は PRiSM PLUS 以降の仕様。2026/03 時点の最新バージョン）
5. **旧係数**: wiki の「旧係数」列の値が未入手。現行係数を採用するが、過去バージョン対応が必要になったら再調査
