# ADR 0000: スタックと依存の方針（Preact + 自前実装、第三者の UI 依存を足さない）

- Status: accepted
- Date: 2026-10-15

## 背景

この PoC のクライアントに必要なのは、一覧・フォーム・会話ログ・最小の Markdown 表示・コピー程度で、
SSR も RSC も使わない。React 本体の 2025 年の重大な勧告（RCE / DoS / ソース露出）はいずれも RSC の経路で、
ここでは踏まない。ただし、使わない機能を積まないことは更新対応と攻撃面の削減として効く。

実際に効く対策はフレームワークの選択よりむしろ依存の選び方で、クライアントの依存は
サプライチェーンの事故（2025 の npm パッケージ侵害のキャンペーンなど）と、更新・ライセンス確認・レビューのコストを直接受ける。

## 決定

- クライアントは Preact で書く。実行時の依存は Preact（と Hono の `hono/client`）に限る。
- 第三者の React 互換ライブラリ（UI、状態管理、フォーム、Markdown、日付など）は足さず、必要なら自前で書く。
- `preact/compat` は使わない。
- 見た目は Tailwind（ビルド時のみ。クライアントへは CSS だけが出る）で組み、コンポーネント集を持たない。
- 時刻・数値の整形は `Intl` を使い、そのためのライブラリを足さない。
- 自前で書くものは仕様を小さく固定し、DOM に依存しない純関数としてテストする。
  - Markdown: 見出し・段落・強調・インラインコード・リスト・リンク・フェンス付きコードに限定する。
    生 HTML はテキストとして扱い、リンクは http / https だけを許可する。DOM は API で組み立て、`innerHTML` を使わない。
  - SSE: 認証ヘッダを載せるため `EventSource` は使えず、`fetch` のストリームを自前でパースする。
    chunk 境界・改行コード・複数行 `data` を純関数でテストする。
- サーバー側はこの限りではない。仕様や検証を同時に買える依存（OpenAPI のスキーマなど）は検討する（[ADR 0003](./0003-api-reference-for-ai.md)）。

## 理由

- 必要な UI が小さく、コンポーネントライブラリの利点（テーマ、データグリッド、a11y 対応）を使う場面がない。
- 依存を 1 つ足すごとに、更新・脆弱性対応・ライセンス確認・レビューが続く。lockfile 固定、`minimumReleaseAge`、
  `onlyBuiltDependencies`、install 時の `--ignore-scripts` と合わせて、足す依存を選べる状態を保つ。
- Preact は React と同じ JSX / hooks で書けて、実行時の依存が 1 パッケージで済む。バンドルも小さい。

## 影響

- Preact 固有の差分（`class`、`preact/compat` なし）を前提に書く。React 専用の API やパターンを持ち込まない。
- 日本語入力・フォーカス・スクロールなどの細部は自前で面倒を見る。壊れたときに直すのもこちら側になる。
- 依存を足すときは、次を満たすものだけを検討する。
  1. 実行時に必要（ビルド時で足りるなら足さない）
  2. 自前だと見通しが悪くなる規模、または自前だと危険（暗号、パーサなど）
  3. 問題が起きたときに差し替えられる
  4. 保守が続いていて、ライセンスがリポジトリの方針の範囲にある
