# ADR 0002: クライアントは Hono RPC でサーバーのルート型を共有する

- Status: accepted
- Date: 2026-10-15

## 背景

クライアント（Preact）とサーバー（Hono）は同じパッケージにある。`fetch` と手書きの型で API を呼ぶと、
`res.json()` の結果をキャストすることになり、サーバー側の変更がクライアントの型エラーにならない。
以降のステップで API は増えるため、呼び出しの型を保つ仕組みを最初に決める。

## 決定

- クライアントは `hono/client` の `hc` に、サーバーのルート型（`ApiType`）を渡して API を呼ぶ。
- ルート型はサーバーの実装（`src/server/app.ts`）から導出し、クライアントは `import type` で参照する。

## 理由

- レスポンスの型がサーバー実装から決まるため、ずれた時点で `pnpm typecheck` が落ちる。キャストが要らない。
- `hono/client` は `hono` に含まれ、依存を増やさない。
- `import type` はビルドで消えるので、サーバーのコード（`node:fs` など）はクライアントへバンドルされない。

## 影響

- クライアントの型はサーバーのルート定義に依存する（同一パッケージなので問題にならない）。
  別パッケージへ分ける場合は型を共有する仕組みが要る。
- ランタイムの検証は得られない。値そのものの妥当性はテストで担保する。
  API の仕様をスキーマで定義する場合の扱いは [ADR 0003](./0003-api-reference-for-ai.md) で検討する。
