# QR ペアリング（一時コードを共有トークンと交換する）

スマホで 64 桁の共有トークンを手入力する代わりに、`pnpm pair` が出した QR を読み取って認証する。
認証モデルは変えず、**一時コードを既存の共有トークンと交換する**だけにする（端末ごとのセッションは持たない）。

## 流れ

1. クライアントをビルドし、サーバーを起動する（[auth.md](./auth.md)）。

   ```bash
   pnpm build
   PORT=18081 pnpm start
   ```

2. LAN 到達設定を追加する（[lan-access.md](./lan-access.md)）。

   ```bash
   ./scripts/lan-access.sh --add
   ```

3. 一時コードを発行する。Windows の LAN IP を検出し、`http://<Windows の LAN IP>:<PORT>/#pair=<コード>` を QR として端末に描画する。

   ```bash
   pnpm pair
   ```

4. スマホで QR を読み取る。クライアントが `#pair=<コード>` を読んで `POST /api/pair` へ交換を投げ、受け取った共有トークンを `sessionStorage` に保存して通常の画面に入る。
   ハッシュは交換のあと `history.replaceState` で消える。交換に失敗した場合もハッシュは消え、理由が入力画面に出る。

`#pair=` はフラグメントなので、HTTP リクエストの URL・アクセスログ・Referer には送られない。ただしコード入りの URL は、端末に出した QR と、読み取った側の履歴には残りうる。

## 一時コード

- 8 バイトの `base64url`（11 文字）にする。長くすると QR が大きくなり、端末で読み取りにくくなる。
- 有効期限は 60 秒。**単回使用**で、交換に成功した時点で破棄する。
- 有効なコードはメモリに 1 件だけ置く。再発行すると以前のコードは即座に無効になる（複数の QR を同時に有効にしない）。
- 一致の判定は固定長へ揃えてから `timingSafeEqual` で行う（[auth.md](./auth.md) と同じ方針）。

## 発行できる相手

`POST /api/pair/new` は、サーバーから見た送信元が `127.0.0.1` / `::1` のときだけ受け付ける。それ以外は 404 を返し、発行 API の存在を見せない。

- portproxy は「Windows ホストからの新規接続」に置き換わるため、WSL2 から見た送信元は LAN のスマホも Windows のブラウザも同じ値になる。一方、WSL2 内のプロセスが `127.0.0.1` へ繋いだ場合は送信元が `127.0.0.1` になる。この差で発行元を判定する。
- この判定は、サーバーの待ち受けポートへ直接届いたリクエストにだけ意味を持つ。ローカルの reverse proxy を通すと、サーバーから見た送信元が loopback になる。
- 既知の経路である Vite の dev proxy は `/api/pair/new` を 403 で拒否する（転送しない）。

保証の範囲は「サーバーの待ち受けポートへ直接届いたリクエスト」と「Vite の dev proxy を塞いでいること」まで。他のローカル reverse proxy や SSH トンネルを併用した構成は対象外になる。

## 試行回数制限

`POST /api/pair` はプロセス全体で 1 分あたり 10 回を上限にし、超えたら 429 を返す。再発行ではリセットしない。
portproxy 経由ではスマホも Windows のブラウザも同じ送信元に見えるため、送信元ごとの区別はしない。

## API

| メソッドとパス | 認証 | リクエスト | 応答 |
| --- | --- | --- | --- |
| `POST /api/pair/new` | 不要（loopback 限定） | `{"origin":"http://<Windows の LAN IP>:<PORT>"}` | `{"code","url","expiresAt"}` |
| `POST /api/pair` | 不要 | `{"code":"<11 文字>"}` | 一致で `{"token"}`。形式不正は 400、不一致・期限切れ・使用済みは 410、回数超過は 429 |

- `origin` は `^http://[0-9A-Za-z.\-]+:[0-9]{1,5}$` の形だけを受け付ける。受け取った URL をそのまま QR にするため、https やパス付きは受け付けない。
- 410 と 400 の応答本文にトークンもコードも含めない。

## 残存リスク

- **HTTPS を使わない。** 一時コードも共有トークンも LAN を平文で流れる。TTL 60 秒・単回・試行制限で緩和するが、画面のスクリーンショットや撮影には無力。
- 60 秒の TTL は一時コードの期限であり、**交換で取得済みの共有トークンの期限にはならない**。
- 試行回数をプロセス全体で数えるため、LAN の第三者が上限を食い潰すと、その間はペアリングできない（時間窓の経過で回復する）。
- Windows を `mirrored` ネットワークにして送信元が `127.0.0.1` になる構成では、**発行の loopback 限定が成立しない**。
- `sessionStorage` に置くため、スマホのタブが破棄されると再ペアリングが必要になる。
- Windows の LAN IP が変わると QR の URL も変わる（`pnpm pair` は実行時に検出するので追従する）。
- 端末のフォントサイズによっては QR が小さすぎて読めない。その場合の代替（PNG 出力 / ブラウザで開くペアリングページ）は持たない。
