## 1. RATING の全体構造

> Splash PLUS 以降、RATING は **【楽曲RATING（新曲枠）】+【楽曲RATING（ベスト枠）】** で算出される。
> 段位RATING は Splash PLUS で廃止。オトモダチ対戦の段位は現在 RATING に影響しない → **本ツールの対象外**。

```
RATING = Σ 単曲レート値（新曲枠 上位15譜面）
       + Σ 単曲レート値（ベスト枠 上位35譜面）
       + APボーナス（対象譜面のうち AP 以上評価の数）
```

- 新曲枠: 直近バージョン + 一つ前のバージョンで追加された全譜面 のうち、単曲レート値上位 **15** 譜面
- ベスト枠: 新曲枠の候補とならない全譜面 のうち、単曲レート値上位 **35** 譜面（Splash までは 25）
- RATING に反映されるのは「達成率」と「AP ボーナス」のみ。FULL COMBO / FULL SYNC / でらっくスコア は RATING に影響しない（対象外、参考・非公式）

> 出典: 公式②「『maimai でらっくす CiRCLE』の稼働時は、『maimai でらっくす PRiSM PLUS』～『maimai でらっくす CiRCLE』に登場した楽曲から 15 曲が『RATING対象曲（新曲）』の対象に、『maimai でらっくす PRiSM』以前に登場した楽曲から 35 曲が『RATING対象曲（ベスト）』の対象になります。」

## 2. 単曲レート値

```
単曲レート値 = floor( 譜面定数 × 達成率(実数) × Rank係数 )
```

### 2.1 譜面定数

- 提示 Lv とは別の内部難易度（小数第1位まで）。例: 表示「Lv13」でも内部 13.3 として処理されることがある
- 現行は Lv15(.0) / Lv14〜10(.0〜.9) / Lv9〜7(.0, .7) / Lv6以下(.0) の分布
- （参考）BUDDiES までは .7〜.9 に「+」（例: 13+）が付く表記仕様だった
- （参考）PRiSM PLUS 以降、筐体・maimai でらっくすNET で曲が**定数の小さい順**に並ぶため、新曲の定数推測がしやすくなった → 定数推定の際の手掛かり

### 2.2 達成率

- リザルト表示は % 単位だが、算出時は **100分の1した実数** を用いる（例: 99.50% → 0.9950）
- 理論値は 101% だが、RATING 算出では **天井 100.5%（= 1.005）**。それ以上は全て 1.005 とみなす
  - 入力は 0〜101% を受け付けるが、算出時は**上限 100.5% に切り詰める**（100.5% を超えた値は 100.5% として扱う）
  - **較正済み（2026-08-31）**: 実データ（全 LEVEL ページ）で、この上限への切り詰め込みの単曲レート計算が実 RATING と一致することを確認
- **達成率の構造（BREAK ボーナス・2026-08-31 に仕様補足）**:
  - 通常スコア（100% 分）は全ノーツ PERFECT で満点。CRITICAL PERFECT と PERFECT は**等価**（失点なし）
  - BREAK ノーツのみボーナス点（最大 +1%）が加算される。BREAK 1 個あたりのボーナス = 1% ÷ その譜面の総 BREAK 数で、判定で得られる割合が変わる（CRITICAL PERFECT = 全額 / PERFECT = 半減〜消滅 / GREAT 以下 = 0）
  - したがって**達成率 100% 超えは「全ノーツ PERFECT」を意味しない**（GREAT が混ざっていても BREAK の CP で 100% を超え得る）
  - 理論値 101.0000% = 全ノーツ PERFECT + 全 BREAK CRITICAL PERFECT（= AP+）
- クリア基準は達成率 80.0000%（RANK A）以上（参考・非公式）
- COMBO 数は達成率に影響しない（参考・非公式）
- でらっくスコア（CRITICAL PERFECT×3 + PERFECT×2 + GREAT で算出。理論値 = 総ノーツ数×3）は達成率とは別指標で、RATING に影響しない（対象外）
- （参考・非公式）評価メダルの判定条件:
  | 評価 | 条件 |
  | --- | --- |
  | FULL COMBO | すべてのノーツを GOOD 以上 |
  | FULL COMBO+ | すべてのノーツを GREAT 以上 |
  | ALL PERFECT | すべてのノーツを PERFECT 以上 |
  | ALL PERFECT+ | すべての BREAK を CRITICAL PERFECT、それ以外を PERFECT 以上（= 達成率 101%） |
  | FULL SYNC 系 | 2 人以上プレイ時の FC/AP 条件の組み合わせ（詳細略） |

## 3. AP ボーナス

- **CiRCLE から追加** された要素（出典: 公式②「レーティング対象楽曲で『ALL PERFECT』以上の記録を達成した場合、その楽曲のレーティングに『1ポイント』のボーナスポイントが加算されます。」）
- でらっくすRATINGの対象になっている楽曲（譜面＝カウント対象50譜面）に **ALL PERFECT 以上の評価** がつくと +1 ポイント
  - AP = すべてのノーツを PERFECT 以上で取得（達成率 100.00% 以上とほぼ同値。参考・非公式）
  - AP+ = すべての BREAK を CRITICAL PERFECT、それ以外を PERFECT 以上（= 達成率 101% の理論値）も含む
- **AP ボーナス**: 対象譜面 1 つにつき +1 ポイント。**「全ノーツ PERFECT」（= AP）の譜面にのみ**付く（省略は特にない）
- 実装: `単曲レート値 = floor(譜面定数 × 達成率(実数) × 係数) + (perfect == total ? 1 : 0)`
  - `perfect` / `total` は NET の一覧に表示される PERFECT 数 / 総ノーツ数（コピペの 3 行組・HTML・ブックマークレット JSON のいずれでも取得できる）
  - **「達成率 >= 100.00%」での近似判定は廃止（2026-08-31 実データ較正）**: 達成率 100% 超えは BREAK ノーツの CP ボーナス（『達成率』参照）によるもので、GREAT が混ざっていても 100% を超え得るため、全ノーツ PERFECT の判定にはならない。実データでは「達成率 100% 超えの譜面が多数ある」一方「perfect == total」（全ノーツ PERFECT）の譜面はゼロという乖離を確認し、`perfect == total` 判定への変更で実 RATING と一致した
  - perfect / total が揃わない入力（ノーツ数がないコピペ等）では AP 判定をせず +0 とする

## 4. 枠の定義（新曲枠 / ベスト枠）

### 4.1 新曲枠の候補

- **現バージョン** で追加された全譜面 + **一つ前のバージョン** で追加された全譜面（出典: 公式②「『RATING対象曲（新曲）』の対象楽曲につきまして、1バージョン前までの楽曲が『RATING対象曲（新曲）』の対象に含まれるようになります。」）
- 「全てのでらっくす譜面」でも「『新曲だよ！』カテゴリ」でもない。**スタンダード譜面でも現バージョンで追加されれば新曲枠**（譜面難易度単位で判定: BASIC/ADVANCED/EXPERT/MASTER/Re:MASTER それぞれが独立した譜面データ。ST/DX 両系統とも対象。用語は『譜面の 2 系統: ST（スタンダード）と DX（でらっくす）』参照）

### 4.2 Re:MASTER の例外

- BASIC〜MASTER 譜面が **過去バージョン** で追加されている場合、その楽曲の Re:MASTER は例外的に **ベスト枠の候補** となる
- 例1: **We Gonna Party** — Re:MASTER 追加が楽曲収録バージョンより後 → ベスト枠扱い
- 例2: **Blows Up Everything** — Re:MASTER 追加が楽曲収録バージョンと同じ → 新曲枠扱い
- （別ペイン調査結果、2026-08-29）Re:MASTER 保有曲は計 148 曲（ST 系 92 / DX 系 56）。Re:MASTER は **FiNALE（19900）で導入**された仕様のため、それ以前の帯（10000〜19500）の ST 系曲は全て「B〜M の追加より後から追加」になる。**現行の新曲枠ウィンドウ（CiRCLE PLUS / CiRCLE 追加バンド）内で Re:M が後から追加された例はゼロ** → 現行バージョンではこの例外は実質発動しないが、実装は維持する（バージョン更新とともに必要になる）

```
判定ロジック（譜面単位）:
is_new_candidate(chart) =
    chart.added_version ∈ {current_version, prev_version}
    AND NOT ( chart.difficulty == Re:MASTER
              AND song の BASIC〜MASTER の最古追加version < chart.added_version )
```

### 4.3 ベスト枠

- 新曲枠の候補とならない全譜面（= 上記で除外されたものすべて）から単曲レート値上位 35

### 4.4 参考: NET サブスクリプションの「RATING 対象曲」表示（要検証）

- maimai でらっくすNET には**月額 330 円のサブスクリプション**があり、加入すると**でらっくすRATING の対象曲**（枠内 50 譜面）を画面上で確認できる公式機能がある（出典: ⑤ ゲキチュウマイ-NET、2026-08 確認。**表示内容の実測は未確認・要検証**）
- 真偽が確認できれば、枠判定（新曲枠/ベスト枠）の**正解データとして較正に利用できる**（本ツールはこの課金機能を使わず、コピペと計算だけで同等の結果を出すことを目的とする）

### 7.1 譜面の 2 系統: ST（スタンダード）と DX（でらっくす）

maimai でらっくすでは、1 曲に対して 2 系統の譜面が存在しうる（片方だけの曲も、両方ある曲もいる）。どちらも RATING 計算の対象。

| 略称 | 譜面名 | 説明 | 公式マスタ JSON のキー |
| --- | --- | --- | --- |
| ST | スタンダード譜面 | 従来からの譜面（ノーツは TAP / HOLD / SLIDE / BREAK） | `lev_bas` 〜 `lev_remas` |
| DX | でらっくす譜面 | でらっくすから追加された譜面（ST と同じ 4 種 + タッチパネル用の TOUCH ノーツ） | `dx_lev_bas` 〜 `dx_lev_remas` |

- 追加時期は系統ごとに別（例: 渦状銀河のシンフォニエッタは DX 譜面が 2020/08、ST 譜面が 2024/02 に追加された）
- RATING の計算値そのものには ST/DX の区別は**影響しない**（どちらも同じ式・同じ枠で数える）
- ただし「譜面定数」と「追加バージョン」は系統ごとに別の値を持つため、マスタ照合・新曲枠の判定（後述）では区別する
- 用語の整理: 「難易度」は 2 つの意味に区別して使う
  - **Lv**: 表示レベル（1〜15。7 以降は「+」付き）。スコア一覧の並び・LEVEL クエリはこの単位
  - **譜面難易度**: BASIC / ADVANCED / EXPERT / MASTER / Re:MASTER。譜面ごとの難易度区分

### 7.3 version フィールドの意味（確定）

公式マスタの `version` は **「スタンダード譜面（BASIC〜MASTER）の追加バージョン」** を指す。ST 譜面を持たない曲は **DX 譜面の追加バージョン**。以下の変化では**変わらない**（別ペイン調査、2026-08-29。9 事例の照合で確定）:

- Re:MASTER の後からの追加（例: We Gonna Party = 11000 のまま）
- 既存曲への DX 譜面の後からの追加（例: 千本桜 = 11000 のまま。2019 に DX 譜面追加）
- レベル改訂（レベル変更履歴とは無関係）
- 一方、**ST 譜面の後からの追加は反映される**（例: 渦状銀河のシンフォニエッタ = 24014（BUDDiES で ST 追加）、華の集落、秋のお届け = 24510（BUDDiES PLUS で ST 追加））

→ 新曲枠判定には「曲の ST 譜面基準」として使いやすい。ただし「DX 譜面だけ後から追加された曲」や Re:M は公式 version からは判定できないため、『Re:MASTER の例外』の判定ロジックと併用する。

## 9. スコア入力フォーマット

### 9.1 入力方式と取得手順

認証はユーザーのブラウザ側で済ませ、ツールには以下 3 方式のどれかで渡す（run.py が拡張子・内容で自動判定。実測 2026-08-29〜31）。

#### 9.1.1 コピペテキスト（方式 A・当初方式）

1. [maimai でらっくすNET](https://maimaidx.jp/maimai-mobile/)（https://maimaidx.jp/maimai-mobile/）にログイン
2. 「レコード」→「楽曲スコア」→ カテゴリ「LEVEL」で対象 Lv を選択
   - 例（Lv13）: https://maimaidx.jp/maimai-mobile/record/musicLevel/search/?level=19
3. 一覧画面で Ctrl+A → Ctrl+C（全選択コピー）し、そのテキストをファイルに保存してツールに渡す

- テキストには譜面難易度と ST/DX が含まれない（後述『既知の課題』）
- **LEVEL クエリの値は内部の Lv インデックス**で、表示 Lv と「+」を 1 段ずつ数える（Lv7 と Lv7+ が別段のため、7 以降は 2 段刻みになる）
- 表示 Lv N（整数）との対応: `level = N + max(0, N − 7)`。実測例: Lv13 → 19、Lv15 → 23
  - Lv6=6 / Lv7=7 / Lv7+=8 / Lv8=9 / … / Lv14=21 / Lv14+=22 / Lv15=23 の並びになる見込み

#### 9.1.2 ページ保存 HTML（方式 B・2026-08-31 対応）

- 同じ一覧画面をブラウザの Ctrl+S で保存した HTML をそのままツールに渡す（拡張子 .html または内容で自動判定）
- 実測構造: 1 譜面 = 1 フォーム（action が record/musicDetail）。画像 src のファイル名から確定できる:
  - `diff_basic.png`〜`diff_remaster.png` → 譜面難易度
  - `music_dx.png` / `music_standard.png` → ST / DX の系統
  - `music_lv_block` / `music_name_block` / `music_score_block` の div → Lv・曲名・達成率\%＋ノーツ数
- **未プレイの曲はスコアブロック自体が存在しない**（達成率無しエントリとして検出）。RATING 対象外として分離し、一覧で確認できる

#### 9.1.3 ブックマークレット JSON（方式 C・2026-08-31 対応）

- [tools/bookmarklet.html](../tools/bookmarklet.html) のブックマークレットを一覧ページで実行すると、スコアを JSON ファイル（例: `maimai_level19_2026-08-30-17-01-30.json`）としてダウンロードできる
- 出力は方式 B と同じ情報に加え、楽曲詳細ページのトークン（`idx`）を含む（将来の詳細取得用。現時点では未使用）
- JSON ファイルをそのままツールに渡す（拡張子 .json または内容で自動判定）

#### 9.1.4 バージョン別ページ（record/musicVersion・2026-08-30 実測）

- URL: https://maimaidx.jp/maimai-mobile/record/musicVersion/search/?version=26&diff=3
  - `version` = 0 始まりの連番（0 = maimai 初代 … 26 = CiRCLE PLUS。全 27 バージョン分）
  - `diff` = 譜面難易度（0=BASIC / 1=ADVANCED / 2=EXPERT / 3=MASTER を実測。4=Re:MASTER と推測・要確認）
- 掲載曲は「このバージョンで追加された譜面」単位のため、追加時期が系統（ST/DX）ごとに分かれる曲では公式マスタの version と一致しないことがある
  - 実測例: 魔理沙は大変なものを盗んでいきました DX MASTER 13+ はマスタ version=12002（GreeN）だが CiRCLE PLUS のページに掲載される → **譜面単位の追加バージョンの正は NET のバージョン別ページ**（『version フィールドの意味（確定）』の補足）
- コピペテキストでは難易度が文字に落ちないため CLI で `--difficulty` を指定する（HTML / JSON 入力では画像・DOM から確定するため指定不要）
- コピペのヘッダ行は LEVEL の代わりにバージョン名（例: `CiRCLE PLUS`）になる

※ 画面上は DX/ST や譜面難易度が画像アイコンで表示されており**見た目では区別できる**が、**コピペテキストには落ちない**（後述の『既知の課題』）。将来は Playwright 等で HTML をパースすれば画像タグから DX/ST を判別でき、より細かい情報も取れる（将来ステップ）。

```

...
```

※ 上記のスコア値・統計ブロックは**構造を実測したもので、数値自体はダミー**（実プレイデータではない）

- **達成率は 4 桁小数**（例: 98.7654%）→ 係数の境界寸止め判定（99.9999 / 100.4999 など）に必要な精度を NET 側が持っている
- `1,234 / 1,345` は Perfect 数 / 総ノーツ数（読取は任意。ユーザー較正時の目安に使える）
- LEVEL ヘッダ直後の統計ブロック（CLEAR!/S/S+/…/SSS+/FC/AP/SYNC PLAY/FS/★1〜5 の 分母付きカウント）は、ツール出力と自分の実績を突き合わせる**較正用データ**として使える

### 9.2 既知の課題: 譜面難易度・ST/DX がコピペテキストに含まれない

- コピペテキストからは「レベル・曲名・達成率・ノーツ数」しか得られず、**譜面難易度（BASIC〜Re:MASTER）と ST/DX の区別が消える**（HTML 上は画像/アイコンで表現されているため。実測確認済み）
- **HTML 保存・ブックマークレット JSON 入力では解決済み**（2026-08-31 実装・実測）: 画像 src / DOM から確定できるため、同一 (表示Lv, 曲名) に ST と DX が同居する曲も別レコードとして確定できる。
  - 実例: Lv13 の一覧で 17 譜面・Lv13+ で 5 譜面が「同一 (Lv, 曲名) に ST/DX の MASTER が同居」（定数 DB 集計・2026-08-31）で、コピペでは衝突になるが HTML / JSON では解決される
- したがって同一（レベル, 曲名）に複数譜面がぶつかる場合（例: MASTER と Re:MASTER が同 Lv、DX と ST で同 Lv）は、**コピペだけでは**どちらのスコアか確定できない
  - 対応候補: (a) 衝突時はユーザーに確認（楽曲詳細画面の譜面難易度別スコアから補完）、(b) 同じ曲名でも全譜面を同一達成率で扱う近似はしない、(c) 楽曲詳細画面のコピペも受け付ける
  - ※ コピペ方式のままなら衝突として報告・除外する方針（『枠選定』の実装メモ参照）。HTML / JSON 方式を推奨
- 曲名重複（『注意・データギャップ』）も同じ衝突問題に含まれる
- **将来ステップ**: Playwright 等で描画済み HTML をパースする認証付き自動取得に移行すれば、画像要素の alt/src から DX/ST 判別が可能になり、譜面難易度・ノーツ内訳なども取得できる（README の「認証つきの自動取得は将来ステップ」に対応）

### 9.3 正規化 CSV（内部用）

パース後は以下の形に正規化して計算コアへ渡す。


- `difficulty` / `chartType` はコピペからは得られない場合がある（『既知の課題』参照）。定数 DB 照合は `(songName, level)` で絞り込み、定数・追加バージョンは譜面が確定してから適用する
- AP は `achievement >= 100.00` で自動判定（明示フラグ列も許容）
- 譜面定数は別途 **定数 DB**（`constant` と `addedVersion` を持つ）を用意し、`(songName, difficulty, chartType)` で照合する
