# 文書作成ルール

このプロジェクトのドキュメント・コミュニケーションでの表記ルール。

## 表記

- 節の参照に「§」を使わない（例: 「§7.5」は禁止）。
  - 節を参照するときは、節タイトルを『』で囲んで参照する（例: 『楽曲画像（image_url）の取得』参照）
  - 見出しの番号（例: `### 7.5`）自体は使ってよい。禁止するのは本文中の「§」による参照のみ
- ドキュメントは日本語で書く。読者が馴染みのない記号・略記は避け、平易な表現にする
- 公式の文言を引用する場合は、句読点・括弧を含めてそのまま正確に引用する

## 出典

- 第三者が運営するデータサイト・攻略情報サイトを**出典として記載しない**（トラブル回避のため）。サイト名も具体例として書かない
- 引用・参照できるのは公式ソースのみ:
  - https://maimai.sega.jp/（公式サイト）
  - https://info-maimai.sega.jp/（公式おしらせ）
  - https://maimaidx.jp/（maimai でらっくすNET）
  - https://www.sega.jp/（SEGA 製品ページ）
- 第三者サイトの情報から得た知見を文書に含める場合は、サイト名を書かず「別ペイン調査」「コミュニティ調査」「調査整理」等の無難な表現にする

## 用語

- ST = スタンダード譜面 / DX = でらっくす譜面（説明: [domain.md](domain.md) の『譜面の 2 系統: ST（スタンダード）と DX（でらっくす）』参照）
- 「難易度」は 2 層を区別して書く: **Lv**（表示レベル 1〜15、7 以降は「+」付き）と **譜面難易度**（BASIC / ADVANCED / EXPERT / MASTER / Re:MASTER）

## 技術決定の記録（ADR）

- 技術スタック・アーキテクチャに関する決定は、[docs/adr/](adr/README.md) に ADR（Architecture Decision Record）として記録する
- 採番は連番（0001〜）、テンプレートは [docs/adr/template.md](adr/template.md) に従う
- ステータス: Proposed → Accepted → Superseded。決定が覆ったら元の ADR を Superseded にし、新しい ADR を立てる（元の ADR は書き換えない）

## 作業フロー

- 調査・実装の結果は**ローカルコミットまで**とし、push はユーザーから指示があるまで行わない
- PR の作成も、ユーザーから指示があるまで行わない（勝手に PR を出さない）
