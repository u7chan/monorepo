# ADR-0001: 定数 DB は JSON で開始し、ビューア実装時に RDB へ移行

- ステータス: Accepted（2026-08-29）
- 関連: docs/domain.md の『データモデル（実装用・例示）』『注意・データギャップ』

## コンテキスト

- RATING 計算には譜面定数が必要だが、公式マスタには定数が含まれない。DX 譜面の定数（970 曲分）は別途収集が必要
- 定数 DB の規模は数千行程度で、実行時（RATING 計算）は読み取り専用
- 更新は「収集 → 検証 → 更新」のプロセスで、変更履歴のレビューをしたい（git diff）
- 将来のビューア実装では曲の検索・絞り込み・画像キャッシュ管理などが出てくる可能性がある

## 決定

- 最初は **JSON ファイル**（git 管理）として用意する。diff で更新履歴を見える化する
- ビューア実装時に **SQLite / PostgreSQL へ移行**し、JSON をシードとして投入する
- RDB への移行先は、ビューアの技術スタック決定時に選定する（現時点では決めない）

## 結果

- 良い点: 実装初期に依存が不要、定数の変更が git diff でレビューできる、移行時に JSON をシードに使える
- 注意点: JSON は読み取り全量前提のため、データが肥大化したら（ビューア以降）RDB へ移行する
- 見直し条件: ビューア実装の着手時（移行先を選定して新 ADR を立てる）
