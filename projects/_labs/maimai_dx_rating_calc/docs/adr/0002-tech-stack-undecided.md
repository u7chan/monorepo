# ADR-0002: 技術スタックはビューア設計時に決定（現時点では未決定）

- ステータス: Accepted（2026-08-29）
- 関連: docs/domain.md の『データモデル（実装用・例示）』

## コンテキスト

- RATING 計算ツール（自作ツール）をこれから実装するが、ビューアの要件（画像の事前ダウンロード・検索・DB 運用・ホスティング）が未検討
- domain.md のデータモデルは TypeScript 表記で書かれていたが、これは仕様の構造を示すための例示であり、実装言語を約束するものではない
- 定数 DB の RDB 移行先（SQLite / PostgreSQL）もビューアの技術選定に依存する

## 決定

- **技術スタックは決定しない**。ビューアの設計（要件・運用・ホスティング）を行う時点で決定する
- それまでは、決定に必要な情報（仕様・データの形・制約）をドキュメントに残し、言語・フレームワーク非依存の表現で記述する
- 技術スタックが決まったら、本 ADR を `Superseded` にして新しい ADR を立てる

## 結果

- 良い点: ビューア要件を踏まえた歪みのない技術選定ができる。docs の例示表記に実装言語が混入しない
- 注意点: 実装を始める前に技術スタックの ADR が必要になる（計算コアの実装開始時が最初の決定ポイント）
- 見直し条件: 実装開始・ビューア設計の着手時
