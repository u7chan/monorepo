# GUI デザイン仕様案（枠内 50 譜面一覧ビューア）

> ステータス: 草案（2026-08-30・デザイン検討用。実装未着手）
> 技術スタックは未決定（[ADR-0002](adr/0002-tech-stack-undecided.md)）のため、本書は
> 画面構成と振る舞いをテキスト + ASCII 図で定義する（実装言語・フレームワークに依存しない）。
> 本書の数値は**すべてダミー**。実スコアは記載しない（作成ルールは [conventions.md](conventions.md)『プライバシー（個人データの非記載）』）。

## 1. 背景と目的

- 枠内 50 譜面（**新曲枠 15 + ベスト枠 35**）を一覧表示するビューアのデザイン案。
- 計算自体は PoC CLI（`poc/run.py` → `rating_detail.csv` / `rating_summary.csv`）で済んでおり、
  ビューアは**計算結果の閲覧に特化した読み取り専用画面**とする（スコア入力・再計算 UI は範囲外）。
- テーブルの列構成は既存 `rating_detail.csv` を踏襲し、左端にジャケット画像サムネイル列を追加する。
- レイアウトは 2 パターンを用意し、モックアップでは **1 つの HTML にタブを置いて切り替えられる構成**を提案する。

## 2. 前提（スコープとデータ源）

| 項目 | 内容 |
| --- | --- |
| 表示対象 | 枠内 50 譜面（枠 = 新曲 / ベスト）。`枠=圏外` 等の枠外行は既定非表示（フィルタは未確定・11 節） |
| データ源 | `rating_detail.csv`（行データ）+ `rating_summary.csv`（RATING 値・枠別合計・AP ボーナス数） |
| 画像 | 公式楽曲マスタの `image_url`（ファイル名のみ。フル URL と取得方針は domain.md『楽曲画像（image_url）の取得』） |
| ソート | 既定は枠ブロック内で**単曲レート降順** |
| 用語 | 「難易度」は Lv（表示レベル）と譜面難易度（BASIC〜Re:MASTER）の 2 層を区別する（conventions.md『用語』） |

## 3. 画面全体構成

1 画面 = ヘッダ領域（1 つ）+ タブ（レイアウト切替）+ テーブル領域。

```
+--------------------------------------------------------------------------+
| ヘッダ領域（RATING 値・色帯・残り値・枠別合計）…… 4 節                      |
+--------------------------------------------------------------------------+
| [パターン A: 全 50 曲 1 テーブル] | [パターン B: 枠別分離]   ← タブ切替     |
+--------------------------------------------------------------------------+
| テーブル領域（タブの選択に応じて 6 節 or 7 節のレイアウトを描画）           |
+--------------------------------------------------------------------------+
```

- タブは「同じデータの 2 通りの見せ方」の切り替え。データは 1 ソース（CSV）で共通。
- モックアップはこの構成のまま静的 HTML 1 枚 + 最小限のスクリプトで作れる規模感。

## 4. ヘッダ領域

```
+--------------------------------------------------------------------------+
| RATING 15,123（ダミー）         新曲枠 4,700 / ベスト枠 10,420 / AP +3     |
| 色帯:  白─青─緑─黄─赤─紫─銅─銀─金─白金─[虹]─虹(極)                        |
|                            ▲ 現在地: 虹 ☆      次の色「虹 ☆☆」まで 残り 127 |
+--------------------------------------------------------------------------+
```

### 4.1 RATING 値と色帯

- RATING 値は `rating_summary.csv` の「RATING値」（踏襲）。
- 色帯は domain.md『RATING と色』の公式色表（白〜虹 (極) の 20 段階）に基づく横帯。
  - 帯幅は各帯の RATING 幅に比例させる（下位帯は最小幅を確保）。
  - 現在地に ▲ マーカーを置き、現在地の名称（例: 虹 ☆）をテキスト併記。
  - 公式は名称のみで RGB を公開していないため、配色は名称に基づく近似色を割り当てる
    （白帯は背景と区別できるよう境界線必須。近似色の確定は実装時）。
  - 14000 以上のマーク / 16000 以上のプレート変化（CiRCLE PLUS 稼働告知による公式仕様）は帯の注記として付けてもよい。

### 4.2 目標色までの残り値

- 「次の色の下限 − 現 RATING」をテキスト表示（例: 次の色「虹 ☆☆」まで 残り 127）。
- 下限値の取得元は domain.md『RATING と色』の実装用下限列。

### 4.3 枠別合計

- `rating_summary.csv` 踏襲: 新曲枠合計 / ベスト枠合計 / AP ボーナス数。
- パターン B（7 節）では各テーブルの見出しにも小計を重ねて表示してよい（重複は許容）。

## 5. テーブル列定義（両パターン共通）

基本は `rating_detail.csv` の列構成を踏襲する。画像列のみ追加。

| # | 列 | 内容・形式 | 備考 |
| --- | --- | --- | --- |
| 1 | 画像 | ジャケットサムネイル | **追加列（CSV には無い）・左端固定**。詳細は 8 節 |
| 2 | 曲名 | テキスト | CSV の「曲名」 |
| 3 | 譜面系統 | ST / DX | 計算値には影響しないが表示する（人間が見分ける情報として） |
| 4 | 譜面難易度 | BASIC / ADVANCED / EXPERT / MASTER / Re:MASTER | |
| 5 | 表示Lv | 1〜15（7 以降は + 付き） | |
| 6 | 達成率 | 小数 4 桁 + %（例: 100.5123%） | |
| 7 | 定数 | 小数 1 桁（例: 14.5） | |
| 8 | 係数 | Rank 係数（例: 22.4） | |
| 9 | 単曲レート | 整数（例: 326） | 既定ソートの基準 |
| 10 | 枠 | 新曲 / ベスト | パターン A ではブロック見出しと重複 → 非表示も選択肢（6 節） |
| 11 | APフラグ | AP 取得の有無（例: ○ / −） | AP のみ表示。FULL COMBO 等は RATING に影響しないため出さない |
| 12 | 追加バージョン | バージョン名（例: CiRCLE PLUS） | 新曲枠判定の根拠を可視化する列 |

- 追加候補（CSV に無い・要検討）: **枠内順位**（1〜15 / 1〜35）。「底上げで何番目か」を話すときに便利。

## 6. パターン A: 全 50 曲 1 テーブル（塊表示）

現行 CSV を開いたときの塊表示に近いスタイル。新曲枠ブロック → ベスト枠ブロックの順に 1 テーブルへ積む。

```
+--------------------------------------------------------------------------+
| [パターン A: 全 50 曲 1 テーブル] | [パターン B: 枠別分離]                 |
+--------------------------------------------------------------------------+
| ■ 新曲枠（15 譜面・単曲レート降順）                                        |
| +------+---------------+------+--------+----+-----------+------+------+----+
| | 画像 | 曲名          | 系統 | 難度   | Lv | 達成率    | 定数 | 単曲 | AP |
| +------+---------------+------+--------+----+-----------+------+------+----+
| | [J]  | ダミー曲名 A1 | DX   | MASTER |14+ | 100.5123% | 14.5 |  326 | ○  |
| | [J]  | ダミー曲名 A2 | ST   | MASTER |14  | 100.0123% | 14.0 |  302 | −  |
| | …    |                  （計 15 行）                                     |
| +------+---------------+------+--------+----+-----------+------+------+----+
|                                                                          |
| ■ ベスト枠（35 譜面・単曲レート降順）                                      |
| （新曲枠と同じ列構成のテーブル。計 35 行）                                  |
+--------------------------------------------------------------------------+
```

- ASCII 図では幅の都合で 係数・枠・追加バージョン 列を省略している。**本実装では 5 節の全列を表示する**。
- ブロック見出しに曲数と降順ソートを明記。ブロック間は間隔を空ける。
- 「枠」列はブロック見出しと重複するため、パターン A では非表示にしてよい
  （表示のままにする場合は CSV との照合性が上がる。実装時に選択）。
- 向いている用途: CSV の確認・全体の雰囲気把握・コピペで表比較をしたい場面。

## 7. パターン B: 枠別 2 テーブル

新曲枠 / ベスト枠を**別テーブル**に分離する。既定は縦積み（上: 新曲枠 / 下: ベスト枠）。

```
+--------------------------------------------------------------------------+
| [パターン A: 全 50 曲 1 テーブル] | [パターン B: 枠別分離]                 |
+--------------------------------------------------------------------------+
| ■ 新曲枠テーブル（15 譜面・単曲レート降順）     枠合計: 4,700（ダミー）     |
| +------+---------------+------+--------+----+-----------+------+------+----+
| | 画像 | 曲名          | 系統 | 難度   | Lv | 達成率    | 定数 | 単曲 | AP |
| +------+---------------+------+--------+----+-----------+------+------+----+
| | …    |                  （計 15 行）                                     |
| +------+---------------+------+--------+----+-----------+------+------+----+
|                                                                          |
| ■ ベスト枠テーブル（35 譜面・単曲レート降順）   枠合計: 10,420（ダミー）    |
| （同じ列構成。計 35 行）                                                   |
+--------------------------------------------------------------------------+
```

- 各テーブル見出しに枠合計（単曲レート総和）を表示。AP ボーナスはヘッダ領域側でよい。
- 横幅が十分な環境では**左右並置**（新曲枠を左・ベスト枠を右）にしてもよい（ワイド画面向けの変形）。
- 向いている用途: 枠ごとの底（最下位）を確認し、底上げの対象を探す場面。

## 8. ジャケット画像サムネイルの扱い

- **ソース**: 公式楽曲マスタの `image_url`（ファイル名のみ）。フル URL は maimai でらっくすNET の画像パスを基底とする
  （PNG 190×190。domain.md『楽曲画像（image_url）の取得』参照）。
- **取得方針**: 表示のたびに公式サイトへリクエストを投げず、**事前に一括ダウンロードしてローカル保持**する
  （公式側のアクセス負荷への配慮。再取得は更新差分のみ）。
- **表示**: サムネイルは 32〜40px 角程度を想定（行高を圧迫しない）。左端固定・クリックで拡大は任意機能。
- **フォールバック**: 画像未取得・読み込み失敗時は、空セルにせず **枠バッジ（新曲 / ベスト）+ 系統（ST / DX）の
  文字プレースホルダ** で代用する。
- **モックでの扱い**: 実画像をリポジトリに同梱しない（配信画像の再配布回避 + サイズ。グレーボックス等のダミーで代替）。

## 9. 表示の振る舞い

- 既定ソート: 枠ブロック内で単曲レート降順（パターン A / B 共通）。
- 列ヘッダクリックによるソート（達成率・定数・単曲レート等）は実装時オプション。
- 行ホバーの強調・行選択から曲詳細（将来の拡張）への導線は本仕様の範囲外（検討事項として 11 節に記載）。

## 10. モックアップ作成時の注意（ダミーデータ方針）

モックアップは `docs/` 配下（**Git 管理**）に置くため、以下を必須とする。

- **全数値はダミー**: 達成率・定数・係数・単曲レート・RATING 値・残り値・枠別合計は、
  実データと無関係に手で作った値（本書の ASCII 図のダミー同様、計算式に一貫したそれらしい値でよい）。
- **実データ照合チェック**: モック完成後、実データ CSV（`data/score_dump/out_fixed/`）と突き合わせ、
  **偶然一致した値があれば差し替える**。実 CSV の行をそのままコピペしない（`data/` は gitignore 済みだが参照して作らない）。
- **曲名**: 実在楽曲名を使用してよい（公式マスタ由来の公開情報）。「実在曲名 × ダミー数値」の組み合わせとし、
  誰かの実スコアの再現にはならないこと。
- **ジャケット画像**: 実画像を同梱しない。グレーボックス・単色ブロック等のプレースホルダ（8 節）。
- **公式値は使用可**: 色表の下限（15000 など）・係数表の値（22.4 など）・天井 100.5% は公式・仕様値なので
  そのまま使ってよい（domain.md『RATING と色』『Rank係数』『達成率』）。
- ダミーデータの持ち方: HTML に直接埋め込むか、別 JSON / 別スクリプトで生成するかは未確定（11 節）。
