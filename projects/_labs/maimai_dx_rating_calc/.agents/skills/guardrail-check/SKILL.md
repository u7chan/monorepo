# ガードレール点検（コミット前チェック）

コミット / push 前に、リポジトリに載せてはいけないものが diff に混入していないかを点検する。
ルールの正は [docs/conventions.md](../../docs/conventions.md)『出典』『プライバシー（個人データの非記載）』。

## 検査対象の diff

| 状態 | コマンド |
| --- | --- |
| コミット済み（作業ツリーがクリーン） | `git diff main...HEAD` |
| ステージ済み（コミット直前） | `git diff --cached` |
| 未コミット | `git diff` |

## 手順

1. 検査対象の diff を用意する（上の表に従う）
2. 補助スクリプトを実行する: `bash .agents/skills/guardrail-check/check.sh [--cached | diffファイル]`
   - 機械チェック可能な項目（①〜⑫）を自動で流す
   - 実データ由来の数値・曲名は **`data/` からその都度抽出**する（SKILL.md やスクリプトにハードコードしない）
3. 機械チェックで「!! ヒット」が出た項目は 1 件ずつ目視で確認し、**実データ（ユーザーの実スコア等）かどうか**を判断する
   - ダミー値（`poc/example_*` 等）や公式データの集計値（マスタ・定数 DB の譜面数など）は**問題なし**と判断してよい
4. 機械チェックできない項目を目視で確認する:
   - プレイ傾向が推測される記述がないか（得意 Lv・プレイ済み曲数・実績の並びなど）
   - 第三者サイトの名前・URL が具体的に書かれていないか（どんな文脈でも書かない）
   - `data/` 配下のファイルが追跡・ステージされていないか
5. 結果を報告する（下記テンプレート）

## チェック項目一覧

| # | 項目 | 方法 |
| --- | --- | --- |
| ① | 機密パターン（API key・秘密鍵・パスワード・個人パス・UUID・issue 番号） | スクリプト（grep） |
| ② | .jsonl（セッションファイル）・.pyc の混入 | スクリプト（git status） |
| ③ | 実データ由来の数値（達成率 4 桁小数・5 桁 RATING 値）の一致 | スクリプト（data/ から抽出した候補と diff を照合） |
| ④ | 実曲名（data/ の分析・プラン文書の表から抽出）の一致 | スクリプト（同上） |
| ⑤ | 「§」表記の不使用（conventions『表記』） | スクリプト（grep） |
| ⑥ | 第三者サイトの具体名（@wiki・攻略・データサイト・定数表サイト等） | スクリプト（grep） |
| ⑦ | http(s) URL の一覧表示 → 公式のみか目視 | スクリプト（表示 + 公式ドメイン以外を検出） |
| ⑧ | 達成率っぽい値の構造的な出現（目視用） | スクリプト（表示のみ） |
| ⑨ | diff の整形（空白エラー） | `git diff --check` |
| ⑩ | `data/` の追跡なし（.gitignore 除外が機能しているか） | スクリプト（git ls-files） |
| ⑪ | 未追跡ファイル・作業ツリーの状態 | スクリプト（git status） |
| ⑫ | テスト（コード変更時は必須） | `python3 -m unittest poc/test_rating.py` |

公式ドメイン: `maimai.sega.jp` / `info-maimai.sega.jp` / `maimaidx.jp` / `otogame-net.com` / `www.sega.jp`（conventions『出典』）。サンプル用の `example.com` / `localhost` は許可。

## 報告テンプレート

```
ガードレール点検の結果（<対象: コミット hash や範囲>）
- ①〜⑫: ヒットなし / !! ヒット N 件（内容と判断を列挙）
- 目視項目: 問題なし / 問題あり（内容）
```

## 注意

- `data/` は**読むだけでコミット・push しない**（.gitignore 除外済み）。スクリプトも読み取りのみ
- 実スコア値・実曲名を SKILL.md やスクリプトにハードコードしない（data/ から抽出する。値はプレイのたびに変わるため）
- ③④の一致は「実データ漏れの疑い」のサイン。公式データやダミー値が引っかかった場合は問題なしと判断してよい
- スキル自身（`.agents/skills/guardrail-check/`）の差分は、パターン定義を含むため機械チェックから自動除外される（スクリプトが注意メッセージを出す）。その場合はスキルファイルの内容を**目視で確認**すること
