# 価格の取り込みと単価の決め方

- Status: accepted
- Date: 2026-11-23

## 背景

価格は OpenRouter のモデルごとの `/endpoints` の `pricing[]` にしか無く、一覧 API は返さない。
1 モデルに複数の endpoint が返ることがあり、同じ請求単位で単価が違うことがある。上流は通貨も請求単位も
宣言しない。

画像は出力側の単価だけを返すが、音声の一覧 `GET /api/v1/models?output_modalities=speech` は
`pricing.prompt` / `completion` を返すものの**請求単位を持たない**。実測では 39 モデルが文字（30）/
UTF-8 バイト（4）/ text+audio トークン（3）/ 出力秒（1）/ 不明（1）に分かれ、`prompt` をそのまま
「1M tok」と表示すると取り違える。特に `bytedance-seed/seed-audio-1-0` は `prompt: 0` /
`completion: 0.0025` なので、素直に写すと無料に見える。

## 決定

取り込みの手順（叩く API・並列度・コマンド）と失敗時の扱いは README を正とし、ここには判断と前提だけを書く。

- 同じ請求単位は最大単価に潰す。配列順に依存させず、過小評価しない側に倒す。`endpoint` は応答に含めない
  （OpenRouter 固有の語彙を u7agent まで持ち込まない）。
- provider 横断でも最大を採る。音声は provider 間で最大 6 倍の差がある。
- 通貨は `USD` 固定で付与する。上流の `pricing[]` は通貨を宣言しない（2026-11-16 時点で全行に無い）。
  将来 `USD` 以外を宣言する provider を足したときは、その行を落とす。
- `token` 建てのモデルは 1 枚単価を出さない（1M token あたりで出す）。1 枚の実額は測らない。
- `billable` を `output_image` / `input_text` / `output_audio` に増やし、表示側は `side` に正規化する。
  画像の「出力側だけ」は画像固有の規則で、音声は入力側（文字・バイト・トークン）が主。
- 金額は数値 API を正とし、単位語は `llms.txt` の `## Pricing` からだけ写す。`minute` だけは秒→分の係数
  （×60）を llms の金額で検算し、食い違えば前回行を残す（60 倍の誤表示を黙って出さない）。
- `:free` は `/endpoints` が 0 を返すので `$0`。`llms.txt` は base の価格を返すため、金額には使わない。
- 単位語が未知・混在・`llms.txt` の形式変更のときは、そのモデルの前回行を残す。確定した「価格なし」だけ落とす。
- 上流の応答本文はログにもファイルにも出さない。

## 採用しない案

- `prompt` をそのまま「1M tok」として表示する: 文字・バイト・秒のモデルを取り違え、無料に見える行も出る。
- `llms.txt` の金額を使う: base の価格で、provider ごとの単価ではない。
- 平均や最小を採る: 過小評価になり、実際に選ぶと高い方に当たる。
- `endpoint` を応答に含める: OpenRouter 固有の語彙が u7agent まで漏れる。
- 通貨を推測する: 上流が宣言しない以上、`USD` 以外の provider を足したときに黙って誤表示する。

## 影響

- 古い価格が残る期間は許容する。取り込みは手動で、鮮度は `fetchedAt` で見える。
- 単位語が読めないモデルは前回の行が残る。新しいモデルは行ができない。
- 音声の `minute` は llms の金額と食い違うと反映されない。
