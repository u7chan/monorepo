# u7agent から独立したコストマスタ

- Status: accepted
- Date: 2026-11-23

## 背景

u7agent の 設定 → コンテンツ生成 はモデル名しか出さず、1 枚 $0.007 のモデルと $0.25 のモデルが同じ見た目で並ぶ。
価格は OpenRouter のモデルごとの `/endpoints` の `pricing[]` にしか無く、一覧 API は返さない。

BFF が価格を取りに行くと、設定画面の更新がモデル数ぶんの上流リクエストに縛られる（2026-11-16 時点で 68 件）。
加えて「高価だから既定で一覧に出さない」という人の判断をどこかに持つ必要があり、リポジトリの seed だと
変更のたびに PR と再デプロイが要る。

## 決定

- 価格と判断を u7agent の外に置く。u7agent は任意の URL に問い合わせ、未設定・OFF・失敗のどれでも従来どおり動く。
- 公開するのは読み取りの API が主で、更新はマスタの置き換え（`PUT /api/master/:kind`）と判断の 1 行更新
  （`PUT /api/judgments`）だけに限る。DB も認証も持たない。LAN / VPN の内側に置く前提も変えない。
- マスタの更新は当初「ファイルを編集してデプロイ」で足りるとしたが、この判断は改訂した。置き場と契約は
  [master-files.md](./master-files.md)、判断は [judgments.md](./judgments.md) に分ける。
- 守るのは「一覧に出すか」という表示だけの情報で、秘密も会計も無い。統制は到達範囲（LAN / VPN）と
  same-origin 検査（別サイトからの送信を拒否）に置く。
- サーバーは上流へ出ない。価格の取り込みは手元で実行し、結果をマスタとしてアップロードする。
- 会計は目的にしない。実額・残高・予算は扱わず、モデルを選ぶときの指標だけを返す。

## 採用しない案

- u7agent に取り込む: 価格の取り込みと人の判断が u7agent のリリースに縛られ、u7agent 側の変更も大きくなる。
- DB を持つ: 読み取り専用の JSON で足り、バックアップと migration が増える。
- 認証を足す: 守る対象が表示の判断だけなので、1 ユーザー向けの認証を別途持つ理由が無い。
- BFF が上流を叩く: 設定画面の表示が上流の応答時間とレート制限に縛られる。
- seed をリポジトリに置いて PR で変える: 判断 1 件の変更にも PR とデプロイが要り、「リリースを待たずに変える」を満たさない。
- 判断を別サービスに分ける: 価格と判断は同じ画面で突き合わせるので、2 つの URL と鮮度を持つ理由が無い。

## 影響

- u7agent は価格の取得先を 1 つの URL として持ち、未設定・OFF・失敗のどれでも従来どおり動く。
- 価格の鮮度は `fetchedAt` で見える。自動更新はしないので、古い価格が残る期間は許容する。
- ロールバックの意味は「image tag を戻す」ではなく「`.bak` または直前のファイルをアップロードし直す」に変わる。
