# マスタの 2 ファイルと置き場

- Status: accepted
- Date: 2026-11-23

## 背景

マスタには、機械的に生成できる価格と、人が決める「一覧に出すか」の判断が混ざる。当初は image に焼き込み、
更新のたびに CD とデプロイを回す構成にしたが、判断 1 件の変更にも再ビルドが必要で、「判断はリリースを
待たずに変えたい」という出発点を満たしていなかった。

## 決定

### 2 ファイルに分ける

`prices.json` は機械生成、`enabled.json` は人手。1 ファイルに混ぜると、生成スクリプトが人の判断を上書きするか、
人が生成値に触れるかのどちらかになる。生成は行だけを書き、判断は別ファイルに置く。

### 置き場は volume にする

- マスタを `MASTER_DIR`（volume）に移し、volume に 1 つも無いときだけ image 同梱の初期値を seed する。
  片方だけあるときはコピーしない（消した判断を image の初期値で黙って戻さない）。
- リクエストごとに mtime を見て読み直す。再起動なしで反映される。
- 置き換えは原子的（tmp + rename）で、直前の内容を 1 世代 `.bak` に残す。

### 更新の契約

- アップロードは起動時の読み込みより厳しい。1 行でも不正なら全体を拒否する。人が明示的に反映する操作で、
  黙って行を落とすと「隠したつもりが隠れていない」に気付けない。
- 片方だけ差し替えて全体が読めなくなるなら拒否する（「反映したのに 503」を作らない）。
- ファイル単位の破損（無い・トップレベルの形が違う・JSON として壊れている・有効な価格行が 1 つも残らない）は
  503 にする。空の一覧を 200 で返すと「価格が消えた」と読めるため、u7agent には前回の値を持たせる。
- 行単位の破損（型・語彙・負の単価・重複・同じモデルの `enabled` の食い違い）は、その行だけ落として既定へ倒し、
  起動ログに理由を出す。1 行の破損で価格一覧全体を止めない。
- 読めないときは理由（`failure`）を `/api/health` に固定の語彙で返し、画面にも同じ理由を出す。
  ログを見なくても次に何を直すかが分かるようにする。
- 語彙（スキーマ）を変える版は、アップロードを先、デプロイを後にする。旧版は知らないキーを無視するので
  先にアップロードしても読めるが、逆順にすると旧形式のファイルが全行落ちて 503 が続く。
- `version` は `prices.json` の世代のまま動かさない。判断の変更は u7agent の手動更新で届く。

### 履歴

マスタは git の履歴から外れる（volume が正）。変更の記録は `.bak` と画面の操作だけになるため、「いつ何を隠したか」を
残したい場合は監査ログを足す。この版では持たない。

## 採用しない案

- image に焼き込む: 判断 1 件の変更に再ビルドが必要で、目的を満たさない。
- DB に置く: 読み取り専用の JSON で足り、バックアップと migration が増える。
- git で管理する: 第三者の価格をリポジトリの履歴に載せず、更新のたびに PR を要求しない。
- 1 ファイルにまとめる: 生成が人の判断を上書きするか、人が生成値に触れるかのどちらかになる。
- 片方だけ volume に無いときも seed する: 消した判断が image の初期値で戻る。
- 起動時に全ファイルをメモリへ固定する: 更新のたびに再起動が要る。

## 影響

- 再デプロイせずにマスタを更新できる。起動時に volume が空なら image の初期値から始まる。
- `.bak` は 1 世代なので、連続した更新は互いの直前の状態を上書きする。
- マスタの更新は u7agent の手動更新で反映される。
