# ADR 0016: 使い切ったカードは一覧の末尾に回す

- Status: accepted
- Date: 2026-10-29
- 関連: [ADR 0009](0009-window-blocking-and-five-hour-rolling.md) の停止表示

## 背景

カードは Codex、続いて登録順の OpenCode Go アカウントで、利用状態に関係なく並んでいた。
使い切ったアカウントも同じ位置に残るため、2 列の画面では使えるカードと交互に並ぶ。
上から読んでも「いま使えるのはどれか」が分からず、使えるカードを探して視線を往復することになる。

## 決定

- すべての窓が 100%、または外側の窓に止められているカードを「使い切ったカード」として一覧の末尾にまとめる。
- 使い切っていないカードどうし、使い切ったカードどうしは元の並び（Codex → 登録順）を保つ。
- 取得前・取得失敗で窓が無いカードは、使えるか分からないため動かさない。
- 並びはクライアントで毎回決める。保存しない。

採用しない案:

- 残量の少ない順に並べる: 窓ごとに意味の違う % を 1 つの値に潰すことになり、リセット直後と月末で並びが入れ替わり続ける。
- 使い切ったカードを隠す: リセット日時は確認したいので、消さずに下へ回すだけにする。
- サーバー側で並べ替える: 表示の都合で API の応答順を変える必要はない。

## 理由

知りたいのは「いま使えるのはどれか」で、使えないカードは待つしかない。上に置いておく価値がないため
下へ回す。並びを保存しないので、リセットで使えるようになったカードは自動で元の位置へ戻る。

## 影響

- `src/client/lib/order.ts` の `isExhausted` / `orderSources` を `App` が描画前に通す。
- `key` は source id のままなので、並びが変わってもカードの開閉状態は付いていく。
- 使い切った瞬間にカードが位置を飛ぶ。起きるのはリセット境界の 1 回だけで、移動のアニメーションは付けない。
