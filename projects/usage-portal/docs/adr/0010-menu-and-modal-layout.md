# ADR 0010: 常設ボタンをヘッダーとカードのメニューへ移し、追加はモーダルにする

- Status: accepted
- Date: 2026-10-27

## 背景

ヘッダーにはログアウト、カードには編集と削除、一覧の下には「OpenCode Go のアカウント」セクションと
アカウント追加のボタンが常に出ていた。日常の操作は「利用枠を見る」だけで、これらはたまにしか使わない。
スマホでは縦に長くなり、いちばん見たいゲージが押し下げられる。どのボタンがどのカードに効くのかも
並びだけでは分かりにくかった。

## 決定

- ヘッダー右上の `⋮` に「アカウントを追加」と「ログアウト」を入れる。ツールバーは自動更新の状態だけにする。
- カード右上（状態ラベルの隣）の `⋮` に「編集」と「削除」を入れる。操作の対象がカードの中に閉じる。
- アカウントの追加は `<dialog>` のモーダルにする。一覧の下のセクションは廃止する。
- 未登録のときは一覧に案内カードを 1 枚出し、そこにも追加ボタンを置く。行き止まりを作らない。
- 削除の確認はカード内のインラインのままにする。モーダルの上にモーダルを重ねない。
- メニューは自前の 1 段だけ。Esc と外側のクリックで閉じる。

採用しない案:

- メニューをライブラリで作る: 1 段の開閉に依存を増やさない（[0000](0000-stack-and-style.md)）。
- 追加フォームを一覧の先頭にインラインで出す: 入力中に一覧が押し下げられ、対象のカードが動く。
- 背景のクリックでモーダルを閉じる: 入力中の API キーを誤タップで捨てる。
- 削除もモーダルにする: 確認と実行が同じ位置にある方が、押し間違いに戻せる。

## 理由

見るための画面から、設定のための操作を 1 段下げる。操作は対象（ヘッダーなら全体、カードなら
そのアカウント）の近くに置き、常時出す必要のないものだけを隠す。

## 影響

- ログアウトはヘッダーのメニューにしか無いため、`App` ではなくダッシュボードがレイアウトごと描く。
- アカウントの上限（10 件）に達したら、メニューの項目を無効にし、ラベルに上限を出す。
