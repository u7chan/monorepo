# ADR 0009: 外側の窓が尽きたときの停止表示と、ローリングの 5 時間

- Status: accepted
- Date: 2026-10-27
- 一部置き換え: [ADR 0008](0008-remaining-gauge-and-window-trend.md) の OpenCode Go のローリングの期間（6 時間 → 5 時間）

## 背景

ゲージは窓ごとに独立して残量を出していた。窓は入れ子になっていて、月次 ⊃ 週次 ⊃ ローリングの
順に外側が内側を制限する。OpenCode Go の利用枠は月次の上限に対して 5 時間で 20%、週次で 50%、
月次で 100% と定義されている。月次が尽きた時点で、週次とローリングが残っていても使えない。

それでも内側の窓は「残り 40%」と表示され、しかも自分のリセット時刻を出していた。残っているように
見えるうえ、リセットまで待てば使えるとも読める。実際には外側が戻るまで使えない。

ローリングの期間は ADR 0008 で 6 時間としていた。OpenCode Go の API は `limit_window_seconds` を
返さないため、id から引くしかない。上流の定義を確認したところ 5 時間が正しかった。

## 決定

- 外側の窓（期間が長い方）が 100% のとき、内側の窓は赤いバーと「使用不可」にする。
- 止められた窓のキャプションからリセット時刻を外し、「月次が上限のため使えません」に差し替える。
  自分のリセットでは解除されないため、時刻を出すと嘘になる。
- 複数の外側が尽きているときは、最も外側を理由にする。いつ使えるように戻るかを決めるのはそれだから。
- 窓の内外はラベル（ローリング / 週次 / 月次）で決める。期間が分からないラベルは比較に参加させない。
- 100% に達した窓自身も赤にし、80〜99% の橙とは分ける。「残りわずか」と「もう使えない」は別の状態。
- OpenCode Go のローリングの期間は 5 時間。推移の横軸は `trend.ts` の `ID_SPANS_MS` で決める。

採用しない案:

- 内側の窓を非表示にする: 外側が戻った直後に何が残っているか読めなくなる。
- 内側の窓にリセット時刻を残す: 解除されると誤読する。
- 止められた窓を橙のままにする: 「残りわずか」と「使えない」の区別が付かない。
- 窓の並び順で外側を決める: 並びは provider の実装詳細で、Codex と OpenCode Go で根拠が違う。
- ローリングを 6 時間のままにする: 上流の定義とずれ、リセット直後の推移が 1 時間余分に平らになる。

## 理由

「残っているか」ではなく「いま使えるか」を 1 目で分かるようにする。使えない窓に残量だけを出しても
行動は変わらず、リセット時刻は誤った期待を作る。ゲージの色と文言で停止を表せば、窓を消さずに
残量と履歴は残せる。

## 影響

- 窓を足すときは `WINDOW_LABELS` のいずれかのラベルにする。未知のラベルは停止判定の対象外になる。
- `limitReached` は provider 全体の状態として扱い、停止判定には使わない。窓ごとの使用率で決める。
