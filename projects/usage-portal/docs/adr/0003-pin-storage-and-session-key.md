# ADR 0003: PIN とセッション鍵の保存（初回セットアップで完結させる）

- Status: accepted
- Date: 2026-10-25
- Supersedes: [ADR 0002](./0002-authentication-and-exposure.md) の「PIN ハッシュと署名鍵を環境変数で渡す」部分

## 背景

ADR 0002 は `PIN_HASH_B64` と `SESSION_SECRET` を `.env` で渡す前提だった。この形には次の問題があった。

- PIN を決めるためにホストでハッシュ生成コマンドを実行し、`.env` を編集する必要がある。手順が 2 段階で、初回の敷居が高い
- `$argon2id$...` を base64url に変換する理由（Compose の `$` 展開を避ける）が利用者に見えない
- デプロイ基盤側は `.env` の存在を前提にできないため、target ごとに「必須ファイル」の扱いを足す必要がある

一方で、秘密はリポジトリに置かない前提は維持する。6 桁 PIN は 10^6 通りしかないため、ハッシュをリポジトリへ置くと総当たりで PIN が復元できてしまう。

## 決定

- PIN は初回アクセスの画面で登録する。6 桁の数字だけを受け付け、`Bun.password.hash`（Argon2id）のハッシュだけを
  `DATA_DIR/pin-hash` に 0600 で保存する。ソルトはハッシュ文字列に内包され、別に管理しない
- セッション署名鍵は初回起動時に 32 bytes を生成し、`DATA_DIR/session-key` に 0600 で保存する。環境変数では受け取らない
- `pin-hash` は `O_CREAT|O_EXCL`（`wx`）で作る。同時にセットアップされた場合は後勝ちにせず、負けた側を 409 にする
- 状態は `setup_required`（`pin-hash` が無い）/ `ok` / `misconfigured`（`pin-hash` が壊れている、`session-key` が読めない）。
  `setup_required` は故障ではないため `/api/health` は 200 を返す
- PIN を忘れたときの操作は `pin-hash` の削除。再起動は不要で、次のリクエストからセットアップ画面に戻る
- 保存時暗号化（API キーや Codex の資格情報）は入れない。平文 0600 とし、ディレクトリ 0700 と非 root で守る

採用しない案:

- `.env` にハッシュを置き続ける: 生成コマンドと base64url 変換が利用者に見え、デプロイ側にも「必須ファイル」の分岐が要る。
  値を GitHub Actions の secret へ移す方法もあるが、設定が 2 箇所に散るだけで、初回の手間は減らない
- PIN ハッシュを SQLite の行に持つ: リセットが `DELETE` 文になり、履歴（24 時間の推移）を巻き込むか、スキーマを知る必要が出る
- PIN を暗号化して保存する: 照合には復号が要るので、鍵の管理がもう 1 つ増える。6 桁 PIN はハッシュの計算コストと試行制限で守る
- master key を `DATA_DIR` に置いても暗号化する: 暗号文と同じ場所に鍵を置くことになり、ディスク全体を持ち出された場合に無意味

## 理由

- 初回の操作が「開いて PIN を決める」の 1 段階になり、ホスト側の作業が消える。デプロイ基盤は `.env` を用意しなくてよい
- ファイル 1 個の追加・削除で状態が変わるので、運用（リセット）とテストが単純になる。DB のスキーマに認証を持ち込まない
- ソルトをハッシュに内包させる Argon2id の形式にそのまま乗るので、ソルトの保存先を決める必要がない

## 影響

- PIN を変更すると `pin-hash` が変わる。署名は「セッション鍵 + 現在の PIN ハッシュ + payload」に対して取るため、
  変更前の cookie はすべて無効になる。全端末で再ログインが必要
- `DATA_DIR` のバックアップには PIN ハッシュとセッション鍵が含まれる。復元するとログイン状態も戻る
- `pin-hash` を消せる人（ホストにアクセスできる人）は PIN を再設定できる。ADR 0002 の「信頼する 1 ユーザー・閉域 LAN」前提の範囲
- セッション cookie の `Secure` は付けない。v1 は HTTP で LAN 内にだけ出すため。TLS 終端を置くときに足す
- client は `hc` ではなく `fetch` と `src/client/api.ts` の型で API を呼ぶ。`hc` の request body 型は validator を入れるまで
  共有できず、auth の POST には利点がないため。`AppType` は server 側の型の正として残す
