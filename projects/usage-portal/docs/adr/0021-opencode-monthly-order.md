# ADR 0021: OpenCode Go のカードは月次の残りが多い順に並べる

- Status: accepted
- Date: 2026-11-18
- 関連: [ADR 0009](0009-window-blocking-and-five-hour-rolling.md) の窓の入れ子、[ADR 0016](0016-exhausted-cards-last.md) の並び

## 背景

ADR 0016 で使い切ったカードだけを末尾へ回し、それ以外は登録順（Codex → 登録順）のままにしていた。
同じ契約のアカウントを複数登録すると、月次が残り 1% のアカウントが 34% のアカウントより上に来る。
登録順は登録した時点の都合で、いま残っている量とは関係がない。

月次は一番外側の窓で、尽きたら週次とローリングが残っていても使えない（ADR 0009）。次に使えなくなるのは
月次の残りが少ないアカウントで、どのアカウントから使うかを決めるにはその順番で並んでいる方がよい。

## 決定

- 使い切っていない OpenCode Go のカードを、月次の残り（100 − 使用率）が多い順に並べる。
  残りが同じなら元の順を保つ。
- 月次を読めないカードは元の位置に残す。Codex（月次を持たない）、取得前・取得失敗（窓が無い）、
  月次を返さない応答が該当する。
- 使い切ったカードはこれまでどおり末尾にまとめる。月次の残り順は使い切っていないカードにだけ適用する。
- 並びはクライアントで毎回決める。保存しない。

採用しない案:

- すべての provider を同じ基準で並べる: Codex は週次しか持たず、月次と同じ物差しが無い。混ぜると、
  確かめていない順位で上に出る。
- 月次を読めないカードを 0% か 100% とみなす: 取得前・取得失敗のカードが、実態と違う位置へ飛ぶ。
- すべての窓の残りを 1 つの値に潰す: ADR 0016 で採らないと決めた。窓ごとに意味が違う。
- サーバーで並べ替える: 表示の都合で API の応答順を変えない（ADR 0016 と同じ）。

## 理由

同じ契約のアカウントを複数持つとき、知りたいのは「どれから使えば長くもつか」で、月次はその比較に使える
唯一の共通の窓になる。使い切ったカードは待つしかないため、ADR 0016 のとおり末尾のままにする。

## 影響

- `src/client/lib/order.ts` の `orderSources` が `byMonthlyRemaining` を通す。
- 月次がリセットされると並びが入れ替わる。移動のアニメーションは付けない。
- 月次を読めないカードは位置を保つため、月次の残り順の途中に残ることがある。
