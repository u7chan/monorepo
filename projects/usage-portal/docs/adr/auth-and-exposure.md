# 入口の認証と公開範囲

- Status: accepted
- Date: 2026-11-23

## 背景

画面は読み取り専用だが、どの利用枠がどれだけ残っているかは外に見せたくない。利用端末は自宅 LAN のスマホと PC で、
出先では VPN 経由で自宅 LAN に入る。利用者は 1 人で、ユーザー管理・パスワード再発行・複数端末の使い分けは要らない。
利用枠を守るのは上流の認証情報であり、入口の認証ではない。入口に求めるのは「誰でも開ける状態を避ける」ことで、
通信の秘匿や LAN 内の盗聴への対策ではない。

## 決定

- 6 桁の数字 PIN を 1 つだけ持つ。PIN は Argon2id のハッシュだけを `DATA_DIR/pin-hash` に 0600 で保存し、
  ソルトはハッシュ文字列に内包させる。
- PIN は初回アクセスの画面で登録する。`O_CREAT|O_EXCL`（`wx`）で作り、同時にセットアップされた場合は
  後勝ちにせず、負けた側を 409 にする。
- セッション署名鍵は初回起動時に 32 bytes を生成し、`DATA_DIR/session-key` に 0600 で保存する。
  環境変数では受け取らない。
- ログイン成功で署名付き HttpOnly cookie を発行する。サーバー側のセッションは持たず、有効期間は 30 日。
  残り 3 日で再ログインを促す。
- 署名は「セッション鍵 + 現在の PIN ハッシュ + payload」に対して取る。PIN を変えると全端末がログアウトされる。
- ログイン試行はメモリ上の sliding window で制限する。5 回失敗したら 15 分ロックし、`Retry-After` を返す。
  失敗の記録は DB に書かない。
- 公開範囲は自宅 LAN または VPN の内側だけ。`0.0.0.0:3001` で待ち受け、インターネットへは公開しない。
  TLS 終端は v1 のスコープ外とし、HTTP のまま使う。
- 認証 API と `/api/usage` は `Cache-Control: no-store` を付け、`POST` は同一 origin のときだけ受け付ける。
- PIN を忘れたときの操作は `pin-hash` の削除。再起動は不要で、次のリクエストからセットアップ画面に戻る。
- 状態は `setup_required`（`pin-hash` が無い）/ `ok` / `misconfigured`（`pin-hash` が壊れている、
  `session-key` が読めない）。`setup_required` は故障ではないため `/api/health` は 200 を返す。
- 保存時暗号化（API キーや Codex の資格情報）は入れない。平文 0600 とし、ディレクトリ 0700 と非 root で守る。

## 採用しない案

- 認証なし: 読み取り専用でも、利用状況は同じネットワークの誰にでも見せない。
- Basic 認証: ブラウザのダイアログとアプリの画面が二重になり、cookie の期限やログアウトをアプリ側で扱えない。
- パスキー / TOTP: 1 ユーザーの入口には過剰。総当たり耐性は Argon2id とレート制限で補う。
- インターネット公開 + TLS 必須: 6 桁 PIN はインターネット公開に耐える強度ではない。公開するなら認証方式ごと変える。
- PIN ハッシュや署名鍵を `.env` で渡す: PIN を決めるのにホストでハッシュ生成と base64url 変換が要り、
  デプロイ基盤にも「必須ファイル」の分岐が増える。
- PIN ハッシュを SQLite の行に持つ: リセットが `DELETE` 文になり、履歴を巻き込むかスキーマを知る必要が出る。
- PIN を暗号化して保存する: 照合には復号が要るので、鍵の管理がもう 1 つ増える。6 桁 PIN はハッシュの計算コストと
  試行制限で守る。
- master key を `DATA_DIR` に置いても暗号化する: 暗号文と同じ場所に鍵を置くことになり、ディスク全体を
  持ち出された場合に無意味。

## 影響

- cookie を盗まれた場合、有効期限まで使える。ログアウトはブラウザの cookie を消すだけで、サーバー側の失効リストは
  持たない。この用途では許容する。
- `DATA_DIR` のバックアップには PIN ハッシュとセッション鍵が含まれる。復元するとログイン状態も戻る。
- `pin-hash` を消せる人（ホストにアクセスできる人）は PIN を再設定できる。信頼する 1 ユーザー・閉域 LAN という前提の範囲。
- セッション cookie の `Secure` は付けない。v1 は HTTP で LAN 内にだけ出すため。TLS 終端を置くときに足す。
- PIN、ハッシュ、試行回数、cookie、API キー、token はログに出さない。
