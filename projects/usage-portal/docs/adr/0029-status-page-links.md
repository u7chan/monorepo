# ADR 0029: 稼働状況はアプリに取り込まず、メニューから公式ステータスを開く

- Status: accepted
- Date: 2026-11-22
- 置き換え: [ADR 0020](0020-opencode-service-status.md) の、公式の稼働状況を共通の欄に表示する決定

## 背景

ADR 0020 では、OpenCode Go の公式ステータス API を BFF で正規化し、カード一覧の上に共通の稼働状況欄を
置いていた。全体の状態に加えて、モデル別の状態と未解決のインシデントも展開して表示していた。

実際に使うと、Go のカードがあるあいだ常に一覧の上を占有する一方、稼働状況を確かめるのは障害を疑った
ときだけだった。モデル別の内訳も、公式ページを見れば同じ内容を確認できる。アプリ側で持つために、
認証付き API・キャッシュ・鮮度の判定・60 秒ごとの取得を維持する必要もあった。

## 決定

- OpenCode Go の稼働状況欄と、そのための `GET /api/opencode/status`、上流の取得・キャッシュ・鮮度判定、
  client の定期取得を削除する。モデル別の状態とインシデントもアプリでは表示しない。
- ヘッダーの `⋮` メニューに「ステータス」の子メニューを置き、Codex・Claude・OpenCode の公式ステータス
  ページへのリンクを並べる。リンクは新しいタブで開く。
- 子メニューは 1 段だけとし、既存のメニューのキーボード操作（矢印・Home / End・Escape）を子メニューでも使える
  ようにする。「ステータス」の項目では ↓ / → で子メニューを開き、Escape は子メニューだけを閉じて親の項目へ
  フォーカスを戻す。
- 稼働状況をアプリ内で監視・通知する機能は持たない。状態の判断は各社の公式ページに任せる。

## 採用しない案

- 稼働状況欄を残してモデル別の内訳だけ消す: 一覧の上の占有と、API・キャッシュの維持は変わらない。
- ステータスを引き続き取得し、正常時だけ隠す: 異常を検知するために常時取得する必要があり、
  表示しない情報のために通信と鮮度管理を続けることになる。
- 3 つのリンクをメニューの最上位に並べる: 設定やログアウトのあいだに外部リンクが混ざり、
  メニューが縦に伸びる。子メニューにまとめると、日常の操作の並びを変えずに置ける。

## 影響

- 稼働状況の API・キャッシュ・テストを削除する。依存パッケージ・環境変数・DB は変えない。
- 障害時の情報はアプリから通知されない。利用者はメニューから公式ページを開いて確認する。
- Codex・Claude の状態も同じ子メニューから確認できるようになり、provider ごとに導線が分かれない。
