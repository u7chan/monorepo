# ADR 0015: リセット行は残り時間を先頭のバッジにする

- Status: accepted
- Date: 2026-10-29
- 追記: [ADR 0008](0008-remaining-gauge-and-window-trend.md) のゲージの補足行

## 背景

リセット行は「リセット 04/15 10:00 · あと 9 日」と、日時と残り時間を同じ淡色のキャプションに
並べていた。ゲージが縦に続く画面では同じ形の行が繰り返され、視線は残量の数値とバーに集まる。
残り時間は同じ行の末尾にあり、日時の数字を読み終えてから探すことになる。

利用枠を使えるのは「いつ戻るか」ではなく「あとどれくらい待つか」で判断する。日時は確認用の
補足で、先頭に置く情報ではない。

## 決定

- 残り時間（「あと 12 日」）を枠付きのバッジにして行の先頭に置き、日時（「リセット 04/02 09:00」）を
  その右に淡色で続ける。
- バッジに状態の色は付けない。危険度は見出しの状態ラベルとゲージの橙 / 赤が持つ。
- 停止中に差し替わる「月次が上限のため使えません」はバッジにしない。待てば戻る情報ではないため。

採用しない案:

- 日時のまま末尾にバッジを足す: 残り時間が行末に流れ、狭い列では次の行へ単独で落ちる。
- 「04/02 09:00 にリセット」と語順ごと変える: 文言が伸びて 1 行に収まらず、カードが縦に伸びる。
- 残り時間を状態の色で塗る: 残量の色と二重になり、どちらが危険度を表すのか分からなくなる。

## 理由

待ち時間は数字 1 つで足りるため、バッジにすると行の中で最初に目に入る。日時は形の違う淡色の
文字として残すので、必要なときに読める。DOM の順序も読み上げの順序と一致する。

## 影響

- `describeReset` の返す文字列は変えず、`UsageMeter` の並びだけを変える（`test/client-format.test.ts` は据え置き）。
- 見た目は `.up-badge`（枠と背景）と `.up-meter-reset`（折り返しと間隔）で決める。
