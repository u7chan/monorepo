# ADR 0020: 有効な Go カードがあるときだけ公式の稼働状況を表示する

- Status: accepted
- Date: 2026-11-15

## 背景

利用枠が残っていても、モデルの遅延や上流プロバイダーの障害で使いにくいことがある。利用枠・契約の状態と
サービスの稼働状況を区別して確認したい。一方、Go を使っていないときまで情報を増やす必要はない。

[OpenCode の公式ステータス](https://opencode.ai/status/) は、認証不要の
`https://opencode.ai/status/api/status` で状態、モデル別の内訳、インシデントを公開している。
全体の状態には Free・従量課金も含まれるため、そのまま Go の状態として使うと誤表示になる。

## 決定

- 有効な Go カードが 1 件以上あるとき、カード一覧の上に共通の稼働状況欄を 1 つ置く。
  有効とは利用枠の取得に成功しており、現在のエラーが未接続・キー無効・契約なしでないこととする。
  利用枠の上限到達は契約無効とは扱わない。一時的な取得失敗でも前回値があれば表示を続ける。
- 欄が表示されている間だけ、client が初回と 60 秒ごとに認証必須の `GET /api/opencode/status` を呼ぶ。
  API は `Cache-Control: no-store` とし、上流の取得失敗も 200 の `state` で返す。
- BFF は要求時に公開 API を取得し、成功・失敗とも 60 秒キャッシュする。同時取得は single-flight にする。
  キャッシュは全端末・アカウント共通で、DB には保存しない。上流のタイムアウトは 8 秒。
- 現在の状態は `components` の `service: "go"` を使う。全体・Free・従量課金の状態は混ぜない。
  正常・性能低下・障害を文言・記号・色で区別し、未知の状態を正常へ丸めない。
- 初期状態は閉じ、見出しと状態ラベルだけを表示する。見出しボタンを押すと、理由・影響モデル・公式更新日時・
  公式リンク・モデル別の内訳・Go の未解決インシデントをまとめて展開する。開閉時は高さ・透明度・矢印を
  アニメーションさせ、動きを減らす設定では即時に切り替える。閉じた詳細は読み上げ・キーボード操作の対象にしない。
  閉じていても状態ラベルの更新は続ける。Go が正常に戻っても未解決のインシデントは復旧後の監視中として残す。
- 通信・HTTP・schema の失敗を Go の障害とは判定しない。前回値があれば `stale`、無ければ `error` とする。
  BFF 再起動後に snapshot の無い取得失敗が返っても、ブラウザの前回値を消さない。公式が `stale` と返す場合や
  `updatedAt` が 5 分より古い場合も「更新停止」とし、古い正常値を緑で出さない。
- 公開 API に API キーや cookie を送らない。任意の本文・notes・履歴を転載せず、必要な分類・時刻・モデル ID
  だけを正規化する。利用枠の取得・接続確認・カードの状態判定は変更しない。

## 採用しない案

- アカウントごとに同じ情報を表示・取得する: 稼働状況はアカウントに依存せず、表示と要求が重複する。
- 常に取得する: 有効な Go カードが無いときにも通信・表示が増える。
- 利用枠の sampler に組み込む: 5 分周期では遅延や短い障害に気づきにくく、不要な保存も増える。
- 利用枠の上流エラーを障害とみなす: 契約・キー・通信の問題と、公式が報告するサービス障害を区別できない。
- 個別モデルの状態から Go 全体を再判定する: 公式の集約基準と食い違うため、集約は公式に任せる。

## 影響

- 依存パッケージ・環境変数・DB migration は追加しない。再起動するとキャッシュは失われる。
- 公式が監視する主要モデルの状態であり、全モデルの状態や個別の推論リクエストの成功を保証するものではない。
- 表示条件は利用枠の最新取得結果で変わるため、契約・キーの変更の反映は利用枠の取得周期に従う。
