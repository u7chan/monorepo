# ADR 0011: 表示の密度を「簡易」と「標準」で切り替える

- Status: accepted
- Date: 2026-10-28

## 背景

Codex 1 枚に OpenCode Go のアカウントごとのカードが加わるため、3 件も登録すると 1 画面に収まらない。
カードの高さの大半は推移グラフが占める。日常的に見たいのは「いま残りがいくつか」で、推移は
原因を調べるときにだけ見る。推移を消してしまうと調べるときに見られず、常に出すと件数が多い日に
スクロールが増える。

## 決定

- ヘッダー右上に「簡易 / 標準」の切り替えを置く。カード単位ではなく画面全体の密度を変える。
- 簡易表示では推移グラフ（見出し・タブ・凡例）と provider の補足（OpenCode Go / プラン名）を出さず、
  カードの余白も詰める。残量のゲージ、リセット時刻、注意の文言は残す。
- 900px 以上では、簡易表示のあいだカードを `auto-fit` で 3 列まで並べる。3 件程度なら
  スクロールせずに一望できる。標準表示は推移を読める幅を優先して 2 列のままにする。
- 選択はサーバーに持たせず `localStorage`（`usage-portal:view-mode`）に置く。既定は標準表示。
  値が読めない・書けない環境（プライベートモードなど）でも、標準表示で開いて例外は投げない。
- 推移のデータはこれまでどおり `/api/usage` が返す。表示しないだけで、取得と保存の量は変えない。

採用しない案:

- 推移をカードごとの折りたたみにする: 見たい窓を開くのにカードごとに 1 押し増える。画面全体で
  1 回切り替える方が速く、開閉状態をカードの数だけ持たなくてよい。
- 推移の高さだけ縮める: 3 件を 1 画面に収めるには足りず、グラフも読みにくくなる。
- 表示設定をサーバーに保存する: 同じアカウントを PC では標準、スマホでは簡易で見たい。
  端末ごとに決まる設定をサーバーへ寄せる理由が無い。
- 画面幅だけで自動的に切り替える: 何を見たいかは幅ではなく用事で決まる。手で 1 タップ切り替える。

## 理由

情報を減らすのではなく、見たい粒度を選べるようにする。標準表示は従来どおり推移まで見え、
簡易表示は件数を一望するための表示になる。設定は端末に閉じるため、認証やセッションとは独立に扱える。

## 影響

- 簡易表示では推移を描かないぶん、カード 1 枚の高さと描画の計算が減る。サーバーの応答は変わらない。
- 3 列になるとカード 1 枚は狭くなる。provider の補足は標準表示にだけ出し、見出しの折り返しを避ける。
- ブラウザのデータを消すと標準表示に戻る。
