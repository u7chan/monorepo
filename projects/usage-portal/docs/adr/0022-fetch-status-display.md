# ADR 0022: 取得状況はカード内の間隔・経過・進捗バーで示す

- Status: accepted
- Date: 2026-11-18
- 関連: [ADR 0001](0001-state-fetching.md) の client 60 秒 / BFF 5 分、[ADR 0013](0013-meter-status-icons.md) の状態ラベル

## 背景

画面のヘッダーに「● 自動更新（60 秒） · 最終取得 23:31」を出していた。60 秒は client が
`/api/usage` を取得し直す間隔で、上流の値が新しくなる間隔ではない。最終取得も `generatedAt`
（BFF が応答を組み立てた時刻）で、こちらも上流の取得時刻ではない。どちらも利用者が知りたい
「いま表示している値がいつ時点か」に答えていなかった。

フッターにも「5 分ごとに取得」と書いていた。取得間隔を変えられるようにすると、この文言は必ず嘘になる。

カード内の `capturedAt`（実際の上流取得時刻）だけが鮮度の根拠になるが、時計時刻は暗算を強いる。
障害時は `state` が `stale` / `error` になり、バーを出し続けると「動いている」と誤読させる。

## 決定

- ヘッダーの自動更新・最終取得の行を削除する。フッターの「5 分ごとに取得」も削除する。
- カードのフッターに取得間隔と、最後に取得してからの経過を出す。標準表示は「10 分間隔・3 分前」、
  簡易表示は「3 分前」だけにする。正確な時刻は `title` に残す。
- カード下端に 2px の進捗バーを置き、次の取得予定までの進み具合を表す。`capturedAt` から
  `intervalMs` ぶん進んだら満タンで止め、循環させない。満タンのまま値が変わらないことが
  「予定を過ぎても来ていない」の合図になる。
- バーは `state` が `ok` のときだけ出す。`stale` / `error` / 取得前は出さず、文言と状態ラベルで示す。
- バーは `aria-hidden` の装飾とし、意味は文言で伝える。`prefers-reduced-motion` では transition を切る。
- 進捗は 30 秒ごとの再描画に合わせて更新し、transition で補間する。描画のたびに 0 からやり直さない
  よう、要素の `key` に `capturedAt` を使う。
- エラー時の再試行文言は固定の「5 分後」ではなく、取得間隔から作る。

採用しない案:

- 時計時刻だけを残す: 暗算が要り、間隔を変えたときに意味が変わる。
- 数値のカウントダウン（「あと 7 分」）: 常時更新する文字列になり、ちらつく。バーは同じ情報を静かに出す。
- バーを循環させる: 動いているように見え、取得が止まっていることを隠す。
- すべての状態でバーを出す: `error` / `stale` でも進み続け、動いていると誤読させる。
- ヘッダーに間隔と最終取得を戻す: カードごとに間隔が違い得るため、1 か所の表示では表せない。

## 理由

利用者が判断したいのは「この数字は今のものか」と「次はいつ変わるか」で、どちらもカードの中にある。
バーは後者を文章なしで伝え、前者は経過時間が伝える。バーだけにすると取得失敗時に古さを表せないため、
文字も残す。

## 影響

- `src/client/lib/format.ts` に `formatFetchInterval` / `describeAge` / `fetchProgress` を追加する。
- `ProviderCard` が `intervalMs` を受け取り、フッターとバーを描く。`CodexCard` / `OpenCodeAccountCard` は
  `/api/usage` の `sampleIntervalMs` をそのまま渡す。
- `styles.css` の `.up-toolbar` / `.up-toolbar-fetched` / `.up-auto` を削除し、`.up-fetch` / `.up-fetch-fill` を追加する。
- 取得間隔そのものはこの ADR では変えない。provider ごとの設定は別の ADR で扱う。
