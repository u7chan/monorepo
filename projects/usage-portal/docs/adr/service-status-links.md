# 稼働状況は取り込まず公式ページへリンクする

- Status: accepted
- Date: 2026-11-23

## 背景

利用枠が残っていても、上流プロバイダーの障害で使いにくいことがある。以前は OpenCode Go の公式ステータス API を
BFF で正規化し、モデル別の状態と未解決インシデントをカード一覧の上に表示していた。

実際に使うと、Go のカードがあるあいだ常に一覧の上を占有する一方、稼働状況を確かめるのは障害を疑ったときだけだった。
モデル別の内訳も公式ページで同じ内容を確認できる。アプリ側で持つために、認証付き API・キャッシュ・
鮮度の判定・60 秒ごとの取得を維持する必要もあった。

## 決定

- 稼働状況をアプリに取り込まない。OpenCode Go の稼働状況欄と、そのための API・上流の取得・キャッシュ・
  鮮度判定・client の定期取得を持たない。モデル別の状態とインシデントも表示しない。
- ヘッダーのメニューから、Codex・Claude・OpenCode の公式ステータスページを新しいタブで開けるようにする。
- アプリ内で監視・通知する機能は持たない。状態の判断は各社の公式ページに任せる。

## 採用しない案

- 稼働状況欄を残してモデル別の内訳だけ消す: 一覧の上の占有と、API・キャッシュの維持は変わらない。
- 正常時だけ隠して常時取得する: 異常を検知するために常時取得する必要があり、表示しない情報のために通信と
  鮮度管理を続けることになる。
- 利用枠の取得と一緒にステータスも取る: 取得周期では遅延や短い障害に気づきにくく、不要な保存も増える。
- 利用枠の上流エラーを障害とみなす: 契約・キー・通信の問題と、公式が報告するサービス障害を区別できない。

## 影響

- 障害時の情報はアプリから通知されない。利用者はメニューから公式ページを開いて確認する。
- 依存パッケージ・環境変数・DB は変えない。
- 公式ステータスの公開 API の形に追従する必要が無くなる。
